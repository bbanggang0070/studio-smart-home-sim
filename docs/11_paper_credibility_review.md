## 1. 무엇이 실제 데이터이고 무엇이 합성인가

EXP-5 데이터셋은 **Isaac Sim이 아니라 고속 모드**(환경 모델 + 센서 모델 + 제어기 + 하네스)가 만든다. Isaac Sim은 실시간 1배라 장기 · 대량 데이터를 만들 수 없고(물리 모드 실시간 비 1.00), 온습도 · CO₂ · PM · 에너지는 Isaac이 아니라 ROS 쪽 환경 모델이 계산한다.

| 구성 요소 | 출처 | 검증 수준 | 증거 |
|---|---|---|---|
| 창문 · 블라인드 · 팬 동작, 끼임 반력 | Isaac Sim PhysX | **시뮬레이터 내 검증** (실물 아님) | `check_scene` 13/13 · 끼임 스윕 195회(접촉 있는 165회 감지 100 %) · 물리 39회 판정 |
| 조도(주광) 모델 | Isaac 경로 추적 렌더 → 표 | **렌더 대조**(실측 아님) · 직사광 비율은 가정 | `results/validation/daylight_check.csv` · docs/06 v2.2 |
| 참값 열모델 3R3C | 문헌 기반 초기값(draft) | ❌ **실측 보정 없음** | `config/environment_model.yaml` thermal 블록 draft 표기 |
| 습도 · PM · CO₂ · 결로 | 문헌 식(Magnus 등) · 집중 정수 | 식 검증만 · 실측 없음 | docs/06 §5 · 가정 A12 |
| 에어컨 전력 | 부분부하 COP 곡선 | ❌ **draft 곡선** | `cop_values` draft · docs/08 §6.2 |
| 재실 | 비균질 마르코프(Page 2008 변형) | 생성기 자체 · 실제 거주 데이터 대조 없음 | §5.3 |
| 날씨 | 시나리오 고정값 · 사인파 일교차 · 범위 추출 | ❌ 실제 기후 아님 | `harness.yaml energy_training` |
| 센서 잡음 | 데이터시트 기반 | 시뮬레이션 가정 | `config/sensor_models.yaml` |
| 에너지 | 정격 · COP × 가동 시간 (추정 Wh) | 계량값 아님 | 지표 #7 "추정 소비전력량" |

> **논문 표기:** "Isaac Sim 기반 디지털 트윈에서 합성한 데이터"가 아니라 **"Isaac Sim으로 액추에이터 동작을 검증한 회색상자 집중 정수 시뮬레이터에서 합성한 데이터"** 로 쓴다. 시뮬레이터 구성은 표처럼 나눠 밝힌다.

## 5. 문헌이 한계로 지적했는데 우리가 강행하고 있는 것

### 5.1 저충실도 에뮬레이터에서 RL을 평가한다 — **필수 대응**
- **문헌:** A3 — "현실적인 동역학을 가진 건물 환경에서 모델 없는 RL은 성능이 나쁘다(선행연구 주장과 반대)". D1 — 에뮬레이터는 Modelica로 현실적 동역학을 표현해야 비교가 의미 있다.
- **우리:** 참값이 3R3C 집중 정수(제어용 2R2C와 같은 계열)이고 계수는 draft. RL이 **단순한 동역학 덕분에** 실제보다 좋아 보일 위험이 있다.
- **대응:** 같은 3방식을 **고충실도 외부 에뮬레이터 하나에서도** 돌려 순위가 유지되는지 확인한다. 후보는 BOPTEST **BESTEST Air**(단일 공간 · 48 m² · 팬코일 냉난방 · Denver)이다. 원룸은 아니지만 단일 공간 냉방 비교로는 쓸 수 있고, 결과가 엇갈리면 그 자체가 보고할 결과다.

### 5.2 학습과 평가가 같은 시뮬레이터 계열이다 — **필수 대응**
- **문헌:** D3 — 일반화가 과제다(전이 학습). A2 — 모델과 실제의 상태 · 행동 공간 불일치가 배포의 걸림돌이다.
- **우리:** docs/10 §4는 평가 때 참값 계수를 ±20 % 바꾸는 것으로 막으려 한다. 하지만 **구조(3R3C · 집중 정수 · 단일 공간)는 그대로**라 "구조 불일치"는 시험하지 않는다.
- **대응:** ① 평가 계수 변동 범위를 문헌 · 실측 근거로 정한다(±20 %는 근거 없음). ② §5.1의 외부 에뮬레이터를 구조 불일치 시험으로 겸한다. ③ 논문 주장을 "같은 계열 안 일반화"로 한정한다.

### 5.3 사무실용 재실 모델을 주거에 쓴다 — **권장 대응**
- **문헌:** F16(Page 2008)은 **1인 사무실** 데이터로 만든 모델이다.
- **우리:** 같은 구조에 시간대별 재실 확률 · 머무름 30분 · 근무 형태를 직접 정했다(draft). 생성기로 학습도 하고 평가도 하므로, LSTM · GBM은 **생성기 규칙을 배운다**(docs/08 §5.2에 이미 적은 한계).
- **대응:** 시간대별 재실 확률을 공개 생활시간 통계(예: 통계청 생활시간조사의 1인 가구 재택 비율)로 보정하고 출처를 밝힌다. 그리고 "재실 패턴 정확도는 주장하지 않는다"(A18)를 논문 한계에 그대로 쓴다.

### 5.4 날씨가 합성이다 — **필수 대응** (일반화 · 계절 결과를 말하려면)
- **문헌:** D5(Sinergym)은 **여러 날씨 유형**을 환경으로 제공한다. A2는 날씨 정규화 에너지를 쓴다.
- **우리:** 외기 고정 · 사인파 일교차 · 범위 추출뿐이다. 연속 폭염 · 장마 · 일사 변동이 없다.
- **대응:** 실측 시간별 기상(기상청 지상관측 등 — 기온 · 습도 · 일사 · 강수)을 외부 조건 시계열로 넣는다. 학습 연도와 평가 연도를 나눈다.
- **결과 (2026-10-19):** analysis_report §8 — 2024 실측일 대입 시 제안 통과 100 → 92.1 %. 합성 날씨로 식별한 2R2C 는 실측 날씨에서 RMSE 0.78 → 2.44 °C — EXP-4 오차는 같은 합성 분포 안의 값이다.

### 5.5 RL 알고리즘을 SAC 하나로 정했다 — **권장 대응**
- **문헌:** A1에서 SAC는 기준선보다 뚜렷한 이점이 없었고 DDPG만 나았다. A2는 모델 기반 RL이었다.
- **우리:** docs/10 표는 "SAC 또는 DQN", EXP-5 초안은 SAC만 쓴다.
- **대응:** 이산 행동(켜기 · 끄기 · 설정 단계)이면 DQN 계열, 연속이면 SAC · DDPG를 함께 두고 **같은 튜닝 예산**으로 비교한다. 최소한 "RL 한 종으로 RL 전체를 대표하지 않는다"고 한계에 쓴다.

### 5.6 통계적 반복이 없다 — **필수 대응**
- **문헌:** A2는 95 % 신뢰구간을 보고했다. docs/10 §4도 시드 5개 이상 · 신뢰구간을 계획했다.
- **우리:** 고속 모드 시나리오 · 기준선 70개 묶음 중 **81 %에서 3회 반복의 에너지가 완전히 같다**(2026-10-16 재계산). 지금 결과의 "3회 반복"은 같은 실행을 세 번 한 것에 가깝다.
- **대응:** 반복마다 날씨 · 재실 · 센서 잡음 · 참값 계수를 다르게 뽑아 평균 ± 신뢰구간을 낸다. 지금까지 결과에는 "결정적 시뮬레이션 — 반복 간 분산 없음"을 명시한다.

### 5.7 순수 RL은 제약을 어긴다 — **우리 설계로 대응됨 · 보고 필요**
- **문헌:** C6 — 순수 RL은 제약을 어긴다.
- **우리:** 안전 · 결로 · 전력 한도는 규칙 계층이 강제한다. 다만 그러면 RL 성능 일부가 규칙 덕분이다.
- **대응:** docs/10 계획대로 **규칙이 덮어쓴 횟수**를 방식별로 보고한다. 규칙 없이 돌린 결과도 부록으로 둔다.

### 5.8 LSTM의 학습 밖 약점 — **강행이 아니라 검증 대상** (공통점)
B1의 지적(설정온도가 바뀌면 LSTM 성능 저하)을 우리는 실험 축으로 삼는다. 문헌과 같은 방향이면 재현, 다르면 새 결과다.

## 6. 문헌과 별개로 — 우리 내부의 신뢰성 위험

### 6.1 결과를 본 뒤 판정 기준을 바꿨다
docs/03 변경 이력에 남은 사후 개정이다. 모두 이유(물리적 한계 · 설계 변경 · 사용자 결정)는 있지만, 논문에서는 **사후 조정**으로 읽힌다.

| 버전 | 시나리오 | 개정 |
|---|---|---|
| v2.13 | C1 · C13 | RH 30분 내 ≤ 60 % → 60분 내 ≤ 72 % / ≤ 60 % |
| v2.15 | C9 · C11 | 에너지 비교 기준 변경 |
| v2.17 | C15 | 건조 ≤ 4 h → ≤ 6 h + Proposed−P 대비 단축 |
| v2.19 | C9 · X5 | 에너지 · 과열 판정 삭제 · RH 회복 30 → 90분 |
| v2.27 | B1 · B2 | 기본 환기 틈 허용 · 부분 차광 |
| v2.29 | C3 · B3 | '열원 먼저' 판정 폐지 · 블라인드 판정 변경 |

**대응:** 최종 실험 전에 판정 · 지표를 **동결**하고(날짜 · 커밋 해시), 논문에는 원래 기준과 개정 기준의 결과를 **둘 다** 표로 낸다.

### 6.2 지표 정의를 사후에 바꿨다
- #1 유지율: 공기 온도 → 실링팬 보정 온도(v2.31). 제안 제어기 평균이 바꾸기 전 27.7 %(A 21.2 %), 바꾼 뒤 55.9 %(A 27.3 %).
- #7 에너지: 전체 비교 → 같은 목표 달성 · 조명 제외(v2.34). 전체 −36 %(증가), 바꾼 뒤 +6.8 %(절감).
- 제외 규칙: #4 접촉 없는 30회 · #9 X6 · #11 C6.

**대응:** 정의마다 바꾸기 전 값을 함께 보고한다(이미 #7은 '전체 · 참고' 행이 있다). 바꾼 이유가 결과 개선이 아니라 정의 오류 수정임을 보여야 한다.

### 6.3 개발에 쓴 시나리오로 평가했다
제어기를 41개 시나리오에 맞춰 반복 수정(W09–W13)했고, 같은 41개로 "123/123 통과"를 보고한다. 머신러닝의 학습 데이터 = 시험 데이터와 같은 구조다.

**대응:** 제어기를 동결한 뒤 **새로 만든 시나리오 묶음**(같은 생성 규칙 · 다른 조합)으로 평가하고, 개발 시나리오 결과와 따로 보고한다.

### 6.4 기준선이 약할 수 있다
- A(장치별 독립 규칙)는 우리가 직접 만들었다. 조명을 켜지 않고(C4 제외) 비 오는 날 창문을 연다. 판정 통과율 15 %, C1–C8 기준 통과 62 %.
- B는 제안 제어기에서 히스테리시스만 뺀 것이라 독립 기준선이 아니다.
- **문헌 대비:** BOPTEST는 테스트 케이스마다 기준 제어를 내장한다(D1).

**대응:** "사람이 하는 행동(어두우면 조명 · 비 오면 창문 닫기)"을 넣은 A′ 또는 상용 스마트 온도조절기 방식의 기준선을 추가한다. 최소한 A의 규칙 전체를 부록에 공개해 심사자가 판단하게 한다.

### 6.5 제어용 모델 = 참값 모델인 부분이 있다 (분리 원칙의 예외)
- 열모델은 분리돼 있다(2R2C vs 3R3C).
- 그러나 다음은 참값과 **같은 값의 사본**을 제어기가 쓴다. 제어기가 정답 계수를 아는 셈이다.
  - 주광 표: `tests/test_daylight.py`가 두 값이 같은지 검사한다
  - 냉방 블라인드 선택 계수: 블라인드 유량 계수 · 일사열 계수 · 창문 유량 식(`cooling_blind.py` 머리말 "참값 모델과 같은 초기값의 사본")

**대응:** 평가 때는 참값 쪽만 무작위로 바꾼다(§5.2와 함께). 논문에는 "열 동역학은 분리, 일부 하위 모델은 공유"로 정확히 쓴다.

### 6.6 끼임 안전의 표준 인용이 부정확하다
eCFR 49 CFR 571.118(FMVSS 118) S5를 확인한 결과:

| 요건 | FMVSS 118 S5 | 우리 | 판정 |
|---|---|---|---|
| 끼임 힘 | 100 N 이상이 되기 전 정지 · 반전 | 최대 52.9 N(스윕) · 85.4 N(시나리오) | ✅ 수치는 충족 |
| 시험봉 | 직경 4–200 mm · 강성 25 mm 이하 ≥ 65 N/mm · 25 mm 초과 ≥ 20 N/mm | 강체 화분(100 mm) 65 N/mm | ✅ 충족 |
| (표준 밖) | — | 연질 쿠션 2 N/mm · 탄성 스펀지 0.8 N/mm | 표준보다 무른 추가 시험. 표준 결과와 섞지 않는다 |
| **반전 거리** | 시작 위치까지, 또는 **125 mm 이상 더 열림**, 또는 지름 200 mm 봉이 지날 만큼 | **50 mm** (`reverse_distance_m: 0.050`) | ❌ **미충족** |
| 적용 대상 | **자동차** 창 · 칸막이 · 선루프 | 건물 창 | 표준 대상이 다르다 |

- 건물용 전동 창 · 문 구동장치의 해당 표준은 **IEC 60335-2-103**(가정용 문 · 창 · 게이트 구동장치)이다.
  - ⚠️ 끼임 힘 한계 · 측정법(BB.20.107)은 원문을 확인하지 못했다.
  - 제조사 문서에 400 / 150 / 25 N이 인용되어 있다.

**대응:**
- 논문의 "FMVSS 118 참조"를 "**FMVSS 118의 100 N 기준과 시험봉 정의를 빌려 썼다(반전 거리 요건은 미적용)**"로 고친다.
- 반전 거리를 125 mm 이상으로 바꿀지 결정한다. 설계 변경이므로 사용자 확인 후 진행한다.
- 건물용 표준 IEC 60335-2-103은 원문을 확보해 비교한다.

### 6.7 명칭 · 문서 정합성
| 항목 | 현재 | 고칠 것 |
|---|---|---|
| "체감온도 · operative temperature" | 공기 온도 − 실링팬 단계별 고정값(0.8 / 1.5 °C) | 실제 operative temperature(평균 복사온도 포함)가 아니다 → "실링팬 보정 온도"로 부르고 근거(ASHRAE 55 고풍속 냉방 효과의 단순화)를 밝힌다. 변수명 `operative_temp_c`도 정정 대상 |
| docs/05 §1 대비표 | "센서 4종" · "시나리오 180회" | 현재 센서 7종 · 249회 + 스윕 195회 |
| 가정 A6 | "전력은 가동 시간으로 대리 측정" | 현재는 정격 · COP 곡선 × 가동 시간(추정 Wh) |
| 가정 번호 | 화장실 가정이 A20(mmWave)과 중복 | ✅ 2026-10-16 A23으로 정정 |
| docs/10 B2 서술 | "LSTM + MPC 조합 구성 방법" | ANN · GPR · 선형 모델 비교 → 서술 정정 |

### 6.8 Isaac Sim의 역할을 과장하지 않는다
Isaac Sim은 액추에이터 물리 · 끼임 반력 · 조도 렌더 대조를 맡는다. 에너지 · 쾌적 결과와 EXP-5 데이터셋에는 들어가지 않는다.

"Isaac Sim 디지털 트윈으로 에너지 제어를 학습했다"는 표현은 사실과 다르다. 검색 범위에서 Isaac Sim으로 건물 열 · 에너지를 다룬 선행 사례는 찾지 못했다. 그래서 신규성으로 내세울 수 있는 것은 **"주거 창호 · 블라인드 액추에이터의 물리 검증"까지**다.

## 7. 논문에 쓸 수 있는 주장 / 쓰면 안 되는 주장

| 쓸 수 있다 (근거) | 쓰면 안 된다 (이유) |
|---|---|
| 같은 시뮬레이터 · 같은 규칙 아래 세 방식의 상대 비교 | 실제 원룸에서 몇 % 절감된다 — 실측 · 보정 없음 |
| 회색상자 2R2C는 4주 합성 데이터로 RMSE 0.52 °C (참값 3R3C 대비) | 실제 방 열 거동 예측 정확도 |
| 협조 제어가 시나리오 판정 기준을 A보다 많이 지킨다(62 % → 100 %, C1–C8) | 협조 제어가 에너지를 20 % 줄인다 (#7 미달 · 9쌍) |
| 끼임 시 100 N 미만에서 정지 · 반전(시뮬레이션) | FMVSS 118 · IEC 60335-2-103 적합 |
| LSTM은 학습 밖 상황에서 성능이 떨어진다(실험 결과가 나오면 · B1과 비교) | RL이 새로운 집에서 바로 최적이다 (구조 불일치 시험 없음) |
| 재실 생성기 3유형에서 분위수 GBM의 귀가 예측 손실 | 실제 1인 가구 귀가 예측 정확도 (A18) |
