창문·블라인드는 **위치 제어**, 팬은 **속도 제어**로 드라이브를 구성해 독립 구동을 검증하고,
**조명 intensity ↔ lux 매핑을 캘리브레이션으로 확정**한다.

### T5.7 조도 캘리브레이션 절차

> **Light Prim의 `intensity`는 lux가 아니라 렌더러 상대 단위다.** 매핑을 우리가 정의해야 한다.

```text
1. 블라인드 완전 차광 + 외부광 0 → 실내를 암실 상태로 만든다
2. 천장 조명만 0 → 100 % 스윕, 바닥 중앙 기준점의 조도를 기록
3. 스탠드만 0 → 100 % 스윕, 책상면 기준점의 조도를 기록
4. 두 기여가 선형 합산되는지 확인 (겹쳐 켰을 때)
5. 결과를 thresholds.yaml의 lighting_model에 반영:
     ceiling_lux_at_full / desk_lux_at_full / ceiling_to_desk_k_geo
```

> **왜 중요한가:** 지금은 *"조도 250 lux에서 점등"* 이라는 임계값과 *"밝기 70 %"* 라는 출력이
> **물리적으로 연결되어 있지 않다.** 이 캘리브레이션이 그 고리를 잇는다.
> 또한 **책상 조도 센서를 없애고 추정으로 대체**했으므로(범위정의서 §2.5), `ceiling_to_desk_k_geo`의
> 정확도가 곧 그 결정의 타당성을 결정한다.

```text

```

## 5. 리스크 / 대응
| 리스크 | 대응 |
|---|---|
| 창문 조인트 떨림(진동) | damping 증가, 최대 속도 제한, 목표값 램프 입력 적용 |
| 튜닝에 시간 과소요 | 파라미터 스윕 스크립트 자동화, 3일 초과 시 기본값 확정 후 진행 |
| **조도 캘리브레이션에 렌더링 노출 자동조정이 개입** | 노출을 고정하고 측정. 톤매핑이 값을 왜곡하므로 반드시 선행 확인 |
| **책상 조도 추정 오차가 과대(>20 %)** | 기하 계수를 거리별 테이블로 세분화. 그래도 크면 **책상 조도 센서 1개 추가**(+2,000원)를 검토하고 범위정의서를 갱신 |
| **Zone A–D 구간이 반력 그래프에서 구분되지 않음** | W03 씰 마찰 계수 재튜닝. **여기서 막히면 W10 센서리스 구현이 불가능하므로 즉시 되돌아간다** |
