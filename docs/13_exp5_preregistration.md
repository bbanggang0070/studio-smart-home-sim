# 13. EXP-5 사전 등록 — 외출 중 냉방 결정: 질문별 모델 vs LSTM vs 강화학습

> 작성 2026-10-27 · 제어기 v1.29 (동결 · 바꾸지 않는다) · 계획 원본 [`10`](10_energy_control_comparison_study.md) §1–§6
> **이 문서는 평가를 돌리기 전에 커밋한다.** 커밋 뒤에 바꾸는 항목은 §10 '등록 후 변경' 표에 이유와 함께 적고, 결과에 함께 보고한다.
> 평가 시드 · 조건은 여기 적지만, 평가 집합은 방식 코드가 동결(§9)되기 전에는 만들지도 돌리지도 않는다.

---

## 0. 한 줄 요약

외출 중 에어컨을 **셋백 · 끄기 · 언제 프리쿨링을 시작할지** 정하는 한 가지 결정을 세 방식으로 바꿔 끼우고, **같은 데이터 · 같은 비용식 · 같은 평가 환경**에서 기대비용을 비교한다. 데이터 양(1–8주)과 학습에 없던 조건(참값 계수 변동 · 재실 패턴 변화)에서 성능이 어떻게 변하는지가 주 관심이다.

## 1. 범위 — 무엇을 비교하고 무엇을 비교하지 않나

| 포함 | 제외 |
|---|---|
| 외출(AWAY · 무재실) 구간의 에어컨 결정 — docs/08 §5.3 의 `EnergyPlanner` 가 맡는 부분 | 습도 · 환기 · 차광 · 조명 · 이벤트 — 협조 제어기 전체 |
| 냉방철(6–9월) · 냉방 목표 26 °C · NORMAL 모드 λ | 난방 (범위 밖) |
| 참값 3R3C 환경 모델로 만든 **에어컨만 있는 에피소드 환경** (§4) | Isaac Sim 물리 모드 |

**왜 좁히나** — 협조 제어기 전체를 학습 방식으로 바꾸면 비교 대상이 너무 많고(액추에이터 11종 · 규칙 10개) 안전 · 결로 규칙이 결과를 가린다(docs/10 §4). 외출 중 냉방 결정은 ① 예측(귀가 · 열 거동)과 최적화가 모두 들어가고 ② 안전 규칙과 겹치지 않아 세 방식을 공정하게 비교할 수 있다.

**제어기 v1.29 는 바꾸지 않는다** — 결과가 어떻든 EXP-5 는 비교 연구로만 보고한다. 학습 방식이 더 나아도 동결 제어기에 넣지 않는다 (넣는다면 새 버전 · 새 보류 평가가 필요하다).

## 3. 비교 방식

| | 열 거동 | 귀가 | 결정 | 학습에 쓰는 것 |
|---|---|---|---|---|
| **① 질문별 모델** (현재 · v1.29) | 제어용 2R2C — 기록 데이터로 식별 | `auto` (경험 분포 / 분위수 GBM — 검증 손실로 선택) | 기대비용 최소화 (셋백 · 끄기 · 프리쿨링 시작 5분 격자) | 운전 기록 k주 · 귀가 이력 k주 |
| **② LSTM + 같은 최적화** | LSTM 1층 — 과거 창으로 다음 5분 실내 온도 예측 · 자기회귀로 굴림 | ① 과 같음 | ① 과 같은 최적화에 2R2C 대신 LSTM | ① 과 같은 데이터 |
| **③a 데이터 기반 RL** | 모델 없음 (정책) | 관측에 ① 의 귀가 분위수(q20 · q50 · q80) 포함 | DQN — 5분마다 {끄기 · 셋백 · 설정 온도 냉방} | ① 과 같은 데이터로 만든 학습 시뮬레이터(식별 2R2C + 귀가 이력 부트스트랩)에서 상호작용 |
| **③b 시뮬레이터 접근 RL** (참고) | 모델 없음 (정책) | ③a 와 같음 | DQN — 같은 행동 | 참값 3R3C · 계수 무작위(도메인 무작위화 · E-계수와 같은 범위) · 학습 연도 기상 · 학습 시드 재실 — **데이터 양과 무관 · 특권 정보**라 따로 보고 |

**기준 정책** (모든 표에 함께)
- 언제나 셋백(+2 °C) · 언제나 끄기(귀가 때 냉방)
- **오라클** — 참 귀가 시각과 참값 모델을 알고 프리쿨링 시작을 격자 탐색 (비용 하한 · 후회 = 비용 − 오라클)

**같게 두는 것** — 비용식 · 행동 집합(셋백 · 끄기 · 설정 냉방 · 5분 결정 간격) · 에어컨 명판 값 · 압축기 최소 ON 300 s / OFF 180 s (환경이 강제하고 덮어쓴 횟수를 센다) · 관측 가능한 값(실내 온도 · 외기 · 실내 주광 · 에어컨 전력 · 시각 · 요일 · 출발 시각 · 직전 귀가). 어떤 방식도 참값 계수 · 참 귀가 시각을 보지 않는다 (오라클 · ③b 학습 환경만 예외).

## 4. 환경 · 에피소드

- **환경**: `env_model.room.RoomModel` (참값 3R3C) 에서 에어컨만 움직인다. 창 · 팬 · 차광은 닫힘 · 정지 고정. 1분 적분 · 결정은 5분마다
- **에피소드** = 재실 생성기(`occupancy_gen`)의 외출 하나: 출발 6시간 전부터 설정 온도로 냉방한 상태로 시작(축열 질량 초기화) → 출발 → 귀가 → 귀가 후 60분에 끝
- **외출 길이** ≥ 1 시간인 외출 모두 (3시간 이상 부분집합도 따로 보고 — 기존 '주 귀가' 정의)
- **기상**: ERA5 서울 실측 (Open-Meteo) — 학습 · 검증 2021–2023 · **평가 2024** · 6–9월. 에피소드의 날짜는 연도 안에서 무작위
- **비용** (계획기와 같은 정의): `비용 = 에어컨 전력량 Wh (출발 ~ 귀가 + 60분) + 2,000 × 귀가 후 불쾌 K·h` · 불쾌 = max(0, 실내 − (26 + 1) °C) 의 시간 적분

## 5. 데이터 분할

| 집합 | 내용 | 재실 시드 | 기상 연도 |
|---|---|---|---|
| 학습 k주 | k ∈ {1, 2, 4, 8} — 운전 기록(식별용 무작위 운전 · `train_energy_model.py` 와 같은 방식) + 귀가 이력 | 페르소나 기본 시드 (`harness.yaml occupancy_generator`) | 2021–2023 |
| 검증 2주 | 학습 직후 2주 — 튜닝 · 모델 선택에만 사용 | 같은 시드 연속 | 2021–2023 |
| **평가 4주 × 3 조건** | 학습에 쓰지 않은 재실 · 기상 — 아래 조건 | 시드 **20262700 + 페르소나 번호(0 · 1 · 2)** · 기상 날짜 · 계수 시드 **20262710 + 페르소나 번호** (평가 전용 · 저장소에서 쓴 적 없음 — 2026-10-27 확인) | **2024** |

**평가 조건**
- **E-기본**: 참값 기본 계수 · 같은 페르소나
- **E-계수**: 에피소드마다 참값 계수를 뽑는다 — 기존 무작위 반복의 `truth_params` 범위 그대로 — 침기 0.2–0.4 회/h · 창 U 2.4–3.2 W/m²K · 열용량 3종 ×U[0.8, 1.2] · 에어컨 COP ×U[0.85, 1.15]
- **E-패턴**: 재실 패턴 변화 — 정시 출퇴근의 야근 비율 0.12 → 0.40 · 불규칙의 야간 근무 비율 ×2 · 재택의 오후 외출 확률 ×2 (학기 → 방학처럼 패턴이 바뀐 상황)

**페르소나** 3종 (정시 출퇴근 · 불규칙 · 재택). 재택은 외출이 짧고 적어 결과를 따로 본다.

## 6. 튜닝 예산 · 학습 예산

| 방식 | 튜닝 | 학습 예산 |
|---|---|---|
| ① | **튜닝하지 않음** — v1.29 설정 그대로. 단 ① 의 계획기 설정은 개발 중 시나리오(C16 · EXP-1)로 정했다는 점을 보고한다 | 2R2C 식별 · GBM 학습 (현재 도구) |
| ② | 무작위 탐색 **20회** — 학습률 · 은닉 {32, 64, 128} · 입력 창 {1, 2, 4 h} · 에폭 상한 · 드롭아웃. 검증 2주의 **계획 비용**으로 선택 | 시도마다 조기 종료 · 최대 200 에폭 |
| ③a · ③b | 무작위 탐색 **20회** — 학습률 · 감가율 · 탐색 감쇠 · 목표망 갱신 · 신경망 크기. 검증 2주 비용으로 선택 | 시도마다 환경 **30만 결정 단계** 고정 |

- 튜닝은 페르소나 · k 마다 따로 한다. 선택된 설정으로 학습 시드 **5개**를 다시 학습해 평가한다 (①은 결정론적이라 시드 1개 · GBM 은 기존 시드)
- 튜닝 시도 수 · 학습 시간 · 결정 1회 계산 시간을 모두 보고한다
- 예비 실행(파이프라인 · 시간 확인)은 학습 · 검증 집합에서만 한다. 그 결과로 §5–§7 을 바꾸면 §10 에 적는다

## 7. 지표 · 분석 · 판정 규칙

**주 지표**: 에피소드 비용의 **짝 비 = 방식 / ①** (같은 에피소드 · 같은 조건) — 중앙값

**주 비교 (3개)**: k = 4주 · 세 조건 합침 · 세 페르소나 합침에서 ② / ① · ③a / ① · ③b / ①
- 구간: **(페르소나 × 평가 주) 묶음 부트스트랩 95 %** (10,000회) — 같은 주 안의 에피소드는 기상 · 패턴이 닮았다
- 검정: 에피소드 짝 부호 검정 · **Holm 보정** (3개)
- **판정**: 구간 상한 < 1.00 이고 보정 p < 0.05 → '① 보다 낫다' · 구간 하한 > 1.00 이고 보정 p < 0.05 → '① 보다 못하다' · 그 외 → '차이를 확인하지 못함'. **비열등(±5 %) 판정은 하지 않는다** (등록하지 않은 판정은 쓰지 않는다)

**부 지표** (판정 없이 구간과 함께 보고)
- 데이터 양 곡선 (k = 1 · 2 · 4 · 8) — 방식별 비용 비 · 후회
- 조건별 (E-기본 · E-계수 · E-패턴) 과 '기본 → 변동' 저하량
- 비용 분해 — 전력량 · 불쾌 K·h · 귀가 때 26 + 1 °C 이하 도달 비율
- 압축기 보호가 덮어쓴 결정 수 · 결정 1회 계산 시간 · 학습 시간 · 튜닝 시도 수
- 3시간 이상 외출만 · 페르소나별

**빠진 값 · 실패 처리**: 학습이 발산(검증 비용이 '언제나 끄기' 보다 2배 이상)해도 그 시드를 빼지 않고 그대로 평가한다. 환경 오류로 끝나지 못한 에피소드는 모든 방식에서 같이 뺀다 (개수 보고).

## 8. 하지 않을 것 (사전 약속)

- 평가 결과를 본 뒤 하이퍼파라미터 · 비용식 · λ · 평가 조건을 바꿔 다시 평가하지 않는다
- 평가 집합을 검증 · 튜닝에 쓰지 않는다
- 주 비교 외 비교에 '유의' · '우월' 표현을 쓰지 않는다
- 결과로 v1.29 제어기를 바꾸지 않는다

## 9. 동결 · 실행 순서

1. **이 문서 커밋** (등록) — 해시를 §11 에 적는다
2. 구현: 에피소드 환경 · ② · ③ · 기준 정책 · 분석 도구 (`tools/exp5/` · 설정 `config/exp5.yaml`)
3. 학습 · 검증 · 튜닝 (예비 실행 포함)
4. **방식 동결** — 선택된 설정 · 학습된 가중치 · 코드 해시를 §11 에 적고 커밋
5. 평가 집합 생성 · 평가 1회 실행 → 결과 요약 `archive/exp5/` (원시 기록은 커밋하지 않음)
6. 분석 · 보고 (가설과 다른 결과 포함)
