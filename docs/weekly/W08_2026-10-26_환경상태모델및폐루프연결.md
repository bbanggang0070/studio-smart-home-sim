## 1. 주차 목표
환경 상태 모델을 구현하여, **액추에이터 동작이 조도·온도·습도에 되먹임되는 폐루프**를 완성한다.

> ### 📌 v2.0에서 추가된 것 — 습도가 온도와 동등해졌다
> 시나리오 **C1(고온다습+우천)** 과 **C6(결로 방지)** 가 신설되면서, 습도는 더 이상 부수적 변수가 아니다.
> 온도와 같은 수준의 상태 갱신식을 갖춰야 한다.

### T8.2 습도 갱신식

```text
RH(t+1) = RH(t) + G_occupancy − E_window(개방률, 외기습도차) − E_fan(rpm)
                + C_condensation(저온 시 결로 항)

G_occupancy  : 재실자 발생 수분 (호흡·발한)
E_window     : 자연 환기 배출 — 외기 습도가 낮을 때만 유효
E_fan        : 강제 환기 배출
C_condensation : 저온 + 고습 조건에서의 결로 (시나리오 C6)
```

> ⚠️ **중요한 물리 제약: 비가 오면 외기 습도가 높다.**
> 따라서 **강우 시 창문을 열면 습도가 오히려 올라가야 한다.** 이 되먹임이 모델에 없으면
> 시나리오 C1에서 *"Baseline A가 창문을 열어 상황을 악화시킨다"* 는 결과가 재현되지 않는다.
> **C1은 발표의 대표 사례이므로 이 항을 반드시 구현한다.**

## 5. 리스크 / 대응
| 리스크 | 대응 |
|---|---|
| 상태 모델 계수가 비현실적 | 정상상태 온도가 상식적 범위(20~35 °C), 습도가 30~90 %RH에 들도록 캘리브레이션 |
| 발산(온도·습도 무한 상승) | 외기 기준 점근 형태로 모델링, 클램핑 적용 |
| **습도-온도 결합이 과도해 진동** | 두 상태의 시정수를 분리(습도를 더 느리게). 습도 최소 유지시간 60 s 적용 |
| **조명 발열이 과대해 C4가 비현실적으로 보임** | 실제 LED 효율(약 100 lm/W) 기준으로 발열량 산정. 과장하면 심사에서 지적받는다 |
| **음압 유입 계수가 과대/과소** | 유입량이 너무 작으면 C8에서 "팬을 꺼야 한다"는 결론이 나오지 않고, 너무 크면 비현실적이다. 일반적인 원룸 기밀성능 범위로 설정하고 **민감도를 W12에서 확인**한다 |
