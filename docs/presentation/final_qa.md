## A. 결과의 신뢰성

**Q1. 실제 원룸에서 해보지 않았는데 결과를 믿을 수 있나?**
믿을 수 없는 부분이 있다고 먼저 말씀드린다. 참값 모델 · 가전 계수 · 센서 특성은 문헌과 가정값이고, 실제 절감률이나 정확도는 주장하지 않는다. 대신 결론이 모델 가정에 기대지 않는지 확인했다 — 참값 계수와 외기를 매번 뽑는 무작위 반복, 서울 2024 실측 기상, 센서 결함 주입, 외부 표준 에뮬레이터 BOPTEST. 이 조건들에서 상용 수준 기준선 대비 차이(약 +60 %p)의 방향은 같았다. (§6.2–6.6 · §6.10 · 한계 1)

**Q2. 판정 기준과 제어기를 같은 사람이 만들었으면 유리하게 짠 것 아닌가?**
그 위험이 있어 세 가지를 했다. ① 판정 기준을 해시로 동결하고 개정은 전후 결과를 함께 적었다 ② 보류 평가는 제어기를 동결한 뒤 새 시나리오 묶음을 실행 전에 커밋 · 등록했고, 7차를 마지막으로 정해 결과를 고치지 않았다 — 32/36 (89 %) ③ 판정 문구 157개를 환경 결과 · 수단 · 과정으로 나눠, 기준선 비교는 제어기 설계를 묻지 않는 환경 결과 기준(38개)으로 했다. 완전히 없앨 수는 없어 한계로 적었다. (§5.2–5.3 · 한계 2)

**Q3. 기준선이 약해서 차이가 크게 나온 것 아닌가?**
그 지적 때문에 상용 스마트홈 허브 수준 규칙 자동화(A′)를 결과를 보기 전에 규칙 · 값을 정해 추가했다. A′ 는 기기별 독립(A)보다 환경 결과를 7 %p 더 지켰지만, 제안과의 차이는 약 +60 %p [+35, +84] 로 그대로였다. (§6.3)

**Q4. 시나리오를 41개나 직접 만들었으면 제어기를 시나리오에 맞춘 것 아닌가 — 임계값 과적합?**
제어기 판단 임계값 106개를 실행마다 각각 ±20 % 흔들었다. 환경 결과 통과율은 93.6 % 로 그대로였고, 떨어진 7 %p 는 이벤트 진입 시각 · 구동 횟수 같은 제어기 내부 동작 판정에서 나왔다. 실내 환경 결과는 임계값에 둔감하다. 처음 보는 조합(보류 7차)에서도 89 % 였다. (§6.5–6.6)

**Q5. 통과율 구간은 어떻게 냈나, 반복 5회면 독립이 아니지 않나?**
맞다 — 같은 시나리오의 반복은 서로 닮았다. 그래서 실행 단위가 아니라 **시나리오를 묶음으로 다시 뽑는 부트스트랩**으로 구간을 냈고(실행 독립 가정보다 넓다), 같은 조건 짝 비교는 McNemar · 부호 검정에 Holm 보정을 했다. 이 방식으로 바꾸면서 A′ 대비 에너지 결론을 정정했다. (§5.2 · §6.3)

## B. 에너지 · 비용

**Q6. 에너지를 절감했나?**
에너지 절감이라고는 주장하지 않는다. 기기별 내장 자동(A)보다는 더 쓴다 — A 는 쾌적 유지율 0.32 로 쾌적을 거의 지키지 못해 적게 쓰기 때문이고, A 대비 20 % 절감 목표는 미달이다. 상용 수준(A′)과는 쾌적이 비슷하고(0.60 vs 0.62) 에너지 중앙값은 −16 % 지만 구간이 1 을 포함한다. 주장은 "같은 쾌적을 더 싸게" — 온도 불쾌를 비용으로 넣은 기대비용이 A′ 대비 0.69 [0.58, 0.87] 이다. (§6.4 · 한계 5)

**Q7. 기대비용의 λ = 2,000 Wh/K·h 는 임의값 아닌가?**
임의로 정한 값이 맞다. 그래서 1,000–4,000 으로 바꿔 봤고 기대비용 비는 0.70 안팎으로 같았다. 다만 습도 불쾌까지 넣으면 0.89–0.91 로 줄고 구간이 1 을 넘는다 — 이것도 보고서에 그대로 적었다. (§6.4)

**Q8. 전력량은 어떻게 쟀나?**
시뮬레이션이라 실측이 아니다. 가전별 전력 모델(docs/06 · 08)로 추정하고, 모든 방식에 같은 모델 · 같은 범위(계량 플러그 + 자기 장치)를 적용했다. 그래서 절대값이 아니라 같은 조건 짝의 비율로만 비교했다. (§4 · 한계 1)

## C. 설계

**Q9. 왜 강화학습이나 MPC 를 쓰지 않았나?**
원룸 구성이 집마다 다르고 학습 데이터가 없는 상황에서, 해석 가능하고 안전 계층을 보장할 수 있는 규칙 + 모드 + 이벤트 구조를 먼저 택했다. 프리쿨링에는 제어용 2R2C 열모델로 기대비용을 최소화하는 계획기를 일부 썼다. 학습 기반 방식과의 직접 비교는 같은 하네스에서 사전 등록 후 실험할 계획(EXP-5)이다. (§2 · §8)

**Q10. CO₂ 센서 없이 환기를 어떻게 보장하나?**
재실 중에는 모드별 기본 환기량(일반 25 · 공부 40 · 수면 16 m³/h)을 늘 공급한다. CO₂ 는 시뮬레이션 참값으로 확인만 했고 제어기는 구독하지 않는다. 부품비를 줄이려는 결정이고, 다인 재실처럼 기본 환기량 가정이 깨지면 부족할 수 있다. (§3.1)

**Q11. 문 센서와 3분 판정 창으로 재실을 판단하면, 문 센서가 고장 나면?**
문 센서 이상(모순 신호 · 24시간 문 이벤트 없음 · 10분 이상 열림)을 감지하면 레이더 · Wi-Fi · 가전 전력을 쓰는 24시간 융합 판단으로 넘어가고 사용자에게 알린다. 외출 모드에서 문이 열리고 60초 뒤에도 사람이 감지되면 외출을 해제한다. 범위는 단일 거주자 · 출입구 하나로 가정했다. (§3.2 · 한계 4)

**Q12. 흡기팬이 60 m³/h 로 너무 작지 않나 — 후드 배기량은 300–450 m³/h 인데?**
맞다, 장비 한계다. 사양을 바꾸지 않고 민감도 실험만 했다 — 300 m³/h 면 요리 + 외기 미세먼지 상황에서 PM 피크 −37 %, 틈새 유입 −83 % 지만 에너지 +22 %, 덕트 타공(임대 원룸) · 소음 · 부품비가 늘어 저가 리트로핏이라는 전제와 맞지 않는다. 개선 비용으로 보고했다. (§6.9 · 한계 10)

## D. 안전 · 물리

**Q13. 끼임 안전을 표준에 맞췄다고 할 수 있나?**
아니다. 차량 창문 표준 FMVSS 118 의 100 N 기준만 빌렸고, 반전 거리 요건(125 mm 이상)은 충족하지 않는다 — 현재 반전은 50 mm 로, 끼임 뒤 창문이 덜 열린 채 남는 쪽을 택했다. 건물 창 구동 장치 표준(IEC 60335-2-103) 적합도 주장하지 않는다. 시뮬레이션에서 끼임 감지 165/165 · 오검출 0/20 · 최대 86.5 N 이고, 안전 계층이 없으면 112–126 N 이었다. (§6.11 · 한계 11)

**Q14. 물리 모드가 8개 시나리오 · 반복 3회뿐인데 고속 모드 결과를 믿을 수 있나?**
물리 시나리오를 고속으로도 돌려 비교했다. 참값 온도 차이는 대부분 0.03 °C 이내였고 판정 9개 중 7개가 같았다. 갈린 2개는 구동 횟수 판정 — 액추에이터 동역학이 다르기 때문이다. 그래서 환경 결과는 고속이 잘 대신하지만 구동 횟수 같은 지표는 모드에 민감하다고 적었다. 또 고정 조건 물리 반복은 같은 궤적이어서, 조건을 무작위로 바꾸자 24/24 → 20/24 로 떨어졌다 — 이 값을 보고했다. (§6.7–6.8 · 한계 8–9)

**Q15. 센서가 틀리면 어떻게 되나?**
데이터시트 범위의 편향 · 드리프트 · 이상값 · 끊김을 넣었을 때 전체 86.7 %, 환경 결과 90.9 % 로 떨어졌다. 가장 큰 약점은 습도 편향 — 바깥이 더 건조해 보이면 습한 외기를 배기로 들인다(이슬점 비교 규칙 I10). 가장 현실적인 약점으로 보고했고, 실물에서는 습도 센서 교차 확인이 필요하다. (§6.6 · 한계 6)
