## 2. 판정 기준 사후 개정 — 같은 로그를 개정 전 · 현재 기준으로

개정 직전 커밋의 `pass_criteria` 로 **지금 로그**(고속 210 · 물리 39회)를 다시 판정했다. 로그와 타임라인은 현재 시나리오를 쓴다.

| 시나리오 | 개정 (docs/03) | 개정 전 기준 — 제안 | 현재 기준 — 제안 | 개정 전 기준에서 실패한 판정 | 개정 성격 |
|---|---|---:|---:|---|---|
| C1 | v2.13 습도 완화 | 0 % | 100 % | 30분 안에 RH ≤ 60 % | **물리 한계** — 에어컨 제습 0.5 L/h · 비 오는 날 흡기 습기 부하 |
| C13 | v2.13 습도 완화 | 0 % | 100 % | 30분 안에 RH ≤ 60 % | 물리 한계 (같은 이유) |
| X5 | v2.19 RH 회복 30 → 90분 · 흡기 원복 기준 | 0 % | 100 % | 30분 안에 RH ≤ 60 % · 요리 끝 5분 안에 흡기 원복 | 물리 한계 · 판정 시점 정의 |
| C15 | v2.17 건조 4 → 6 h | 0 % | 100 % | 빨래 4시간 안에 건조 | 물리 한계 — 비 오는 날 기본 환기 습기 부하 |
| C9 | v2.1x PM 피크 −30 % → −15 % (이후 에너지 · 과열 판정 변경) | 0 % | 100 % | PM 피크 ≤ A × 0.7 | **목표 하향** |
| C11 | v2.15 에너지 B 이하 → 장치 전환 B 대비 −50 % | 0 % | 100 % | 에너지 ≤ B | 판정 대상 변경 (에너지 → 불필요 구동) |
| B6 | 샤워 감지 시간 · 회복 30분 | 0 % | 100 % | 샤워 시작 2분 안에 감지 | 감지 시간 완화 (300 s) |
| B1 | v2.27 기본 환기 창문 틈 허용 | 0 % | 100 % | 창문 ≤ 1 % 상시 | **설계 변경**(기본 환기 10 % 틈) 뒤 기준 교체 |
| B2 | v2.27 부분 차광 | 0 % | 100 % | 30초 안에 블라인드 ≥ 72° | 설계 변경(눈부심 부분 차광) 뒤 기준 교체 |
| C3 | v2.29 '열원 먼저' 폐지 · 입력 개정 | 0 % | 100 % | 블라인드 먼저 · 2분 안에 ≥ 70° · 에너지 ≤ A | 설계 변경(블라인드 × 창문 순 열량 선택 — 사용자 피드백) 뒤 기준 교체 |
| B3 | v2.29 블라인드 판정 변경 | 100 % | 100 % | — | 영향 없음 |

기준선 A: C1 · C9 · C11 · C13 · C15 는 개정 전 · 현재 모두 0 %, C3 은 0 % → 100 %. 기준선 B: C11 은 둘 다 100 %, C1 · C3 · C9 · C13 · C15 는 0 % → 100 %.
(전체 표: `results/tables/criteria_revisions.md`)

**논문 서술:**
- 개정은 세 종류로 나눠 밝힌다.
  - **물리 한계로 기준을 바꾼 것** (C1 · C13 · X5 · C15): 같은 원룸 · 같은 장비로는 개정 전 목표에 닿을 수 없다. 장비 용량 한계로 서술하고, 기준선 A · B 도 같은 조건에서 함께 보인다.
  - **목표를 낮춘 것** (C9): 개정 전 목표(−30 %)는 미달로 그대로 보고한다. 지표 #10 도 −14.9 % 로 −15 % 목표에 미달이다.
  - **설계를 바꾼 뒤 기준을 교체한 것** (B1 · B2 · C3 · C11 · B6): 바뀐 설계와 그 이유(사용자 피드백 · 상충 점검)를 함께 밝힌다.
- "개정 전 기준으로는 11개 시나리오 중 10개에서 제안 제어기가 판정을 통과하지 못한다"는 사실을 숨기지 않는다.

## 5. 보류(held-out) 시나리오 — 사전 등록 (docs/11 필수 조치 4)

| 항목 | 내용 |
|---|---|
| 제어기 동결 | 2026-10-19 · `config/freeze.yaml` controller — `scripts/controller` · `scripts/sensors` · `scripts/actuators` · `harness/controllers.py` · `config/thresholds.yaml` 전체 · `models/` (점검 `check_freeze.py --group controller`) |
| 보류 묶음 | `config/heldout_scenarios.yaml` H1–H12 (12개 · 고속 · 기준선 A · B · 제안 또는 제안만) — **실행 전에 이 커밋으로 등록**하고 해시를 files 묶음에 넣었다 |
| 만든 방법 | 기존 규칙(I1–I10 · E1–E15)과 기존 판정 문구를 그대로 쓰고 **조합만 새로** 했다(각 판정 옆에 출처 시나리오). 제어기를 돌려 보지 않고 썼다 |
| 규칙 | 결과가 나빠도 H1–H12 의 입력 · 판정을 고치지 않는다. 제어기를 고치면 controller 묶음을 다시 쓰고 **새 보류 묶음**(H2xx)을 만들어 다시 평가한다 |
| 알려진 결함 | 필수 조치 3 실측 기상 평가에서 찾은 제어기 결함(B8 냉방 ↔ 제습 전환 · C4 자연 냉방 ↔ 에어컨)은 고치지 않은 채 동결했다 — 보류 평가는 지금까지 보고한 모든 결과를 낸 그 제어기를 채점한다 |

| 시나리오 | 조합 (출처) |
|---|---|
| H1 | 여름밤 샤워 + 외기 미세먼지 나쁨 (B6 · C8 · C19) |
| H2 | 플러그형 인덕션 2 kW + 냉방 + 전력 한도 2.5 kW (C17 · C4) |
| H3 | 겨울 요리 + 결로 위험 (B7 · C10 · C19 · C9) |
| H4 | 열대야 수면 + 비 (C5 · C12 · C18 · X1) |
| H5 | 비 오는 날 귀가 → 요리 (B12 · C9 · C18 · C19) |
| H6 | 한낮 일사 + 외기 미세먼지 나쁨 (B8 · C8) |
| H7 | 에어컨 IR 간헐 누락 50 % + 더위 (B8 · X7) |
| H8 | 겨울 빨래 건조 — 바깥 건조 (C15 · C19 · C10) |
