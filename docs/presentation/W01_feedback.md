## 3. 원인 분석 — 피드백 ①이 왜 나왔나

발표 시점(v1.0)의 시나리오 S1–S7을 **조건 개수 × 액추에이터 개수**로 분해해 보면 문제가 명확하다.

| 기존 ID | 조건 수 | 액추에이터 수 | 협조 발생? |
|---|---:|---:|---|
| S1 저조도 | 1 | 1 | ❌ 단일 매핑 |
| S2 과조도 | 1 | 2 | △ 순차 동작 |
| S3 고온 | 1 | 3 | △ 충돌 없음 |
| S4 고온+장애물 | 2 | 2 | ✅ **유일한 협조 사례** |
| S5 무재실 | 1 | 4 | ❌ 전부 OFF |
| S6 경계 진동 | 1 | 2 | ❌ 히스테리시스 검증 |
| S7 수동+장애물 | 2 | 1 | △ 안전 검증 |

> **7개 중 실제로 협조 제어가 관찰되는 것은 S4 하나뿐이었다.** 피드백은 정확한 지적이었다.
>
> **근본 원인:** 협조 제어는 **"제약이 서로 충돌할 때"만 관찰된다.**
> 온도만 높으면 창문을 열면 그만이다. 조건을 하나씩만 준 시나리오로는 협조가 발생할 여지가 없었다.

## 4. 대응 — 기획 v2.0 개정 내역

### 4.1 피드백 ① → 시나리오 16개 3계층 재설계

**제약 충돌 개수로 계층화**했다.

| 계층 | 개수 | 성격 | 역할 |
|---|---:|---|---|
| 🟢 Tier 1 (B1–B5) | 5 | 단일 조건 | 회귀 테스트 |
| 🟡 **Tier 2 (C1–C7)** | 7 | **2개 제약 충돌** | **협조 제어의 본체** |
| 🔴 Tier 3 (X1–X4) | 4 | 3중 제약 · 실패 처리 | 성숙도 입증 (선택 과제) |

**피드백에서 직접 지목된 사례는 C1로 확정**했다 — *고온 + 고습 + 우천 → 창문 폐쇄 유지, 팬 최대로 역할 전면 이전*.
Baseline A는 온도 규칙만 보고 창문을 열어 **비가 들이쳐 습도가 오히려 상승**하는 대비가 성립한다.

**부수 변경:** 습도가 온도와 동등한 상태 변수로 승격(W08 습도 갱신식 신설), 외부 기상(강우) 입력 추가,
평가 지표에 습도 유지율 포함, 실행 횟수 63회 → **90회**.

📄 [`03_scenarios.md`](../03_scenarios.md) 신규 작성

### 4.2 피드백 ② → 알고리즘 기반 센서 최소화

제안하신 PIR + mmWave 조합은 업계 검증 패턴 **"PIR-validates, mmWave-holds"** 와 일치했다.

```text
입실 : PIR 트리거      → 즉시 재실 판정 (빠른 응답)
유지 : mmWave 감지     → 자거나 앉아 있어도 유지 (정지 인체)
퇴실 : 양쪽 클리어     → 비재실
오검출(커튼·옆방) : PIR 미검출로 교차 기각
```

**추가로 3개 센서를 알고리즘으로 대체**했다.

| 제거 | 대체 | 절감 |
|---|---|---:|
| 책상 조도 센서 | `E_desk = f(천장조도, 스탠드 명령값, 기하)` | 2,000원 |
| mmWave 2번째 | **거리 게이트 매핑** (게이트 2–3=책상, 5–6=침대) | 11,900원 |
| 초음파 HC-SR04 | 전류 리플 anti-pinch (피드백 ③) | 2,000원 |
| 우적 센서 | 기상청 단기예보 API | 5,000원 |

| | Naive 구성 | **최소화 구성** |
|---|---:|---:|
| 부품 수 | 7개 | **4개 (−43 %)** |
| 비용 | 39,800원 | **24,100원 (−39 %)** |

**부수 효과:** 무재실 타임아웃 **300 s → 60 s** 단축.
v1.0의 300초는 *"PIR이 정지 인체를 놓치므로"* 필요했던 보정값이었는데, mmWave가 그 문제를 해결했다.

### 4.3 피드백 ③ → 전류 리플 센서리스 전환

조사 결과 **자동차 파워윈도우 anti-pinch**의 성숙 기술이었다. 두 갈래 중 **Ripple 방식**(완전 무센서)을 채택했다.

| 요구사항 | 구현 |
|---|---|
| "처음엔 토크를 크게, 서서히 작게" | **Zone A–D 토크 프로파일** — 기동 100 % → 주행 55 % 선형 점감 |
| "엔드존 램프 검출·보상" | 위치 + 전류 기울기 + 지속거리 3조건으로 **씰 압착(완만한 램프)과 끼임(급격한 계단) 구분** |
| "모터 과부하 징후로 정지" | 전류 초과 ∧ 속도 저하 ∧ 디바운스 ∧ 감지구간의 4조건 AND |
| "창틀 아래쪽 설치" | **랙-피니언 방식** — 창틀 하부에 랙, 패널에 모터+피니언 (한국 특허 KR20090056308A) |
| 2024 저비용 anti-pinch 연구 반영 | **적응형 임계값** — 온도·마모 드리프트를 최근 5회 정상 주행으로 학습 보상 |

📄 [`04_sensorless_window_control.md`](../04_sensorless_window_control.md) 신규 작성

#### ⚠️ 이중화가 아닌 센서리스 단독으로 확정

설계 검토 단계에서 **초음파 1차 + 전류 2차의 이중화**를 제안했으나, **센서리스 단독으로 진행하기로 결정**했다.
*"센서를 제거한다"* 는 피드백 ③의 목표와 이중화가 상충하기 때문이다.

**이 결정의 결과로 안전 기능의 성격이 바뀌었다. 이를 은폐하지 않고 명시한다.**

| | v1.0 초음파 | **v2.0 센서리스** |
|---|---|---|
| 감지 시점 | 접촉 **전** | 접촉 **후** |
| 안전 개념 | **예방** | **피해 최소화** |
| 목표 지표 | 인터록 반응 200 ms | **최대 접촉 반력 ≤ 100 N** (FMVSS 118 참조) |

→ 문서·발표 전반에서 *"장애물을 미리 감지해 멈춘다"* 는 표현을 삭제하고,
**"끼임 발생 시 즉시 정지·반전하여 접촉 반력을 100 N 이하로 제한한다"** 로 통일했다.

#### 🎯 부수 효과 — 프로젝트 존재 이유가 강해졌다

| v1.0 논거 | **v2.0 논거** |
|---|---|
| 하드웨어 제작 전 로직 검증 | **끼임 안전 실험은 실물로 반복할 수 없다** |

Isaac Sim의 **Effort Sensor**(Prismatic 조인트의 힘 측정)와 **Contact Sensor**로
사람 손이 끼이는 상황을 안전하게 수백 번 반복하고 최대 반력을 정량 측정할 수 있다.
**시뮬레이션만이 할 수 있는 실험**이라는 논거가 생겼다.
