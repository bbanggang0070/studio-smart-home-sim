# 교수님 피드백 2 반영 정리

팀 구해줘 홈즈 · 1인 가구 원룸 스마트홈 다중 액추에이터 협조 제어
3주차 발표에서 받은 교수님 피드백을 반영해 수정한 내용입니다. (수정한 내용은 「원룸 협조 제어 설계안」 문서에서 피드백과 관련된 부분만 뽑아 정리했습니다.)

---

## 1. 피드백 원문

> 특정 센서로만 해당 조건을 판단하지 말고 다른 상태를 통해 판단할 수 있는지 여부 확인하여
> → 시나리오 판단에 대해 효율적인 방법을 채택할 것.
> 반면에 동작은 다양한 actuator를 사용하여 여러 방면에 대처하도록 하는 것이 좋음.

### 두 가지 요구로 나누면

| | 요구 | 한 줄 해석 |
|---|---|---|
| ① 판단 | 센서 하나에 기대지 말고, 다른 상태로도 알아낼 수 있는지 확인해서 효율적인 방법을 고른다 | **센서는 적게, 판단은 여러 신호의 조합으로** |
| ② 동작 | 다양한 액추에이터로 여러 방면에 대처한다 | **다양한 기기를 조합해서, 상황이 달라져도 대처할 수 있게** |

여기서 "여러 방면"은 한 문제에 기기를 여러 개 두라는 뜻보다, **서로 다른 상황(계절, 날씨, 요리·샤워·수면 같은 행동)마다 알맞은 기기 조합으로 대처하라**는 뜻으로 읽는다. 그래서 기기 하나는 여러 상황에 쓰이고, 상황마다 기기 조합이 달라지도록 설계한다.

두 요구는 서로 연결된다. 센서를 줄이면 판단이 불확실해지는데, 기기를 조합해 움직인 뒤 **반응을 확인**하면 그 불확실함을 줄일 수 있다.

---

## 2. 설계 원칙

1. **판단은 적은 센서 + 여러 상태의 조합으로.** 상황마다 전용 센서를 달지 않는다. 기본 센서 몇 개, 기기 켜짐·전력, 바깥 날씨·대기 정보, 시간, 계산값을 엮어 상황을 알아낸다. 하나의 판단에는 서로 다른 신호를 2개 이상 쓴다. 측정하지 않는 값을 다른 값으로 계산하는 방식을 학계에서는 "가상 센서"라고 한다 (Li 외 2011).
2. **대응은 다양한 기기를 상황에 맞게 조합하기.** 기기 하나를 한 가지 용도에만 쓰지 않고, 여러 상황에 쓰이게 한다(서큘레이터는 더울 때, 빨래 말릴 때, 결로 막을 때 모두 사용). 상황이 바뀌면 같은 문제라도 기기 조합이 바뀐다. 문제마다 쓸 수 있는 기기가 여러 개라 하나가 막히거나 고장 나도 다음 기기가 맡는다.

## 3. 요구 ① 판단: 센서를 줄이고 다른 상태로 알아내기

### 3-1. 쓰는 센서는 2개뿐

| 구분 | 내용 |
|---|---|
| 기본 센서 | 실내 온습도 1개, 소리 센서(마이크) 1개. 소리는 기기 안에서 특징만 뽑고 음성은 저장하지 않음 |
| 선택 센서 | 현관문 열림 센서, 침대 쪽 사람 감지(레이더). 없어도 동작함 |

센서처럼 쓰지만 새로 달지 않는 신호가 나머지를 채운다.

| 신호 | 내용 |
|---|---|
| 측정하는 기기 | 전력 측정 플러그(가전마다), 창문 모터 전류, 공기청정기 내장 미세먼지 센서 |
| 제어기가 아는 값 | 조명 밝기, 블라인드 각도, 창문 위치, 팬 속도, 현재 모드 |
| 외부 데이터 | 기상청(기온·습도·강수·구름), 에어코리아(바깥 미세먼지), 태양 위치 계산 |
| 시간·생활 패턴 | 시각, 요일, 기상·취침 시각 |
| 공유기 | 휴대폰 와이파이 접속 여부 (원룸에 이미 있는 장치) |

### 3-2. 넣지 않는 센서와 대신 쓰는 방법

| 안 넣는 센서 | 대신 알아내는 방법 | 근거 |
|---|---|---|
| 조도 센서 | 조명은 제어기가 켜므로 이미 알고, 햇빛은 태양 위치·구름 양·블라인드 각도로 계산 | 채광 데이터와 블라인드 상태만으로 조도를 90~94% 맞힘 (Xie & Sawyer 2021) |
| 동작 감지(PIR) | 와이파이 + 생활 소리 + 가전 전력. PIR은 가만히 있는 사람을 놓침 | Wang C. 외 2021 등 |
| CO2 센서 | 재실 시간 × 1인 발생량 − 환기량으로 계산. 집에 있는 동안 최소 환기량은 항상 보장 | Persily & de Jonge 2017, Akimoto 외 2025 |
| 실내 미세먼지 전용 센서 | 공기청정기 내장 센서 + 요리 판단. 저가 측정기는 습도 50% 초과 시 정확도가 떨어지고 0.3μm 미만 입자를 놓침 | Levy Zamora 외 2019, Singer & Delp 2018 |
| 빗물 센서·표면 온도 센서 | 기상청 강수 정보, 이슬점 계산 | Hwang 외 2021 |

### 3-3. 판단 방식: 두 층으로 나누기

원룸은 방이 하나라 "사람이 있는가"와 "무엇을 하는가"를 매번 새로 재면 낭비다. 그래서 두 층으로 나눈다.

**1층. 외출·귀가와 재실**
- 외출·귀가는 **휴대폰 와이파이 접속·해제**로 판단한다. 접속하면 바로 귀가.
- 재실은 와이파이, 생활 소리, 행동 인식(가전 전력·기기 조작)을 종합해 판단하며, 하나라도 있으면 "집에 있음".
- 외출은 와이파이가 끊긴 뒤 다른 재실 증거가 15분 동안 없을 때만 확정한다.
- 휴대폰이 절전으로 끊겨도 요리 소리나 가전 전력이 있으면 외출로 보지 않는다.
- 자는 동안에는 조용하고 행동이 없는 것이 정상이므로, 수면 모드에서는 와이파이가 끊겨도 외출로 판단하지 않는다.
- 휴대폰을 두고 나가면 "집에 있음"으로 남지만, 낭비는 생겨도 불편은 없는 쪽으로 틀리는 것이라 허용한다.

**2층. 무엇을 하나 (집에 있을 때만)**
- 환경 제어를 바꾸는 여섯 가지(요리·샤워·빨래 건조·청소·수면·공부)만 본다.
- 재실을 다시 확인하지 않고 행동 신호만 본다. 외출 중에는 2층을 건너뛰고 습도·결로·비 같은 집 관리 판단만 남긴다.

**알아볼 행동은 기기 동작을 바꾸는 것만 고른다.** 기준은 "이 행동을 알면 기기 동작이 달라지는가"이다.

| 종류 | 행동 | 하는 일 |
|---|---|---|
| 환경을 바꾸는 행동 | 요리, 샤워, 빨래 건조, 청소 | 열·습기·먼지가 생기므로 원인을 바로 처리 |
| 쾌적 기준을 바꾸는 행동 | 수면, 공부·작업 | 생기는 것은 없고 목표 온도·밝기·소음 허용치가 바뀜 |

휴식·TV·식사·양치처럼 기기 동작이 그대로인 행동은 따로 분류하지 않고 "집에 있음(일반 모드)"으로 둔다.

### 3-4. 상황별 판단: 어떤 신호를 조합하나

설계안의 상황 표 20개 중 대표 항목만 추린 것이다. 전체는 설계안 2장에 있다.

| 알아야 할 것 | 신호 조합 | 확정 방법 |
|---|---|---|
| 외출·귀가 | 휴대폰 와이파이 접속·해제 (+선택: 현관문) | 접속하면 귀가. 끊긴 뒤 15분간 재실 증거가 없으면 외출 |
| 집에 있나 | 와이파이 + 생활 소리 + 행동 인식 | 하나라도 있으면 재실. 수면 모드 중에는 유지 |
| 자는 중 | 밤 시간 + 조명 꺼짐 + 가전 전력 거의 없음 + 조용함 (+선택: 침대 레이더) | 모두 맞고 10분 이상 유지 |
| 요리 중 | 조리기구 전력 + 조리 소리 + 후드 켜짐 + 온습도 상승 + 청정기 미세먼지 급등 | 조리 전력이 있고 나머지 중 1개 |
| 샤워 | 습도 급상승 + 온도 동반 상승 + 물소리 + 조리 전력 없음 + 욕실 환풍기 켜짐 | 습도 상승 속도가 기준을 넘고 조리 전력 없음 |
| 빨래 말리는 중 | 세탁기 전력 종료 후 습도 완만·장시간 상승 + 온도 변화 없음 + 조리·샤워 신호 없음 | 1시간 이상 완만한 상승 |
| 공기가 탁하다 | 추정 CO2 + 창문·팬 상태 | 추정값이 기준을 넘거나 재실 중 최소 환기량에 못 미침 |
| 결로 위험 | 실내 온습도 → 이슬점 + 바깥 기온 → 유리 표면 온도 추정 | 표면 온도가 이슬점에 2°C 이내로 접근 |
| 비 | 기상청 강수 + 창문이 열린 상태에서 습도 급등 | 둘 중 하나만 맞아도 창문 닫음(안전 쪽) |
| 창문을 손으로 열었나 | 모터 위치 기록 + 실내 온습도 급변 + 바깥 소음 유입 | 명령 없이 온습도가 급변하고 바깥 소리가 커짐 |
| 기기가 실제로 동작하나 | 명령 + 플러그 전력 + 예상한 환경 변화 | 명령 후 전력 변화 없음 → 재시도 → 다음 기기 |

**예외.** 창문 끼임은 모터 전류 신호 하나로 즉시 정지한다. 안전은 확인할 시간이 없기 때문이다. 같은 이유로 비도 둘 중 하나만 맞으면 창문을 닫는다.

### 3-5. 한 신호가 틀려도 다른 신호가 받쳐 주는 예

| 상황 | 한 신호만 쓰면 | 조합하면 |
|---|---|---|
| 휴대폰 와이파이가 절전으로 끊김 | 외출로 잘못 판단 | 요리 소리·가전 전력이 있으면 집에 있음 유지 |
| 조용하게 책 읽는 중 | 소리만 보면 빈집으로 오판 | 와이파이 접속이 있으면 재실 |
| 습도가 올라감 | 원인을 몰라 대응이 틀림 | 조리 전력이 있으면 요리, 없고 물소리가 있으면 샤워, 세탁기가 끝났으면 빨래 |

### 3-6. 소리 센서 하나로 여러 행동 알아내기 (주파수 분석)

소리 센서는 마이크 하나지만, 소리를 **주파수로 나눠 보면**(FFT, 멜 스펙트로그램) 물소리·튀김 소리·청소기 소리처럼 행동마다 다른 모양이 나온다. 그래서 행동마다 센서를 따로 달지 않고 마이크 하나로 여러 행동의 신호를 얻는다. 피드백 ①의 "특정 센서 대신 다른 상태로 판단"에 해당한다.

**근거 논문 (2023~2025, 동료 심사)**

| 논문 | 알아내는 것 | 장치·방법 | 결과 |
|---|---|---|---|
| Comai 외, *Sensors* 25(19):6221, 2025 | 샤워·세면대·변기·비데 물소리 (동시에 틀어도 구분) | 마이크 1개(MAX9814) + **ESP32**, 1024점 FFT(512개 주파수 칸, 약 11 Hz 간격), 작은 신경망으로 기기 안에서 판단 후 결과만 전송 | 정확도 90.6% |
| Hyun, *Sensors* 24(1):22, 2024 | 샤워·수도꼭지·변기 물 내림 | 마이크 + 라즈베리파이 4, 16 kHz, 멜 스펙트로그램. YAMNet으로 물소리를 먼저 거른 뒤 종류 구분 | 욕실 3곳 F1 0.95~1.00 |
| Shabbir 외, *Frontiers in Big Data* 7, 2025 | 문 여닫기·오븐·수돗물·걷기 등 11종 + 소리 위치 | 마이크 6개, MFCC·스펙트럼 중심 등 주파수 특징 + 랜덤 포레스트 | 정확도 95.0% (딥러닝 81.9%보다 단순 모델이 더 좋음) |
| Cheimariotis & Mitianoudis, *Information* 14(10):534, 2023 | 집 안 소리 10종 (믹서기·튀김·청소기·설거지·물소리·말소리 등) | 주파수 대역마다 가중치를 다르게 주는 "주파수 동적 합성곱", 표준 데이터셋 DESED | 모델 약 500만 파라미터, 다른 방법보다 계산량 적음 |
| Park 외, *ACM TECS*, 2025 (연세대) | 가정 내 소리 이벤트 | 초저전력 MCU(MSP430), 소리 지속 시간을 예측해 반복 처리 줄임 | 에너지 97~98% 절감, 오류율 4.7% |

**설계에 쓰는 곳**

| 행동 | 소리로 얻는 신호 | 다른 신호와 조합 | 근거 |
|---|---|---|---|
| 샤워 | 물소리 | + 습도 급상승 + 조리 전력 없음 | Comai 2025, Hyun 2024 |
| 요리 | 튀김·지글거림, 믹서기, 설거지 소리 | + 조리기구 전력 + 온습도 상승 | Cheimariotis 2023 |
| 청소 | 청소기 소리 | + 청소기 플러그 전력 + 미세먼지 상승 | Cheimariotis 2023 |
| 재실 | 생활 소리(문 여닫기, 걷기, 물소리 등) | + 와이파이 + 가전 전력 | Shabbir 2025 |
| 창문을 손으로 열었나 | 바깥 소음 유입(소리 크기 상승) | + 모터 위치 기록 + 온습도 급변 | — (설계 가정) |

처리는 Comai 2025처럼 **ESP32에서 주파수 분석과 판단을 끝내고 결과(행동 이름)만 보낸다.** 소리 자체는 밖으로 나가지 않는다.

**사생활 보호: 주파수로 말소리 빼기**

"음성은 저장하지 않음"을 지키는 구체적인 방법으로 두 가지가 있다.

| 논문 | 방법 | 결과 |
|---|---|---|
| Iravantchi 외, PrivacyMic, *CHI* 2021 | 사람 말소리 대역을 버리고 들리지 않는 초음파 대역만으로 행동 인식 | 사람이 녹음을 받아 적지 못함, 가정·직장 물건 127종 정확도 95% 이상 |
| Kirigami, *ACM IMWUT* 8(1), 2024 | 가벼운 모델로 말소리 구간만 지우고 나머지 소리로 행동 인식 | 음성인식 단어 오류율 101%(내용 복원 불가), 행동 인식 정확도 76%, ARM Cortex-M4F에서 동작 |

PrivacyMic은 초음파용 마이크가 따로 필요하고, Kirigami는 말소리를 지우면 정확도가 떨어진다(76%). 그래서 우리 설계는 소리만으로 확정하지 않고 **전력·습도와 조합**해서 떨어진 정확도를 보완한다.

## 4. 요구 ② 동작: 다양한 기기를 조합해 여러 상황에 대처하기

### 4-1. 기기 13개

블라인드, 전동 창문(10·30·100% 단계), 필터 흡기팬, 욕실 환풍기, 레인지후드, 공기청정기, 서큘레이터, 에어컨, 제습기, 가습기, 바닥난방(보일러 온도조절기), 조명·스탠드, 스마트 플러그. 알림도 하나의 동작으로 친다.

### 4-2. 문제별 대응 순서 (싼 기기부터)

| 문제 | 대응 순서 | 근거 |
|---|---|---|
| 더움 | 블라인드 닫기 → 창문(바깥이 시원하고 깨끗할 때) → 서큘레이터 → 에어컨(서큘레이터와 함께, 설정온도는 높게) | 팬을 에어컨보다 먼저 돌려 압축기 에너지 36% 절감 (Miller 외 2021). 설정온도 22.2→25°C로 냉방 에너지 평균 29% 절감 (Hoyt 외 2015) |
| 추움 | 창문 닫기 → 낮에는 블라인드 열어 햇빛 들이기 → 바닥 난방 → 에어컨 난방 보조 | 설계 가정 |
| 습함 | **원인부터**: 샤워면 욕실 환풍기, 요리면 후드 → 바깥이 건조하면 환기 → 방이 덥으면 에어컨 제습, 아니면 제습기 | 설계 가정 (제습기 열과 에어컨의 충돌을 피함) |
| 건조 | 가습기 (결로 여유가 부족하면 제한) | 설계 가정 |
| 탁한 공기 | 필터 흡기팬 → 창문(바깥이 깨끗하고 온도차가 작을 때) → 욕실 환풍기 병행 | 수면 중 CO2 1,000ppm에서도 수면 효율 저하 (Kang 외 2024) |
| 실내 미세먼지 | 공기청정기 → (요리 중) 후드 + 필터 흡기로 빠진 공기 채우기 | 후드 + 보충 급기로 조리 후 PM2.5 96.9% 제거 (Kang 외 2025). 자동 제어가 수동 대비 아파트 전체 PM2.5 40% 감소 (Pantelic 외 2024) |
| 결로 위험 | 가습 줄이기 → 서큘레이터를 창 쪽으로 → 짧은 환기 → 제습기 | Hwang 외 2021 (예측 후 사전 환기) |
| 어두움·눈부심 | 블라인드 각도 → 조명·스탠드 | Xie & Sawyer 2021 |
| 전기 몰림 | 미뤄도 되는 기기(제습기·가습기·대기전력)부터 잠시 중단 | 설계 가정 |

한 문제에 기기가 3개 안팎 걸려 있어서 앞의 기기가 막히거나 고장 나면 다음 기기가 맡는다. 같은 기기가 여러 문제에 쓰이므로 서로 충돌하지 않게 4-4의 협조 규칙이 조정한다.

### 4-3. 기기 하나가 여러 상황에 쓰인다

위 대응 순서 표를 기기 기준으로 뒤집으면, 기기 하나가 서로 다른 상황에서 다른 역할을 한다.

| 기기 | 쓰이는 상황과 역할 |
|---|---|
| 블라인드 | 더울 때 햇빛 차단, 추울 때 햇빛 들이기, 어두울 때 채광 조절 |
| 전동 창문 | 더울 때 바깥 공기 환기, 탁한 공기 환기, 습할 때 환기, 결로 전 짧은 환기 |
| 서큘레이터 | 에어컨 보조(냉방), 빨래 건조 때 공기 순환, 결로 막으려고 창 쪽으로 송풍 |
| 에어컨 | 냉방, 난방 보조, 방이 더울 때의 제습 |
| 제습기 | 습할 때 제습, 빨래 건조, 결로 위험 |
| 필터 흡기팬 | 탁한 공기 환기, 요리 중 후드로 빠진 공기 채우기 |
| 욕실 환풍기 | 샤워 습기 배출, 탁한 공기 환기 병행 |
| 레인지후드 | 요리 중 열·연기·습기 배출 (요리 때만) |
| 공기청정기 | 미세먼지 제거, 청소 후 강풍 |
| 가습기 | 건조할 때 가습 (결로 위험이면 제한) |
| 바닥난방 | 추울 때 난방 |
| 조명·스탠드 | 어두울 때, 공부 때 책상 빛 |

그래서 같은 기기 13개로 아래처럼 **상황마다 다른 조합**이 나온다. 예시이며 기준은 위 표와 설계안 시나리오를 따른다.

| 상황 | 조합되는 기기 | 조합 이유 |
|---|---|---|
| 여름 낮 요리 | 후드 + 필터 흡기팬 + 블라인드 + 서큘레이터 → 에어컨 | 열·연기는 후드가 빼고, 빠진 공기는 흡기팬이 채우고, 햇빛은 블라인드로 차단 |
| 비 오는 날 빨래 건조 | 제습기 + 서큘레이터 (창문은 닫힘) | 창문을 못 여니 제습과 공기 순환으로 대신 |
| 겨울 샤워 직후 | 욕실 환풍기 + 가습 중단 + 서큘레이터(창 쪽) → 제습기 | 습기를 빼면서 결로를 함께 막음 |
| 수면 중 공기가 탁해짐 | 필터 흡기팬(저소음) + 창문 일부 열기, 에어컨은 제외 | 수면 목표가 우선이라 소음·찬 바람 큰 기기는 피함 |
| 봄 낮 미세먼지 나쁨 | 공기청정기 + 필터 흡기팬, 창문은 닫힘 | 바깥 공기가 나쁘니 환기 대신 정화로 대응 |

이 방식이면 기기를 문제마다 따로 두는 것보다 적은 기기로 더 많은 상황을 다룰 수 있고, 한 기기가 막혀도 다른 조합으로 넘어갈 수 있다.

### 4-4. 협조 규칙: 4단계

매 주기마다 아래 순서로 돌고, 반응이 없으면 되돌아가 다음 기기를 시도한다.

1. **안전 확인.** 창문 끼임, 비, 전력 한도는 다른 모든 판단보다 먼저 처리한다. 이 단계만 신호 하나로도 즉시 움직인다.
2. **목표 정하기.** 현재 모드의 목표 범위를 불러오고, 목표끼리 부딪히면 **건강 > 수면 > 쾌적 > 에너지** 순서로 정한다. 목표 범위에 여유 폭을 두어 기기가 자주 켜졌다 꺼지지 않게 한다.
3. **기기 고르기.** 문제별 대응 순서에서 싼 기기부터 본다. 그 기기를 쓰면 다른 목표가 30분 안에 나빠질 것 같으면 건너뛴다(예: 바깥 미세먼지가 나쁜데 창문 열기). 전기를 많이 쓰는 기기는 문제가 일정 시간 계속될 때만 켠다.
4. **반응 확인.** 기기를 켠 뒤 플러그 전력이 올랐는지, 환경 값이 예상대로 변하는지 본다. 변화가 없으면 한 번 더 시도하고, 그래도 없으면 "응답 없음"으로 표시하고 다음 기기로 넘어간다. 기기를 움직여 보고 반응으로 고장을 찾는 방식은 건물 설비 고장 진단 연구에서 쓰는 방법이다 (Li 외 2011).

사용자가 직접 조작하면 그 기기는 일정 시간 자동 제어를 멈춘다.

### 4-5. 두 요구가 맞물리는 부분

- **센서 대신 기기로 상태를 확인한다.** "기기가 실제로 동작하나"는 별도 센서 없이 명령 + 플러그 전력 + 예상한 환경 변화로 판단한다. "사용자가 직접 조작했나"도 기기 전력이 마지막 명령과 다른지만 본다.
- **판단이 틀려도 기기가 받쳐 준다.** 요리로 잘못 판단해 후드를 켰는데 소음·전력 변화만 있고 습도·미세먼지가 그대로면, 반응 확인 단계에서 걸러져 다음 대응으로 넘어간다.

## 5. 검증 계획: 피드백 반영 효과를 어떻게 보이나

Python 환경 모델(열·수분·CO2·미세먼지)로 같은 날씨·생활 패턴을 세 방식에 넣어 비교한다.

| 방식 | 판단 | 동작 |
|---|---|---|
| 기기별 자동화 (기준 방식) | 기기마다 자기 센서 하나로 | 기기 하나씩 따로 |
| 협조 (반응 확인 없음) | 신호 조합 | 여러 기기 순서대로 |
| 협조 전체 | 신호 조합 | 여러 기기 + 반응 확인 |

이 비교로 두 요구를 따로 확인할 수 있다. 첫째와 둘째의 차이가 **다양한 기기를 조합해 대처한 효과**, 둘째와 셋째의 차이가 **반응 확인으로 판단 오류를 줄인 효과**다. 오판·고장 시나리오(설계안 5장 ④, 8개)에서 기준 방식과 협조 방식의 차이가 가장 크게 나와야 한다.

## 6. 한계 (설계 가정으로 표시한 부분)

근거 논문을 찾지 못해 **직접 정한 가정**이며, 시뮬레이션과 실측으로 확인해야 한다.

- 1인 원룸에서 휴대폰 와이파이만으로 재실을 판단하는 방식
- 값싼 신호만으로 수면을 판단하는 방식 (밤 시간 + 조명 + 전력 + 소리, 10분 유지)
- 샤워와 빨래 건조를 습도 변화 속도로 구분하는 방식
- 비를 기상청 API로 판단하는 방식
- 공기청정기 내장 센서의 미세먼지 정확도
- 적외선 리모컨 명령이 먹혔는지를 전력으로 확인하는 방식
- 기준값 전부 (15분, 10분, 와트 값, 습도 상승 속도 등)
- 기준값은 집마다 달라서 처음 몇 주 동안 그 집에 맞게 보정하는 것을 전제로 한다 (Bouchabou 외 2021)
- 소리 인식 논문들은 대부분 욕실 같은 정해진 공간에서 시험했다. 원룸처럼 TV 소리 등이 섞이는 한 공간에서의 정확도는 따로 확인해야 한다
- 창문을 손으로 열었는지를 바깥 소음 유입으로 판단하는 방식

## 7. 발표에서 한 줄로 말하기

> 센서는 온습도·소리 2개만 쓰고 나머지는 전력·날씨·시간·계산으로 상황을 알아냅니다. 대신 13개 기기를 상황마다 다르게 조합해서(같은 서큘레이터도 더울 때, 빨래 때, 결로 때 다르게 씁니다) 여러 상황에 대처하고, 기기를 움직인 뒤 반응을 확인해서 판단이 틀렸으면 다음 기기로 넘어갑니다.
