## 1. 프로젝트 개요

### 무엇을 하는가

기존 스마트홈은 **넓은 집 · 고가 허브 · 스마트 가전 일괄 교체**를 전제로 설계된다. 그러나 국내 1인 가구는 전체의 약 1/3이며,
다수가 **17~20 m² 원룸**에 산다. 원룸 거주자는 이미 에어컨 · 제습기 · 공기청정기 같은 가전을 갖고 있지만,
**가전들이 서로를 모른 채 각자 동작**한다. 에어컨은 창문이 열린 줄 모르고, 가습기는 창에 물이 맺히는 줄 모른다.

> **"가전을 새로 만들거나 바꾸지 않고, 이미 있는 가전을 연결해 서로 역할을 나누게 하는 것"** 이 원룸에 맞는 해법이다.

본 프로젝트는 **11만 원대 인터페이스 · 센서 구성**으로 이를 구현하고, 실물 제작 전에 **Isaac Sim 가상 원룸에서 제어 · 안전 로직을 검증**한다.

### 해결하려는 문제

| # | 원룸 거주자의 불편 | 본 프로젝트의 대응 |
|---|---|---|
| 1 | 외출 후 조명 · 에어컨 방치 | 재실 융합 센싱 · **외출 모드** 자동 전환 |
| 2 | 여름철 과열 · 냉방비 | **수단 사다리** — 블라인드 → 창문 → 실링팬 → 에어컨 순으로 협조 |
| 3 | 강한 햇빛 · 눈부심 | 조도 · 일사 기반 자동 차광 |
| 4 | 창문 개폐 시 끼임 — 저가 제품엔 안전 기능이 없다 | **센서 없는 전류 기반 끼임 방지** |
| 5 | **요리 연기 · 냄새가 방 전체로 퍼진다** | **PM2.5 실측 + 요리 감지 → 후드 · 보상 급기 · 청정기 연동** |
| 6 | **겨울 창문 결로 → 곰팡이** | **이슬점 · 창 표면온도 계산 → 가습 상한 · 실링팬 역회전 · 제습** |
| 7 | **자고 일어나면 머리가 무겁다 (CO₂)** | **재실 기본 환기** — CO₂를 재지 않고 수면 소음 상한 안에서 1인 필요량을 상시 공급 |
| 7-1 | **비 오는 날 샤워 · 요리 후 눅눅함** | **샤워 감지 + 이슬점 비교 배기 + 흡기 균형 + 에어컨 · 제습기 강화** |
| 8 | 미세먼지 나쁜 날 환기 불가 | **필터 흡기팬 → 양압 환기** |
| 9 | 가전마다 자동 기능은 있지만 서로 충돌 | **규칙 + 모드 + 이벤트** 기반 통합 중재 |

### 왜 시뮬레이션인가

> **끼임 안전 실험은 실물로 반복할 수 없고, 결로 · 요리 · 수면 시나리오는 실시간으로 수백 번 돌릴 수 없다.**

Isaac Sim의 **Effort Sensor**(Prismatic 조인트의 힘)와 **Contact Sensor**로 끼임 실험을 안전하게 반복하며 **최대 접촉 반력을 정량 측정**한다.
가전 시나리오는 환경 모델로 **가속 실행**해 6시간짜리 수면 · 외출 상황도 몇 분 만에 재현한다.

## 2. 핵심 차별점

### ① 제약이 충돌하는 상황의 협조 제어 — 수단 사다리

**협조 제어는 "제약이 서로 충돌할 때"만 관찰된다.** 그래서 시나리오를 **제약 충돌 개수로 계층화**했다(40개).
v3.0은 이를 **수단 사다리**로 일반화했다 — 목표마다 수단을 비용 순으로 세우고, 제약이 칸을 지우면 다음 칸으로 오른다.

| 상황 | 가전 각자 동작 (Baseline A) | **본 프로젝트의 협조 제어** |
|---|---|---|
| **고온 + 고습 + 우천** (C1) | 창문을 열어 비가 들이치고, 에어컨은 열린 창을 상대로 냉방 | 창문 폐쇄 → **에어컨 제습이 인수** · 습한 외기를 들이는 급·배기 정지 |
| **고온 + 외기 미세먼지** (C8) | 창문을 열어 오염 외기 유입 | 배기 정지 → **필터 흡기로 양압 환기** · 등급별 단계 제한 |
| **요리 + 외기 미세먼지** (C9) | 후드를 강으로 켜고 창문까지 열어 오염 외기 대량 유입 | **후드 3안을 예측해 '약' 선택** + 필터 보상 급기 + 청정기 |
| **겨울 가습 ↔ 결로** (C10) | 가습기 자체 설정 60 % → **결로 발생** | 가습 상한을 외기온으로 53 %까지 낮추고, **실링팬 역회전으로 59 %까지 회복** |
| **장마철 제습** (C13) | 제습기 발열로 방이 더워져 에어컨이 뒤따라 냉방 | **여름엔 에어컨 제습** (겨울엔 제습기 — 계절이 수단을 바꾼다) |
| 수면 중 + 기본 환기 (C12) | 환기 안 함 → CO₂ 2,000 ppm 초과 | **수면 소음 상한(N0) 안에서** 흡기팬 16 m³/h 연속 운전 |
| **장마철 샤워** (C18) | 배기팬을 계속 돌려 습한 외기 유입 · 또는 아무것도 안 함 | **이슬점 차이가 있는 동안만 배기 + 흡기** → 에어컨 제습 강화 · 제습기 |

> 💡 **같은 "창문 폐쇄"인데 인수하는 수단이 다르다.** 우천(C1)은 외기가 **습해서** 무엇으로도 들일 수 없으니 에어컨이,
> 미세먼지(C8)는 외기가 **오염돼서** 걸러 들이면 되니 필터 흡기팬이 맡는다. **제약의 성질이 대체 수단을 결정한다.**
> 그리고 가전이 없는 원룸(P-core)에서는 같은 C1에서 **배기팬이 인수**한다 — 같은 제어기, 다른 답(X8).

### ② 만들지 않고 연결한다 — 알고리즘 · 인터페이스로 최소화

| 원칙 | 적용 |
|---|---|
| **센서:** 알고리즘으로 대체 가능하면 대체, **물리적으로 추정 불가능한 것만 추가** | 책상 조도 · 2번째 mmWave · 초음파 · 우적 센서를 알고리즘/API로 대체 (v2.1) → CO₂ · 실내 PM은 추정 불가하므로 **추가** (v3.0) |
| **액추에이터:** **새로 만들지 않는다** | 가전 6종은 보유 가전 + **IR 송신부 1개 공유 · 릴레이 1개 공유** |
| **모델은 버리지 않는다** | v2.1의 실내 PM 근사 모델을 **외기 유입 예측값**으로 재활용 → 실측과의 **잔차로 요리를 판별** |

| 구분 | Naive | **본 설계** | 절감 |
|---|---:|---:|---:|
| 센서 | 76,800원 | **61,100원 (7부품)** | −20 % |
| 액추에이터 · 구동 회로 | 234,900원 (상용 스마트 플러그 · IR 허브 포함) | **52,900원 (11종)** | −77 % |
| **합계** | **~311,700원** | **114,000원** | **−63 %** |

### ③ 센서 없는 창문 끼임 방지 · 피드백 없는 가전 상태 추정

자동차 파워윈도우의 **anti-pinch 기술**을 차용해 거리 센서 없이 **모터 전류만으로** 안전을 구현한다.

```text
전류 I(t) ─┬─ 고주파 성분 (리플 카운팅) → 위치·속도 추정   ← 엔코더 불필요
           └─ 저주파 성분 (부하 추정)   → 끼임 판정
```

같은 발상을 가전에 적용한다. **IR 리모컨은 단방향**이라 에어컨이 명령을 받았는지 알 수 없다.
→ **명령 후 온도 · 습도 · PM 변화로 가전 상태를 역확인**하고, 실패하면 재송신 2회 후 사다리에서 제외한다.

> ### ⚠️ 안전 개념을 정확히 명시한다
> | | 초음파 방식 (검토 후 폐기) | **전류 센서리스 (채택)** |
> |---|---|---|
> | 감지 시점 | 접촉 **전** | 접촉 **후** |
> | 안전 개념 | **예방** | **피해 최소화** |
> | 목표 지표 | 인터록 반응 200 ms | **최대 접촉 반력 ≤ 100 N** |
>
> 본 프로젝트는 *"장애물을 미리 감지해 멈춘다"* 고 주장하지 않는다.
> **"끼임 발생 시 즉시 정지·반전하여 접촉 반력을 100 N 이하로 제한한다"** 가 정확한 서술이다.

### ④ 센서 하나가 아니라 신호의 조합으로 판단한다 (v3.1)

| 판단 | 신호 조합 | 빠진 센서 |
|---|---|---|
| **재실 · 외출** | mmWave(호흡 미세동작) + **휴대폰 Wi-Fi** + **가전 전력** | PIR |
| **CO₂** | **재지도 계산하지도 않는다**(v3.4) — 재실 중 1인 기준 기본 환기를 상시 공급 · 참값은 검증용 | NDIR · 가상 CO₂ |
| **요리** | **쿡탑 전력** → 연기가 나기 전에 후드 선제 기동 · PM 잔차는 확인용 | – |
| **기기가 켜졌나** | 명령 + **기기 전력 상태(OFF/대기/송풍/가동)** + 환경 변화 | – |

> **"사람이 내는 주파수"로 재실을 판단할 수 있는가?** 소리는 *활동*의 증거일 뿐 *존재*의 증거가 아니다 — 조용히 있는 사람은 소리를 내지 않는다.
> 항상 나오는 사람의 주파수는 **호흡(0.2–0.33 Hz)** 이고, 그것은 마이크가 아니라 **mmWave가 보는 가슴의 미세동작**이다.
> 상세: [`docs/08_multisignal_energy.md`](docs/08_multisignal_energy.md) · 검증: [`feedback2_review.md`](docs/presentation/feedback2_review.md)

### ⑤ 최우선 목표를 위해 감수할 손실을 정한다 · 에너지는 미리 움직인다 (v3.1)

- **빨래 건조**처럼 빨리 끝내야 하는 일이 생기면, 이벤트가 *"건조 시간 최우선 · 실내 온도 +1 °C까지 감수"* 를 선언한다.
  평소 규칙(*여름엔 제습기를 쓰지 않는다*)을 풀고 **에어컨 + 제습기를 함께** 돌린다 — 안전 · 건강 · 결로는 절대 감수하지 않는다(C15).
- **귀가 시각의 분포를 예측**하고(분위수 회귀), **보정된 열모델**로 *"지금 켜면 에너지가 얼마고 귀가 때 얼마나 쾌적한가"* 를 계산해 **기대비용이 가장 낮은 시각**에 프리쿨링한다(C16).
- 외출이 짧으면 **설정온도를 올려 켜 두기(셋백)**, 길면 **끄기** — 손익분기 외출 시간 **T\*** 를 외기온별로 산출한다(EXP-1).
- 원룸 **전력 한도**를 넘기 전에 미뤄도 되는 기기부터 줄인다 — 요리 중 후드는 끄지 않는다(C17).

## 5. 제어 구조 — 규칙 + 모드 + 이벤트

```text
 사용자 ──► 모드    (의도)   "지금 공부한다"          → 목표값 · 상한 · 허용 장치
 센서   ──► 이벤트  (상황)   "요리가 시작됐다"        → 일시적 규칙 추가 · 상한 덮어쓰기
 설계자 ──► 규칙    (방법)   "우천이면 창문을 닫는다"  → 조건 → 행동 · 우선순위

            모드 ⊕ 이벤트 ⊕ 규칙  ──►  수단 사다리  ──►  6계층 중재  ──►  가전 보호  ──►  출력
```

모드 6 × 이벤트 9 = 54가지 특수 케이스를 코드로 쓰지 않고, **15개 정의의 조합**으로 동작이 나온다.
모든 명령에는 **사유 코드**(모드 / 이벤트 / 규칙 ID)가 붙어 로그로 남는다.

### 5.4 6계층 중재

```text
L0 로컬 하드 보호  >  L1 안전 인터록  >  L2 건강·재산 이벤트  >  L3 절전  >  L4 모드 제약  >  L5 쾌적  >  L6 조도
   (끼임·압축기)      (우천·외기·배제)    (요리·샤워·환기미달·결로) (무재실·외출)  (소음·금지장치)  (온·습도·기본환기)

병합:  force = 상위 계층 우선  ·  cap = 최솟값 (L2는 L4 cap 완화 가능)  ·  need = 최댓값
```

> 건강·재산(L2)을 절전(L3) 위에 둔 이유: 무재실이면 환기는 필요 없지만 **결로는 사람이 없어도 진행**된다.

### 8.1 재실 감지 — 문 열림 센서 + 호텔 로직 (v3.2)

> **재실 상태는 문이 열릴 때만 바뀐다.** 원룸의 출입구는 현관문 하나이므로, 문이 닫힌 직후에만 "안에 사람이 있나"를 확인하면 된다.

```text
문 열림 ─► (닫힘) ─► 판정 창 3분: mmWave · 사람이 켜는 기기 · 직접 조작 중 하나라도?
                       ├─ 예  → 재실 고정 — 다음 문 열림까지 (자도, Wi-Fi가 끊겨도 유지)
                       └─ 아니오 → 빈방 고정 — 다음 문 열림까지 (커튼 · 옆집 신호 무시)
휴대폰 Wi-Fi는 판정 증거로 쓰지 않는다 — 휴대폰을 두고 나간 경우를 걸러내기 위해
문 센서 고장 · 문을 10분 넘게 열어 둠 → 24시간 융합(mmWave + Wi-Fi + 전력, 15분)으로 폴백
영역 : LD2410 거리 게이트 2–3 = 책상 · 5–6 = 침대 → AUTO 모드 선택 (mmWave는 계속 켜 둔다)
```

| 상황 | v3.1 융합 | **v3.2 문 기반** |
|---|---|---|
| 휴대폰 절전으로 Wi-Fi 끊김 · 수면 | 30분 내 증거로 버팀 | **문이 안 열렸으므로 재실** |
| 휴대폰 두고 외출 | 15분 뒤 외출 | **문 닫힘 후 3분 → 외출** |
| 빈집 커튼 흔들림 | Wi-Fi · 전력 없음 → 기각 | **빈방 고정이라 무시** |
| 귀가 | Wi-Fi 접속 (수십 초) | **문 열림 즉시** |

**판정 창 증거 강도:** 방 안쪽의 움직임 · 기기 조작은 **강한 증거**, 벽에 붙은 구간의 신호는 **약한 증거**(옆집일 수 있음). 약한 증거만이면 판정 창을 최대 10분 늘리고, 그 사이 휴대폰이 끊기면 외출로 본다.

**mmWave 자동 보정:** 설치 때 *방 끝까지 한 번 걷기* → 감지 거리 상한 · *빈방 2시간마다* → 구간별 감도 기준선 학습(옆집 · 커튼 신호를 "평소 신호"로). **사용자는 숫자를 넣지 않는다.**

**mmWave를 끄지 않는 이유:** 재실 판정에는 판정 창 3분만 필요하지만, **책상/침대 위치(AUTO 모드) · 수면 판단 · 문 센서 고장 감지**에 계속 쓰인다.
소비전력이 약 0.4 W라 꺼서 얻는 이득도 거의 없다. 빈방 고정 중에는 읽는 주기만 낮춘다.

### 8.3 요리 감지 — 후드 아래 온도 + 미세먼지 (v3.3)

```text
요리 시작 = 후드 아래 온도가 실내보다 8 °C 이상 높고 분당 3 °C 이상 오름  OR  쿡탑 전력 가동(플러그형)
요리 끝   = 후드 아래 온도 하강 + 쿡탑 꺼짐 → 후드 5분 더
```

후드 아래 온도 센서(약 2,000원)는 **가스레인지 · 벽 직결 빌트인 · 인덕션 모두** 같은 방법으로 잡는다 — 시판 열 감지 후드와 같은 원리.
미세먼지 센서는 **유지**한다. 원룸에는 청정기가 없거나 센서 없는 저가형이 많아, 실내 공기 상태를 아는 수단이기 때문이다.

| 후드 아래 온도 | 미세먼지 | 판단 | 동작 |
|:---:|:---:|---|---|
| ↑ | ↑ | 요리 | 후드 + 보충 급기 + 청정기 |
| ↑ | – | 물 끓이기 · 수증기 | 후드 약 |
| – | ↑ | 초음파 가습기 물방울 · 외기 유입 · 원인 미상 | **후드 끔** · 청정기 · (외기면 창문 닫기 · 필터 흡기) |

**후드는 "열 + 연기"일 때만 켠다** — 열 없는 미세먼지(가습기 물방울 · 원인 미상)에 후드를 켜면 음압으로 오염된 바깥 공기를 끌어들인다.
외기가 나쁠 때는 **후드 {끔, 약, 강} 3안을 10분 앞까지 예측해 미세먼지 최고치가 가장 낮은 안**을 고른다.
**빈방인데 후드 아래가 뜨거우면 "불 켜고 외출" 경고** — 플러그형 인덕션은 전원 차단.

### 8.4 결로 대처 — 가습 상한은 외기온에 따라 움직인다

| 외기온 | 가습 상한 (기본) | 실링팬 역회전 시 |
|---:|---:|---:|
| 0 °C | 58 % | 64 % |
| −5 °C | **53 %** | **59 %** |
| −10 °C | 48 % | 54 % |

가습기 혼자서는 결로를 피하려면 53 %에서 멈춰야 한다. **실링팬이 창 표면을 데워 주면 59 %까지 올릴 수 있다.**
협조가 '양보'가 아니라 **'상한 확장'** 으로 나타나는 사례다(C10).

|---|---|---|
| 에어컨 | OFF · **송풍(써모오프)** · 가동 | 설정 도달 시 송풍 — **OFF로 오판하지 않는다** |
| 제습기 | OFF · 대기 · 가동 | **명령 ON + 대기 지속 + 습도 높음 → 물통 가득** |
| 쿡탑 · 세탁기 | 가열 / 탈수 종료 | 요리 시작 · 빨래 건조 시작 |

명령 후 **10 s** 안에 상태가 바뀌지 않으면 IR 실패(재송신), **명령 없이 바뀌면 수동 조작**. 측정은 CT 클램프 또는 **계량 스마트 플러그(권장 — 측정 + 제어 + 220 V 안전)**.

### 8.7 에너지 예측 · 셋백 vs 끄기 (v3.1)

| 무엇 | 어떻게 |
|---|---|
| **질문별 모델** | 전략 비교 = **회색상자 2R2C (데이터로 R · C 식별)** · 귀가 예측 = **분위수 회귀** · 소비 분석 = **변화점 회귀** — LSTM은 데이터량 · 반사실 예측 불가로 **검토 후 제외** |
| 프리쿨링 | **기대비용 최소화** — 귀가 분포 표본 × 열모델로 `에너지 + λ·불쾌 시간` 이 최소인 시작 시각 선택 (고정 20분위 규칙은 초기 폴백) |
| 순환 논증 방지 | 참값 환경은 **3R3C**, 제어기는 **2R2C를 데이터로 식별** — 식별 기간별 정확도 실험(EXP-4) |
| 셋백 vs 끄기 | 외출 5종 × 외기 3종 × 전략 3 = **45회 스윕** → 외기온별 손익분기 **T\*** 표 (원룸 벽걸이 인버터 대상 비교 연구가 없음 — 기여 지점) |
| 누진 방어 (선택) | 하계 300 / 450 kWh 구간 경계 예측 → 설정 +0.5 °C · 실링팬 우선 |

> ⚠️ 예측 모델은 **합성 데이터**로 평가하므로 실생활 정확도를 주장하지 않는다. 실측은 선택 과제(계량 플러그 1개 · 1–2주).

### 8.8 조도 — Isaac Sim에는 조도 센서가 없다

NVIDIA 공식 답변으로 확인된 사실이다. **해석적 계산 모델**을 메인으로 쓰고(결정론적 → 반복 재현), W12에 카메라 상대 휘도로 1회 대조한다.
Light Prim의 `intensity`는 lux가 아니라 렌더러 상대 단위이므로 **W05 캘리브레이션**으로 매핑한다.

## 13. 알려진 한계와 확장 아이디어

### 한계 — 발표에서 먼저 밝힌다

| # | 한계 | 서술 |
|---|---|---|
| 1 | **접촉 전 예방이 불가능** | 목표는 예방이 아닌 **피해 최소화(≤100 N)** |
| 2 | **저속에서 감지 성능 저하** | 토크를 낮출수록 반력은 작아지지만 SNR도 나빠진다. 스윕 곡선으로 제시 |
| 3 | **연질 물체가 가장 어렵다** | 반력 상승이 완만해 엔드존과 구분이 어렵다 |
| 4 | **리플은 합성값이다** | 239 Hz > 물리 스텝. 물리 검증(반력)과 모사(리플)를 구분해 명시 |
| 5 | **조도는 계산값이다** | W12 카메라 대조로 모델 오차를 정량 제시 |
| 6 | **mmWave 1개로 방 전 구석을 못 덮는다** | 침대 · 책상을 겨냥한 설치로 한정 |
| ~~7~~ | ~~필터 급기가 불가능하다~~ | ✅ **v3.0 해소** — 필터 흡기팬 · 양압 환기 |
| ~~8~~ | ~~실내 공기질을 측정하지 않는다~~ | ✅ **v3.0 해소** — PM2.5 실측 (CO₂는 v3.4부터 재실 기본 환기로 보장 · 참값 검증) |
| 9 | **가전 동특성은 정격 기반 1차 근사** | 인버터 등 내부 제어 미반영. 계수 민감도로 제시 |
| 10 | **난방은 범위 밖** | 겨울 시나리오는 실내 21 °C 유지를 가정 |
| 11 | **실내 공기는 균일 혼합 가정** | 요리 PM 공간 분포 · 센서 위치 효과는 1차 지연으로만 근사 |
| 12 | **IR 코드 · 릴레이 대상은 제품 의존** | 터치식 전원 가전은 릴레이 불가 (가정 A11) |
| 13 | **고속 모드는 물리를 검증하지 않는다** | 가전 시나리오는 환경 모델 수준의 검증이다. 조인트 · 끼임 지표는 물리 모드 8개에서만 |
| 14 | **실물 220 V 구간은 다루지 않는다** | 릴레이 직결 금지 → **v3.1: 계량 스마트 플러그로 해법 제시** |
| 15 | **Wi-Fi 재실은 휴대폰 1대 = 거주자 1명 가정** | 손님 · 휴대폰 2대는 다루지 않음 |
| 16 | **기본 환기는 1인 기준** | 사람 수를 세지 않는다 — 손님 2명 이상이면 부족할 수 있다 |
| 17 | **예측 모델은 합성 데이터로 평가** | 실생활 정확도 주장 안 함 |
| 18 | **T\* 표는 열용량 · COP 곡선에 의존** | 민감도 함께 제시 |
| ~~19~~ | ~~가스레인지는 전력으로 감지 불가~~ | ✅ v3.3 해소 — 후드 아래 온도 |
| 20 | **소리 신호는 시뮬레이션에서 검증 불가** | 확장 슬롯으로만 예약 |
| 21 | **문 기반 판정은 출입구가 문 하나라는 가정** | 창문 · 베란다 출입은 다루지 않음. 문을 열어 두면 폴백 |

### 범위 밖 (Out of Scope)

실물 하드웨어 제작 · RGB-D 카메라 인식 · 정밀 CFD · **모바일 앱 · DB** · 음성 명령 · TOU 요금 연동 · **난방 제어** · 제조사 클라우드 API · 다중 거주자 · 클라우드 연동

### 확장 아이디어

- **모바일 대시보드 · 이력 DB** — 모드 선택 UI · 상태 이력 조회 (현재는 `/studio/cmd/mode` 토픽 + CSV 로깅)
- 보일러 편입 — 난방까지 사다리에 포함
- 전기요금 시간대(TOU) 연동 — 에어컨 프리쿨링 시각 최적화
- 서카디안 조명 (시간대별 색온도 자동 변화)
- **설치 환경 프로파일**(남향/북향/반지하) 보정 — 파라미터 구조는 준비됨
- 실물 하드웨어(ESP32 + 랙-피니언 + IR + 스마트 플러그) 제작 및 시뮬레이션 결과 대조
- **ROS 2 ↔ MQTT 브리지** — 상용 IoT 생태계 접속
