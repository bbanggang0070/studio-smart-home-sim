## 0. 요약

국내 원룸(3.5 × 5 m)에 이미 있는 가전(에어컨 · 제습기 · 가습기 · 공기청정기 · 레인지후드 · 실링팬)과 저가 리트로핏 장치(창문 모터 · 블라인드 · 배기 · 흡기팬 · 스탠드)를 **센서 7종 + 비센서 신호 3종**으로 묶어, 제약이 서로 충돌할 때 수단을 바꿔 쓰는 **규칙 + 모드 + 이벤트 기반 협조 제어기**를 만들고 NVIDIA Isaac Sim + ROS 2 가상 원룸에서 검증했다.

| 질문 | 결과 |
|---|---|
| 협조 제어가 판정 기준을 더 잘 지키나 | 무작위 반복(참값 계수 · 외기 변동, 센서 잡음 포함) 제안 **95.8 %** [91.5, 97.9] vs A 10.0 % · B 78.9 % · 실측 기상(2024 서울 재분석) 제안 **93.9 %** [89.2, 96.7] |

| 외부 고충실도 에뮬레이터에서도 같은가 | BOPTEST BESTEST Air (에어컨만 있는 건물): 제안 열 불쾌 = A 와 같고 B 보다 8–9 % 적음 · 에너지 차이 2 % 이내 |

## 1. 서론

### 1.1 문제
1인 가구 원룸은 한 공간에서 요리 · 샤워 · 빨래 건조 · 수면 · 공부가 모두 일어난다. 그래서 목표가 자주 충돌한다 — 요리 연기를 빼려 후드를 켜면 음압으로 바깥 미세먼지가 들어오고, 빨래를 말리려 제습기를 켜면 여름엔 방이 더워지고, 겨울에 가습하면 창에 결로가 생긴다. 상용 스마트홈은 기기마다 따로 자동 운전을 하거나(본 연구의 기준선 A) 단순 규칙을 이어 붙여 이런 충돌을 다루지 못한다.

### 1.2 목표
- 이미 있는 가전을 **IR · 계량 플러그 · 릴레이**로 연결하고 센서는 물리적으로 대체할 수 없는 것만 더한다 (부품비 약 137,300원 · 가전 구매 0원)
- 목표마다 수단을 비용 순으로 세우고(**수단 사다리**), 제약이 칸을 막으면 다음 수단으로 넘어가는 협조 제어
- 창문은 **센서리스**(모터 전류 리플 + 반력)로 끼임 · 위치를 판단

### 1.3 기여
1. 제약 충돌을 계층으로 나눈 시나리오 41개(단일 · 2중 · 3중)와 같은 판정 문법으로 돌리는 **2모드 하네스**(물리 Isaac Sim / 고속 환경 모델) — 제어기 코드는 두 모드에서 같다
2. 규칙 10개 · 이벤트 15종 · 사용자 모드 6종 · 6계층 중재로 표현한 협조 제어기 (docs/07)
3. **평가 절차의 신뢰성 장치** — 판정 · 지표 동결(해시) · 사후 개정 전후 병기 · 무작위 반복 신뢰구간 · 실측 기상 · 사전 등록 보류 평가 7차 · 외부 에뮬레이터(BOPTEST) · 물리 ↔ 고속 모드 대조 (§5)
4. 평가 과정에서 드러난 결함 유형 정리 — 특히 **센서 특성 · 가전 보호(L0)를 하네스에 넣자 드러난 제어기 결함** (§7.1)

## 3. 시스템 설계

### 3.1 구성
| 구분 | 내용 |
|---|---|
| 센서 7종 | 온습도 · 밝기 · mmWave 레이더 · 문 열림 · 창문 모터 전류 · PM2.5 · 후드 아래 온도 (PIR · CO₂ 센서 없음) |
| 비센서 신호 | 휴대폰 Wi-Fi · 가전 전력(계량 플러그) · 날씨 공공데이터 API |
| 액추에이터 11종 | 설치 5 (창문 · 블라인드 · 배기팬 · 흡기팬 · 스탠드) + 보유 가전 6 (에어컨 · 제습기 · 가습기 · 실링팬(조명 일체) · 공기청정기 · 레인지후드) + 플러그형 인덕션 차단 |
| 인터페이스 | ROS 2 토픽 55개 (계약 · docs/02 §6) + 내부 5 |

CO₂ 는 제어에 쓰지 않는다 — 재실 중 모드별 기본 환기(일반 25 · 공부 40 · 수면 16 m³/h)를 늘 공급하고, CO₂ 는 시뮬레이션 참값으로만 검증한다.

### 3.2 제어 구조 — 규칙 + 모드 + 이벤트 (docs/07)
- **사용자 모드 6종** (NORMAL · STUDY · NIGHT · SLEEP · AWAY · AUTO) — 목표 온습도 · 조도 · 소음 등급 · 기본 환기량
- **이벤트 15종** (요리 · 결로 · 샤워 · 환기 부족 · 비 · 외기 오염 · 귀가 · 외출 · 가전 이상 · 빨래 건조 · 전력 한도 · 수동 조작 · 프리쿨링 …)
- **상호작용 규칙 10개** (I1 제습 ⟂ 가습 · I2 냉방 중 창문 제한 · I3 배기 시 급기 확보 · I4 가습 상한 = f(결로 여유) · … · I8 전력 한도 차단 순서 · I10 환기 제습은 바깥이 더 건조할 때만)
- **6계층 중재** — L0 가전 보호 · L1 안전 · L2 이벤트 · L3 외출 · 에너지 · L4(.5) 수동 · 우선 목표 · L5 쾌적 사다리 · L6 조명
- **수단 사다리** — 냉방: 차광 → 창문 → 실링팬 → 배기 + 흡기 → 에어컨 · 제습: 창문 → 배기 → 계절 수단(여름 에어컨 · 겨울 제습기)

### 3.3 센서리스 창문 (docs/04)
2계층 — 브릿지 로컬 컷오프(전류 1.80 A, 정지만) + 상위 안전 계층(0.25 A · 속도 저하 → 반전 · SAFETY_HOLD · 방향 잠금). 위치는 정류 리플을 세어 추정한다.

- 열 불쾌는 테스트 케이스 쾌적 범위(재실 21–24 °C) 기준 — 우리 목표(26 °C)와 달라 모든 방식이 BOPTEST 기본보다 크다
- 순위: 쾌적 A ≈ 제안 > B · 에너지 세 방식 2 % 이내. 습도 · 환기 · 차광 수단이 없는 건물이라 협조 제어의 장점은 드러나지 않는다 — **같은 조건에서 에어컨 판단만 비교한 결과**
- 이 비교로 찾은 결함: 창문 없는 건물에서 무료 냉방을 가정 · 겨울(외기 ≤ 10 °C) 과열 냉방 공백 · 연결 코드의 시간 처리 (§7.1)

### 6.7 센서리스 창문 · 끼임 (analysis_report §4 · ⏳ 최종 물리 재실행)
끼임 감지 165/165 · 정상 닫힘 오검출 0/20 · 최대 접촉력 52.9 N (스윕, 토크 25–75 %) · 85.4 N (시나리오 C2) · 리플 위치 오차 최대 2.52 mm · 정지 8.3 ms (물리 1 스텝). 안전 계층이 없는 A 는 같은 상황에서 105–124 N.

## 7. 논의

### 7.1 평가 장치가 찾아낸 결함
평가 신뢰성 장치를 하나 더할 때마다 개발 시나리오에서는 보이지 않던 결함이 드러났다.

| 장치 | 드러난 결함 (예) |
|---|---|
| 보류 평가 | 규칙 공백(전력 한도 마지막 단계 · 급기 조건) · 겨울 요리 후드 냉기 · 청정기 IR 재송신 없음 · 수동 외출 해제 판단 |
| BOPTEST | 창문 · 배기가 없는 건물에서 무료 냉방을 가정해 재실 중 에어컨을 끔 · 겨울 과열 냉방 공백 |
| 물리 ↔ 고속 모드 대조 | 고속 모드에 **센서 특성 · L0 보호가 없었다** · 제어기에 주는 전력 범위 · 판정용 전체 전력 정의가 두 모드에서 달랐다 · 물리 모드 시각이 자정에 되감김 |
| 센서 특성 추가 | 잡음 섞인 한 샘플로 판정하는 곳 7곳 (샤워 오감지 · 가습 진입 · 빨래 건조 냉방 ↔ 제습 · 조명 불감대 · 스탠드 목표 · 프리쿨링 · 냉방 ↔ 제습) |
| L0 보호 추가 | 무응답 판정(E9)이 보호 중인 정상 에어컨을 1분 안에 고장으로 확정 · 늦은 실행을 수동 조작으로 오판 · 켠 뒤 줄이는 전력 한도 |

**교훈:** 고속 모드 결과(논문의 주 근거)는 처음에 '센서가 완벽하고 가전이 즉시 반응한다'는 가정 위에 있었다. 물리 모드와 같은 시스템 구성을 고속 모드에 넣은 뒤에야 실제 설치에서 문제가 될 결함이 보였다.

### 7.2 한계
1. **실측 없음** — 참값 모델 · 가전 계수 · 센서 특성은 문헌 · 가정값. 실제 원룸 몇 % 절감 · 정확도를 주장하지 않는다
2. **에너지 절감 미달** (§6.4)
3. **시나리오 작성자 = 제어기 개발자** — 보류 묶음도 같은 사람이 썼다
4. **판정 기준의 사후 개정** — 개정 전 기준으로는 결과가 다르다 (docs/12 §2–4 병기)
5. **끼임 안전은 시뮬레이션** — FMVSS 118 · IEC 60335-2-103 적합을 주장하지 않는다 · 반전 거리 미적용 · 탄성 물체 주행 구간 미검증
6. **고속 창문은 1차 지연 근사** — 0 에 닿지 않는다 (5차 H501)
7. **장비 한계** — 후드 배기량(300–450 m³/h) ≫ 흡기팬(60 m³/h) — 창문을 못 쓸 때 양압은 규칙으로 해결 불가
8. **BOPTEST 비교는 에어컨 판단만** — 습도 · 환기 · 차광은 비교되지 않았다
9. README §13 의 설계 한계 (조도 계산값 · mmWave 1개 · 난방 범위 밖 등)

## 8. 결론 · 향후

협조 제어기는 제약이 충돌하는 원룸 상황에서 판정 기준을 기기별 독립 운전(A)보다 크게 잘 지켰고(무작위 95.8 % vs 10.0 %), 처음 보는 조합에서도 89 % 를 지켰다. 외부 에뮬레이터에서는 에어컨 판단만으로도 A 와 같은 쾌적을 냈다. 반면 에너지는 줄이지 못했고(A 대비 +21–26 %), 결과는 모두 시뮬레이션이다.

**향후 (논문 단계):** EXP-5 — 같은 원룸 시뮬레이터에서 질문별 모델(현재) · LSTM(+ 기대비용 최적화) · 심층 강화학습을 같은 데이터 · 같은 튜닝 예산으로 비교 (docs/10). 실제 원룸 1–2주 측정으로 3R3C 보정 (docs/11 선택 11).
