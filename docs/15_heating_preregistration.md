# 15. 난방 확장 트랙 사전 등록 — v1.30-H 평가 (docs/14)

> 작성 2026-10-28 · **초안 — 개발 실행 결과를 보기 전에 가설 · 주 비교 · 판정 규칙을 적었다** · 브랜치 `heating`
> 이 문서의 §1–§5 는 등록 커밋 뒤 바꾸지 않는다. 바꾸면 §8 에 이유와 함께 적고 결과에 함께 보고한다.
> 본 결과(v1.29 · docs/12) 와 섞지 않는다 — 보고서에는 '확장: 난방 편입' 절로 따로 둔다.

## 1. 질문 · 가설 (방향)

| # | 질문 | 가설 |
|---|---|---|
| H-RQ1 | 겨울 목표 충돌에서 환경 결과 통과율이 기준선보다 높은가 | 제안-H > A′-H > A-H (충돌이 많을수록 차이가 크다) |
| H-RQ2 | 같은 쾌적에서 비용(가스 + 전기, 원)이 낮은가 | 제안-H 의 난방 기대비용(비용 + 추위 환산)이 A-H 보다 낮다 · A′-H 와는 비슷하거나 낮다 |
| H-RQ3 | 바닥난방처럼 느린 열원에서 외출 셋백이 이득인가 | 셋백 16 °C 가 22 °C 켜 둠(A-H)보다 싸고, 귀가 1시간 쾌적을 지킨다 |
| H-RQ4 | 난방을 넣어도 v1.29 결과가 그대로인가 | 개발 시나리오 249회 · 보류 1–7차가 지표 · 판정 · 상태 모두 같다 |

## 2. 비교 대상 (명세는 결과 보기 전 · `config/baselines.yaml` 2026-10-28)
- **A-H** — 조절기 22 °C 켜 둠 (외출 · 수면에도 그대로) + 기존 A
- **A′-H** — 스마트 조절기: 재실 21 · 15분 비면 16 · 23–07시 19 °C + 기존 A′ (협조 없음)
- **B-H** — 제안-H 에서 히스테리시스 · 대기만 뺀 것
- **제안-H** — v1.30-H (난방 사다리 · I11–I14 · E16 · E17)

## 3. 시나리오
- 개발: `config/scenarios_heating.yaml` H1–H14 + B9H · C6H · C10H · C19H (18개 · 계층 1–3) — 판정 동결 후 해시 등록
- 보류 평가: 난방 트랙 1차 · 2차 (각 12개 · 실행 전 커밋 · 2차를 마지막으로) — 작성 규칙은 v1.29 보류와 같다
- 실측 기상: 기상청 ASOS 겨울(12–2월) — 학습 2021–2023 · **평가 2024** · 시나리오마다 5일
- 무작위 반복: 참값 계수(바닥 열용량 · 배관 · 보일러 효율 · 침기 · U값) × 5

## 4. 주 지표 · 판정 규칙
**주 지표 1** — 환경 결과 기준 통과율 (판정 3분류 · `tools/analysis/criteria_classes.py` 규칙) · 같은 조건 짝
**주 지표 2** — 난방 기대비용 `expected_cost_heating` = 비용(원) + 160 원/K·h × 재실 중 추위 K·h · 짝 비(제안 / 기준) 중앙값

**주 비교 (4개)**: 무작위 반복에서 제안-H vs A-H · 제안-H vs A′-H × (주 지표 1 · 2)
- 구간: 시나리오 묶음 부트스트랩 95 % · 검정: McNemar(통과율) · 부호 검정(비용) + Holm (4개)
- 판정: 구간이 0(차) 또는 1(비)을 넘지 않고 보정 p < 0.05 → '낫다' / 반대 → '못하다' / 그 외 → '차이를 확인하지 못함'

**부 지표** (판정 없음): 전체 기준 통과율 · 가스 kWh · 전기 kWh · 추위 K·h · 결로 노출 · 최저 실내 · 점화 횟수 · 보류 평가 · 실측 기상 · BOPTEST 아파트 케이스

## 5. 하지 않을 것
- 보류 평가 결과를 보고 제어기를 고친 뒤 같은 묶음으로 다시 재지 않는다
- 판정 동결 뒤 판정을 바꾸면 전후 결과를 함께 보고한다
- 결과가 나빠도 기준선 명세(§2)를 바꾸지 않는다

## 6. 동결 · 실행 순서
1. 개발 실행 → 결함 수정 (판정 · 시나리오 수정은 §8 에 기록)
2. **판정 · 시나리오 · 제어기 동결** — `config/freeze_heating.yaml` (해시) · 이 문서 §7 에 커밋
3. 무작위 반복 · 실측 기상 · 여름 회귀(H-RQ4)
4. 보류 1차 등록 → 실행 → (결함 수정 · 재동결) → 보류 2차(마지막) 등록 → 실행
5. 분석 · 보고

- 가설 H-RQ1 (제안 > A′ > A): A 대비는 맞음 · A′ 대비는 확인하지 못함 · H-RQ2 (A 보다 싸고 A′ 와 비슷하거나 쌈): **아니다** — A 와 차이 없음 · **A′ 보다 비싸다**
- **사후 해석 (결과를 본 뒤 · 판정에 쓰지 않음)**: A′-H 는 기본 환기를 거의 하지 않는다 — 기본 환기 충족 3.5 % · 참값 CO₂ 기준 충족 47 % (제안 94.9 % · 98.3 %). 겨울에는 재실 기본 환기(25 m³/h)와 가습(증발 냉각)이 난방 부하의 큰 몫이라, 같은 쾌적 온도에서 A′ 가 가스를 덜 쓴다 (B9H 2 h: A′ 보일러 연소 0 · 제안 1.6 kWh). 냉방(v1.29)에서는 환기 비용이 작아 드러나지 않았던 트레이드오프 — 기대비용에 공기 질을 넣지 않은 등록 지표의 한계이기도 하다
