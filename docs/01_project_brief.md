## 한 줄 소개

**원룸에 이미 있는 가전과 저가 리트로핏 장치를 연결해, 제약이 충돌하는 상황에서 11종의 수단이 역할을 재분배하는 협조 제어를 Isaac Sim + ROS 2 가상 원룸에서 검증하는 AIoT 시뮬레이션 프로젝트**

## 1. 배경 — 왜 원룸인가

기존 스마트홈은 **넓은 집 · 고가 허브 · 다수 장치**를 전제로 설계되어 있다.
그러나 국내 1인 가구는 2024년 기준 전체 가구의 약 1/3을 차지하며, 이들 다수는 **17~20 m² 원룸**에 거주한다.
원룸은 공간이 작아 장치 수를 늘릴 수 없고, 예산 제약으로 고가 허브를 도입하기 어렵다.

→ **"장치를 늘리지 않고, 있는 장치들이 서로 역할을 나누게 하는 것"** 이 원룸에 맞는 해법이다.
→ v3.0에서 이 명제를 **"가전을 새로 만들지 않고, 이미 있는 가전을 연결해 역할을 나누게 하는 것"** 으로 확장했다.
원룸 거주자는 이미 에어컨 · 제습기 · 공기청정기를 갖고 있지만, **가전들이 서로를 모른 채 각자 동작**한다.

## 2. 문제 정의 — 원룸 거주자의 불편

| # | 불편 | 현재 상황 |
|---|---|---|
| 1 | 외출 후 조명 방치 | 불필요한 전력 소모 |
| 2 | 여름철 답답함·과열 | 환기를 사람이 직접 판단·실행 |
| 3 | 강한 햇빛·눈부심 | 블라인드 수동 조절 |
| 4 | 창문 개폐 시 끼임 | 저가 제품에는 안전 기능이 없음 |
| 5 | 저가형 장치의 한계 | 장치별 제어가 분절되어 협조 불가 |
| **6** | **요리 연기 · 냄새** (v3.0) | 후드를 늦게 켜고, 외기가 나빠도 창문을 연다 |
| **7** | **겨울 결로 · 곰팡이** (v3.0) | 가습기는 창에 물이 맺히는 줄 모른다 |
| **8** | **수면 · 공부 중 CO₂** (v3.0) | 닫힌 원룸에서 1인 기준 시간당 약 430 ppm 상승 |

## 3. 제안 시스템

**구성 (v3.0):** 센서 7종 + 액추에이터 11종 (설치 5 + **보유 가전 연결 6**)

| 센서 7종 | 부품 | 액추에이터 11종 | 인터페이스 |
|---|---|---|---|
| 온습도 | DHT22 | 창문 (위치 + 토크 프로파일) | 모터 드라이버 · **센서리스** |
| 밝기 | BH1750 | 블라인드 (슬랫 각도) | 서보 |
| **문 열림** (v3.2) | **리드 스위치** — PIR 자리 · 호텔 객실 로직 | 배기팬 (속도) | PWM |
| 사람 위치 | mmWave | **실링팬 — 조명 일체형** (천장 조명 + 대류) | 조명 PWM · 팬 릴레이 |
| 전류 | ACS712 (창문 · **센서 대신**) | 책상 스탠드 (디밍 + 색온도) | PWM |
| **CO₂** | **v3.4 폐지** — 재실 기본 환기로 보장 | **에어컨** | IR |
| **미세먼지** | **PMS7003 (PM2.5)** | **제습기** | 릴레이 |
| **후드 아래 온도** (v3.3) | **DS18B20** — 요리 감지 · 불 켜고 외출 | **가습기** | 릴레이 |
| | | **흡기팬 + 필터** | PWM |
| | | **공기청정기** | IR (에어컨과 공유) |
| | | **레인지후드** | 릴레이 |

```text
사용자 모드 (의도) ┐
센서 → 이벤트 (상황) ├─► 규칙 → 수단 사다리 → 6계층 중재 → 가전 보호 → 리트로핏 · 가전 구동
설계 규칙 (방법)   ┘                                                   → 실내 상태 갱신 → (반복)
```

**제어 우선순위 (6계층):** `L0 로컬 보호` > `L1 안전 인터록` > `L2 건강·재산 이벤트` > `L3 절전` > `L4 모드` > `L5 쾌적` > `L6 조도`

**사용자 모드 6종:** 일반 · 공부 · 야간 · 수면 · 외출 · 자동 — 상세 [`07_modes_rules_events.md`](07_modes_rules_events.md)

## 4. 핵심 차별점 — 3축

> v1.0에서는 "협조 제어" 단일 축이었다. W01 발표 피드백을 반영해 **3축으로 확장**했다.

### ① 제약이 충돌하는 상황의 협조 제어

**협조 제어는 "제약이 서로 충돌할 때"만 관찰된다.** 온도만 높으면 창문을 열면 그만이다.
그래서 시나리오를 **제약 충돌 개수로 계층화**하여 17개로 재설계했고, v3.0에서 32개, **v3.1에서 38개**, **v3.4에서 40개**로 확장했다.

| 상황 | 단일 제어 (Baseline A) | **본 프로젝트의 협조 제어** |
|---|---|---|
| **고온 + 고습 + 우천** (C1) | 온도 규칙만 보고 **창문을 열어 비가 들이침** | 창문 폐쇄 유지 → **에어컨 제습이 인수** (v3.0) · 가전 없는 원룸(P-core)에서는 **배기팬이 인수** |
| 고온 + 강한 일사 (C3) | 창문부터 열어 일사열 유입 증가 | **블라인드로 열원을 먼저 차단**한 뒤 창문·팬 |
| 저조도 + 고온 (C4) | 천장 조명 100 % → 발열로 온도 악화 | 천장 밝기 **상한 제한** + 스탠드로 국부 보충 + 팬 보상 |
| 수면 중 + 고온 (C5) | 재실 위치를 몰라 팬 고속 → 수면 방해 | **침대 영역 인지** → 창문 우선, 팬은 저속 상한 |
| 무재실 + 우천 (C7) | 절전 상태라 아무 명령도 안 냄 | **안전이 절전보다 우선** → 창문 폐쇄 실행 |
| **고온 + 미세먼지 나쁨 (C8)** | 창문을 열어 **오염 외기 유입** | 등급별 **단계적** 제한 · 배기 정지 → **필터 흡기로 양압 환기** (v3.0) |
| **요리 + 외기 미세먼지 (C9)** 🆕 | 후드 강 + 창문 개방 → 오염 외기 대량 유입 | **후드 3안 예측 → 약** · 필터 보상 급기 · 청정기 |
| **겨울 가습 ↔ 결로 (C10)** 🆕 | 가습기 자체 60 % → 결로 | 가습 상한 53 %로 하향 → **실링팬 역회전으로 59 % 회복** |
| **장마철 제습 (C13)** 🆕 | 제습기 발열 → 에어컨이 뒤따라 냉방 | **여름엔 에어컨 제습** / 겨울엔 제습기 — 계절이 수단을 바꾼다 |

> 💡 **C1과 C8은 같은 "창문 폐쇄" 상황인데 인수하는 수단이 다르다.**
> 우천은 외기가 **습해서** 걸러 들일 수 없으니 에어컨이, 미세먼지는 외기가 **오염돼서** 걸러 들이면 되니 필터 흡기팬이 맡는다.
> 두 경우 모두 **배기팬은 멈춘다** — 음압이 틈새로 습기 · 오염을 끌어들이기 때문이다.
> **제약의 성질에 따라 대체 수단이 달라진다.** (v2.1 · 가전 없는 원룸에서는 C1 = 배기팬 인수, C8 = 수단 소진)

**즉, 제약 조건이 냉각 전략 자체를 바꾼다.** 이것이 단일 장치 제어로는 불가능한 지점이다.
→ 상세: [`03_scenarios.md`](03_scenarios.md)

### ② 알고리즘을 통한 센서 최소화 → v3.0: 만들지 않고 연결한다

> **v3.0 원칙:** 알고리즘으로 대체 가능한 센서는 계속 대체하고, **물리적으로 추정 불가능한 CO₂ · 실내 PM만 추가**했다.
> 가전은 **새로 만들지 않고** IR 송신부 1개 · 릴레이 1개를 공유해 연결한다. 전체 **114,000원 (naive ~311,700원 대비 −63 %)**.
> 상세: [`06_appliance_integration.md` §1.2 · §6](06_appliance_integration.md). 아래는 v2.1 최소화 내역이다.

시나리오를 17개로 확장하면 순진하게는 센서를 7개까지 늘려야 한다. **알고리즘으로 3개를 대체했다.**

| 제거한 센서 | 대체 알고리즘 | 절감 |
|---|---|---:|
| 책상 조도 센서 | `E_desk = f(천장조도, 스탠드 명령값, 기하)` — 스탠드 출력은 이미 아는 값 | 2,000원 |
| mmWave 2번째 | **거리 게이트 매핑** — LD2410의 0.75 m 게이트 8개로 책상/침대 구분 | 11,900원 |
| 초음파 HC-SR04 | **전류 리플 anti-pinch** (차별점 ③) | 2,000원 |
| 우적 센서 | 기상청 단기예보 API | 5,000원 |

**액추에이터도 같은 방식으로 줄였다.**

| 제거·축소한 것 | 대체 설계 | 절감 |
|---|---|---:|
| 700 mm 리니어 액추에이터 | **회전 모터 + 랙-피니언** (본체 길이 ≥ 행정 제약 해소) | 46,000원 |
| 엔코더 · 리밋스위치 전량 | **리플 카운팅 + 하드스톱 재동기화** | 9,000원 |
| 블라인드 승강 모터 | **슬랫 각도만 제어** — 목적이 차광이므로 충분 | 9,800원 |
| 팬 2개(흡기+배기) | **1개** — 창문 개방률과 협조하여 급배기 경로 구성 | 2,200원 |
| RGB 풀컬러 컨트롤러 | **CCT 듀얼화이트** — 조명 모드는 색온도만 사용 | 12,000원 |

> **팬 축소가 특히 의미 있다.** 협조 제어가 목적이었는데 **결과적으로 부품이 줄었다.**
> *"장치를 늘리지 않고 있는 장치들이 역할을 나누게 한다"* 는 명제가 하드웨어 구성에서도 성립한다.

| | Naive 구성 | **최소화 구성** | 절감 |
|---|---:|---:|---:|
| 센서 | 39,800원 (7개) | **24,100원 (4개)** | −39 % |
| 액추에이터 | 116,900원 | **33,400원** | −71 % |
| **합계** | **156,700원** | **57,500원** | **−63 %** |

**재실 감지 융합 전략 (v2.1 기록 — 현행 v3.2는 문 열림 센서 + 판정 창 3분, [`08` §1.0](08_multisignal_energy.md))** — 업계 검증 패턴 *"PIR-validates, mmWave-holds"*:

```text
입실 : PIR 트리거      → 즉시 재실 판정 (응답 빠름)
유지 : mmWave 감지     → 자거나 앉아 있어도 재실 유지
퇴실 : 양쪽 모두 클리어 → 비재실
오검출(커튼·옆방) : PIR 미검출로 교차 기각
```

부수 효과로 **무재실 타임아웃을 300초 → 60초로 단축**했다.
v1.0의 300초는 *"PIR이 정지 인체를 놓치므로"* 필요했던 보정값이었는데, mmWave가 그 문제를 해결했기 때문이다.

### ③ 센서 없는 창문 끼임 방지 — 전류 리플 방식

창문 안전을 **거리 센서 없이 모터 전류만으로** 구현한다. 자동차 파워윈도우의 anti-pinch 기술을 차용했다.

```text
전류 I(t) ─┬─ 고주파 성분(리플 카운팅) → 위치·속도 추정   (엔코더 없음)
           └─ 저주파 성분(부하 추정)   → 끼임 판정
```

| 핵심 요소 | 내용 |
|---|---|
| **Zone A–D 토크 프로파일** | 기동 100 % → 주행 55 %로 점감 → 엔드존 70 % 보상 → 밀착 구간 감지 비활성 |
| **엔드존 램프 검출·보상** | 씰 압착(완만한 램프)과 끼임(급격한 계단)을 상승 형태·지속 거리로 구분 |
| **적응형 임계값** | 온도·마모로 정상 전류가 드리프트해도 오검출하지 않도록 최근 5회 주행으로 학습 |
| **구동 기구** | **랙-피니언** — 창틀 하부에 랙, 패널에 모터. 창문 개조 최소 (특허 KR20090056308A) |

> ### ⚠️ 안전 개념이 달라졌음을 명시한다
>
> | | v1.0 초음파 (폐기) | **v2.0 센서리스 (채택)** |
> |---|---|---|
> | 감지 시점 | 접촉 **전** | 접촉 **후** |
> | 안전 개념 | **예방** | **피해 최소화** |
> | 목표 지표 | 인터록 반응 200 ms | **최대 접촉 반력 ≤ 100 N** |
>
> 발표와 문서 전반에서 *"장애물을 미리 감지해 멈춘다"* 는 표현은 사용하지 않는다.
> 대신 **"끼임 발생 시 즉시 정지·반전하여 접촉 반력을 100 N 이하로 제한한다"** 로 통일한다.

**그럼에도 센서리스를 채택한 이유:** ① 이동하는 패널에 센서·배선이 불필요 ② **센서 사각이 없다** — 어느 지점에서 걸려도 감지 ③ **양방향 대응** ④ 자동차에서 검증된 성숙 기술
→ 상세: [`04_sensorless_window_control.md`](04_sensorless_window_control.md)

## 5. 왜 시뮬레이션인가 — 존재 이유

> v2.0에서 이 논거가 결정적으로 강해졌다.

| v1.0 논거 | **v2.0 논거** |
|---|---|
| 하드웨어 제작 전 로직 검증 | **끼임 안전 실험은 실물로 반복할 수 없다** |

사람 손이나 물체가 창문에 끼이는 상황은 실물로 수백 번 반복할 수 없다.
Isaac Sim의 **Effort Sensor**(Prismatic 조인트의 힘을 측정)와 **Contact Sensor**를 사용하면
이 실험을 **안전하게 반복하고 최대 접촉 반력을 정량 측정**할 수 있다.

**즉 이것은 시뮬레이션만이 할 수 있는 실험이다.**
