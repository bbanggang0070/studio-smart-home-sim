# 센서리스 창문 제어 설계서 (Sensorless Window Control)

> **신규 산출물** · 작성일 2026-09-12 · v1.0
> **작성 배경:** W01 프로젝트 발표 피드백 ③ *"최신 기술을 접목하여 센서 없이 액추에이터로만 제어하는 방식"* 반영
> **확정 사항:** HC-SR04 초음파 거리 센서를 **제거**하고, **전류 리플(Ripple) 기반 센서리스 anti-pinch** 로 전면 전환

## 1. 개요

### 1.1 무엇이 바뀌었나

| 구분 | 기존 (v1.0) | **변경 (v2.0)** |
|---|---|---|
| 장애물 감지 | HC-SR04 초음파 Raycast | **모터 전류 리플 분석** |
| 센서 부품 | 초음파 센서 1개 (패널 선단 부착) | **없음** — 전류 검출 회로만 (**ACS712**, 1,000~3,700원) |
| 배선 | 움직이는 패널까지 플라잉 리드 필요 | **고정부에만 배선** (이동부 배선 0) |
| 위치 피드백 | 조인트 엔코더 가정 | **리플 카운팅으로 위치 추정** |
| 감지 시점 | 접촉 **전** (비접촉, 예방) | 접촉 **후** (반력 감지, 피해 최소화) |
| 감지 방향 | 진행 방향 전방만 | **양방향 모두** (개방·폐쇄 공통) |
| 구동 기구 | 창문 상부 레일 + 캐리지 | **랙-피니언** (창틀 하부 랙 + 패널 모터) |

### 1.2 ⚠️ 안전 등급이 달라졌음을 명시한다

> **이 전환으로 안전 기능의 성격이 바뀌었다. 문서 전반에서 이를 정직하게 서술한다.**

| | 초음파 방식 (폐기) | **전류 센서리스 (채택)** |
|---|---|---|
| 안전 개념 | **예방** — 닿기 전에 멈춤 | **피해 최소화** — 닿은 뒤 즉시 멈춤 |
| 목표 지표 | 인터록 반응 200 ms | **최대 접촉 반력 ≤ 100 N** |
| 물리적 의미 | "0.3 m 앞에 물체가 있다" | "이미 눌렀고 반력이 감지됐다" |

**따라서 기존의 "장애물 감지 → 창문 정지, 접촉 없음" 이라는 서술은 더 이상 사용하지 않는다.**
대신 **"끼임 발생 → 즉시 정지·반전, 접촉 반력을 100 N 이하로 제한"** 으로 통일한다.

### 1.3 그럼에도 센서리스를 채택한 이유

| # | 근거 |
|---|---|
| 1 | **부품·배선 제거** — 이동하는 패널에 센서와 케이블을 붙이지 않아도 된다. 저가형·레트로핏 정체성에 부합 |
| 2 | **센서 사각이 없다** — 초음파는 전방 원뿔빔만 보지만, 전류는 **어느 방향·어느 지점에서 걸려도** 감지된다 |
| 3 | **양방향 대응** — 열 때와 닫을 때 모두 동일 알고리즘으로 커버 |
| 4 | **자동차에서 검증된 성숙 기술** — 파워윈도우 anti-pinch로 수십 년간 양산 적용 |
| 5 | **시뮬레이션에서만 가능한 실험** — 끼임 실험은 실물로 반복할 수 없다. 이것이 본 프로젝트가 시뮬레이션인 이유를 강화한다 |

## 2. 구동 기구 — 랙-피니언 방식 (확정)

### 2.0 먼저 — "레일"과 "랙"은 다르다

> **미닫이 창은 이미 레일 위에서 움직인다.** 그것이 미닫이의 정의다.
> 우리가 추가하는 것은 **레일이 아니라 톱니 스트립(랙)** 이며, 창틀 하부 홈에 붙이는 **얇은 부재**다.
> 창문을 새 레일에 얹는 공사가 아니다.

```text
[기존 미닫이 창]                    [v2.0 구성]
  창틀 ─────────────                  창틀 ──━━━━━━━━━━──   ← 랙(톱니 스트립) 추가
   └ 레일 (원래 있음)                   └ 레일 (그대로)
  패널 ── 호차(바퀴)                   패널 ── 호차 + 모터·피니언 유닛
```

### 2.1 구동 방식 4종 비교

발표 피드백 *"창문 틀 아래쪽에 설치하는 방법은 없는지"* 와
후속 질문 *"액추에이터만으로 개폐 자동화하는 방법은 없는지"* 에 대한 답이다.

| 방식 | 추가 부재 | 슬립 | **리플 위치 추정** | **끼임 감지** | 채택 |
|---|---|---|---|---|---|
| A. 상부 레일 + 캐리지 | **레일 전체** | 없음 | ✅ | ✅ | ✗ 개조 과다 |
| **B. 랙-피니언** | **랙(톱니 스트립)** | **없음** | ✅ **정확** | ✅ **반력 직결** | ✅ **채택** |
| C. 벨트/와이어 견인 | 아이들 풀리 + 브래킷 | 없음(치형) | ✅ 가능 | ⚠️ 탄성으로 지연 | △ 차선 |
| D. **마찰 구동** | **없음** | **있음** | ❌ **무효** | ❌ **실패** | ✗ 센서리스와 양립 불가 |

### 2.2 ⚠️ D(마찰 구동)를 쓸 수 없는 이유 — 중요

**"액추에이터만으로" 라는 요구에 가장 잘 맞는 방식은 마찰 구동이다.** 실리콘 휠을 창틀 면에 눌러
마찰로 패널을 미는 방식으로, **레일도 랙도 전혀 필요 없고 접착 설치만으로 끝난다.**
상용 제품도 존재한다 — MOES ZigBee Sliding Window Pusher(마찰 구동, **최대 추력 50 N**, 약 $180).

**그러나 본 프로젝트의 센서리스 설계와는 근본적으로 충돌한다.**

| 문제 | 결과 |
|---|---|
| 휠이 미끄러지면 **모터는 도는데 창문은 안 움직인다** | 리플 카운트가 이동량과 무관해진다 → **위치 추정 전면 무효** |
| 장애물에 걸리면 **휠이 그냥 미끄러진다** | **모터 전류가 올라가지 않는다** → **끼임 감지 실패** |

> **역설:** 마찰 구동의 슬립은 **기계적 안전장치**로는 훌륭하다. 과부하가 슬립으로 방출되므로
> 구조적으로 끼임 힘이 제한된다(MOES가 50 N인 이유). 상용 제품이 별도 장애물 감지 기능을
> 명시하지 않는 것도 이 때문으로 보인다.
>
> 하지만 **그 안전이 "전류로 감지한다"는 우리 차별점 ③을 무력화한다.**
> 감지할 신호 자체가 생기지 않기 때문이다. 따라서 마찰 구동은 채택하지 않는다.

### 2.3 왜 B(랙-피니언)인가

**선행 기술:** 한국 특허 **KR20090056308A**(창문 자동 개폐장치) —
*"바퀴는 외주면에 다수의 돌기가 형성된 피니언 부재로 구성되고, 피니언이 이동하는 창틀 구간에 랙 부재가 설치된다."*

| 근거 | 내용 |
|---|---|
| **슬립이 없다 (치합 구동)** | 모터 회전 = 패널 이동이 1:1로 보장 → **리플 카운팅이 성립하는 전제** |
| **반력이 직접 전달된다** | 장애물에 걸리면 곧바로 모터 토크 상승 → **전류로 검출 가능** |
| **정지·기동 정밀도가 높다** | 산업계 평가에서도 랙-피니언은 *"정밀하게 정지·기동하여 안전 센서에 더 잘 반응한다"* 고 기술된다 |
| **창문 개조가 최소** | 창틀 하부에 톱니 스트립만. 좌우 방향 전환(re-handing) 불필요 |
| 비용 | 리니어 액추에이터(약 60,000원) 대비 기어드 모터+랙 약 14,000원 |

**차선책 C(벨트 견인):** 랙조차 붙일 수 없는 상황이라면 치형 벨트가 대안이다.
슬립이 없어 리플 카운팅은 가능하지만, **벨트 탄성이 충돌 반력 전달을 지연**시켜 감지가 늦어진다.
벨트는 시간이 지나며 늘어나 강성이 변하므로 재장력 조정도 필요하다. W12 민감도 실험의 확장 항목으로 남긴다.

### 2.4 모터 종류 — 왜 브러시 DC인가 (스텝모터 대안 검토)

> 선행연구 정리 문서에서 **스텝모터(NEMA17) + 리드스크류**가 대안으로 제시되었다.
> 검토 결과 **채택하지 않았으며**, 그 근거를 명시한다. 발표 Q&A 대비 항목이다.

| | **브러시 DC (채택)** | 스텝모터 + 리드스크류 |
|---|---|---|
| 가격 | 기어드 모터 약 8,000원 + 드라이버 2,500원 | 1.2~2.5만원 (전용 드라이버 포함) |
| **위치 추정** | **정류자 리플 카운팅** — 추가 부품 0 | 스텝 카운팅 (오픈루프) |
| **끼임 감지** | **전류 크기 + 속도 저하** | 탈조 감지 (StallGuard류 back-EMF) |
| 정지 유지 | 기어 백드라이브 저항 | **홀딩 토크** (브레이크 불필요) |
| 위험 요소 | 리플 미스카운트 누적 | **탈조 시 위치 완전 상실** |

#### 결정적 근거 — 스텝모터에는 정류자 리플이 없다

**스텝모터는 브러시가 없으므로 정류자 리플이 발생하지 않는다.**
전류에 리플이 보이기는 하지만 그것은 **드라이버의 PWM 쵸핑 주파수**이며, **회전 위치 정보를 담지 않는다.**

따라서 스텝모터를 쓰면 본 프로젝트의 핵심 메커니즘 —
*"하나의 전류 신호에서 위치(고주파)와 부하(저주파)를 동시에 뽑아낸다"* — 가 성립하지 않는다.
위치는 스텝 카운팅으로, 끼임은 StallGuard로 **각각 다른 방법**을 써야 한다.

> **정리:** 스텝모터로도 같은 목표를 달성할 수 있으나 **방법이 둘로 갈린다.**
> 브러시 DC의 정류자 리플은 **추가 부품 없이 두 정보를 하나의 신호로 준다.**
> 이것이 "저가형 최소 구성"이라는 프로젝트 정체성에 더 부합하므로 브러시 DC를 채택한다.
>
> 다만 스텝모터 방식은 **탈조 시 위치를 완전히 잃는** 반면 리플 방식은 **점진적으로 드리프트**하므로,
> 하드 스톱 재동기화로 복원 가능하다는 점도 유리하다.

### 2.5 기구 제원 (가정값)

| 항목 | 기호 | 값 | 비고 |
|---|---|---:|---|
| 피니언 유효 반경 | `r_p` | 10.0 mm | 랙 피치원 기준 |
| 감속비 | `G` | 30 : 1 | 소형 기어드 DC 모터 |
| 정류자 리플 수 / 회전 | `N_c` | 10 | 5극 × 2 |
| 모터 토크 상수 | `K_t` | 0.012 N·m/A | 저가 브러시 DC 모터급 |
| 기계 효율 | `η` | 0.65 | 기어 + 랙피니언 손실 |
| 창문 유효 이동 거리 | `L` | 700 mm | 폭 1.5 m 미닫이 기준 |

### 2.6 리플 1개당 이동 해상도

```text
리플 1개 = 모터 1/N_c 회전
모터 1회전 = 피니언 1/G 회전 = 2π·r_p/G  이동

Δx = 2π · r_p / (G · N_c)
   = 2π × 10.0 mm / (30 × 10)
   = 0.209 mm  /  리플
```

전체 행정 700 mm ÷ 0.209 mm = **약 3,350 리플** → 위치 분해능은 충분하다.

### 2.7 직선-회전 변환

```text
패널 위치   x [m]        ↔  피니언 각도 θ_p = x / r_p
모터 각도   θ_m = G · θ_p
개방률     ratio = x / L  (0.0 ~ 1.0)
모터 토크   τ_m = F_joint · r_p / (η · G)
모터 전류   I   = τ_m / K_t + I_0
```

## 3. 센서리스 알고리즘

### 3.1 전체 구조

```text
        ┌──────────────────────────────────────────────┐
        │            모터 전류 I(t) 측정                 │
        └───────────────┬──────────────────────────────┘
                        │
        ┌───────────────┴───────────────┐
        │                               │
   ┌────▼─────────┐            ┌────────▼──────────┐
   │ 리플 카운팅   │            │  부하 추정         │
   │ (고주파 성분) │            │  (저주파 성분)      │
   └────┬─────────┘            └────────┬──────────┘
        │                               │
   위치 x̂ · 속도 ω̂              평균 전류 Ī · 상승률 dI/dt
        │                               │
        └───────────┬───────────────────┘
                    │
        ┌───────────▼────────────────────┐
        │  구간 판정 (Zone A/B/C/D)        │
        │  + 적응형 임계값                 │
        └───────────┬────────────────────┘
                    │
        ┌───────────▼────────────────────┐
        │  끼임 판정 → 정지 · 반전         │
        └────────────────────────────────┘
```

### 3.2 리플 카운팅 — 위치·속도 추정

브러시 DC 모터는 정류자가 전환될 때마다 전류에 주기적 맥동(리플)이 생긴다.
**리플 주파수 = 회전 속도**, **리플 누적 개수 = 회전량**이므로 홀 소자나 엔코더 없이 위치를 얻는다.

```text
I(t) = Ī(t) · [ 1 + A_r · sin(N_c · θ_m(t)) ] + n(t)

ω̂ = 2π · f_ripple / N_c          (리플 주파수 → 각속도)
x̂ = Δx · Σ(리플 카운트) · dir     (리플 누적 → 위치)
```

#### 누적 오차와 재동기화

리플 카운팅은 **누적 오차가 불가피**하다. 노이즈로 펄스를 놓치거나(미스카운트) 중복 계수하면 위치 추정이 드리프트한다.

> **대응: 하드 스톱 재동기화.** 완전 개방·완전 폐쇄 위치에 도달하면(전류 급증 + 속도 0) 카운터를 0 또는 `L` 로 리셋한다.
> 이는 실제 파워윈도우가 배터리 탈거 후 수행하는 **"초기화 학습"** 과 동일한 절차다.

### 3.3 위치 구간별 토크 프로파일 (Zone A–D)

> 피드백에서 요청한 *"처음엔 토크를 크게, 서서히 작게"* 를 **구간 기반 프로파일**로 구체화한다.
> 고정 임계값을 쓰면 기동 구간에서 오검출이, 엔드존에서 미검출이 발생한다.

| Zone | 구간 (행정 진행률) | 토크 지령 | 끼임 감지 | 이유 |
|---|---|---:|---|---|
| **A · 기동** | 0 – 5 % (또는 첫 150 ms) | **100 %** | **비활성 (블랭킹)** | 정지마찰 극복을 위해 전류가 정상적으로 급증. 이 구간에서 감지하면 100 % 오검출 |
| **B · 주행** | 5 – 85 % | **100 % → 55 % 선형 감소** | **활성 · 적응형 임계값** | 관성이 붙으면 필요 토크가 줄어든다. 토크를 낮출수록 끼임 시 반력도 작아진다 |
| **C · 엔드존** | 85 – 97 % | **55 % → 70 % 재상승** | **활성 · 임계값 상향 보상** | 씰·가이드 접근으로 마찰이 증가한다. 보상하지 않으면 미검출 |
| **D · 밀착** | 97 – 100 % (폐쇄 방향만) | **100 %** | **비활성** | 씰 압착으로 전류가 정상적으로 급증. 자동차 법규도 이 구간을 제외한다 |

```text
토크
100% ┤███                              ┌───────
     │   ╲                          ╱  │  D
 70% ┤     ╲                    ╱      │
     │  A    ╲────────────╲  C         │
 55% ┤            B        ╲──╯        │
     └──┬────┬──────────────┬───┬──────┴──→ 행정 진행률
        0   5%            85%  97%   100%
     [블랭킹]  [감지 활성]   [보상]  [비활성]
```

> ⚠️ **Zone D는 폐쇄 방향에만 적용한다.** 개방 방향의 종단에는 씰이 없으므로 Zone C 조건을 그대로 유지하고,
> 이동 한계는 조인트 리밋이 처리한다.

### 3.4 엔드존 램프 검출·보상

Zone C 진입 판정을 **위치 추정값에만 의존하면 위험하다** — 리플 카운팅이 드리프트하면 엔드존을 잘못 잡는다.
따라서 **위치 + 전류 기울기** 두 조건을 함께 본다.

```text
엔드존 진입 판정 =
    ( x̂ ≥ 0.85·L )                          # 위치 조건
AND ( dĪ/dx  가 완만한 양의 램프를 형성 )        # 램프 조건 (급격한 계단 ≠ 엔드존)
AND ( 지속 구간 ≥ 20 mm )                      # 끼임의 급격한 상승과 구분
```

**끼임과 엔드존의 구분 근거:**

| 특징 | 끼임 | 엔드존 씰 압착 |
|---|---|---|
| 전류 상승 형태 | **급격한 계단** | **완만한 램프** |
| 상승 지속 거리 | 수 mm 이내 | 20 mm 이상 |
| 발생 위치 | 임의 | **행정 종단 부근으로 한정** |
| 속도 저하 | 급격 | 점진적 |

### 3.5 끼임 판정식

```text
pinch_detected =
      ( Ī - Î_expected(x̂, dir) > ΔI_th(x̂) )        # 부하 초과
  AND ( ω̂ < ω_ref · (1 - k_ω) )                     # 속도 저하
  AND ( 조건 지속 ≥ t_debounce )                      # 노이즈 제거
  AND ( zone ∈ {B, C} )                             # 감지 활성 구간
```

| 기호 | 의미 | 초기값 |
|---|---|---:|
| `Î_expected(x, dir)` | 위치·방향별 정상 전류 기준 프로파일 | 캘리브레이션으로 획득 |
| `ΔI_th(x)` | 위치별 초과 허용량 | Zone B 0.25 A / Zone C 0.45 A |
| `k_ω` | 속도 저하 허용 비율 | 0.35 (35 % 이상 감속 시) |
| `t_debounce` | 판정 지속 시간 | 30 ms |

### 3.6 적응형 임계값

온도 변화, 레일 오염, 씰 경화, 기구 마모로 정상 전류가 서서히 변한다.
고정 임계값은 시간이 지나면 오검출 또는 미검출을 낳는다.

```text
정상 완주한 최근 N회(N=5)의 전류 프로파일을 위치 bin(20 mm)별로 누적하여
    Î_expected(x) ← (1-α)·Î_expected(x) + α·I_measured(x)      (α = 0.2)
로 갱신한다. 끼임이 검출된 주행은 학습에서 제외한다.
```

### 3.7 안전 로직의 2계층 분리 ⭐

> **선행 설계 원칙:** *"안전 로직(끼임 방지)은 통신 왕복 없이 액추에이터 컨트롤러 자체에서 즉시 처리한다 —
> 허브 통신 지연이 안전 반응에 영향을 주지 않도록."*

#### 왜 필요한가

제어기 노드가 모든 판단을 하면 **ROS 2 토픽 왕복이 안전 반응 경로에 들어간다.**
W06에서 측정하는 명령→반응 지연(목표 100 ms 이하)이 그대로 **안전 지연에 더해진다.**

```text
[단일 계층 — 문제 있음]
  전류 상승 → 토픽 발행 → 제어기 판단 → 명령 토픽 → 브릿지 → 모터 정지
             └──────── 네트워크 왕복이 안전 경로에 포함 ────────┘
```

#### 채택 구조

```text
┌─ 로컬 계층 ── isaac_actuator_bridge (물리 콜백 내부, 통신 없음) ─────────┐
│   전류 > local_cutoff_current_a (1.80 A)  또는  반력 > 120 N            │
│        → 즉시 모터 정지 (PWM 0)                                         │
│   반응 시간 = 물리 스텝 1회                                              │
└────────────────────────┬───────────────────────────────────────────────┘
                         │ /studio/internal/window_local 발행 (보고만 — 판단하지 않음)
                         ▼
┌─ 상위 계층 ── window_safety_node (ROS 2 · 50 Hz) ─────────────────────┐
│   1. 정밀 판정 (4조건 AND · 적응형 임계값 · Zone 확인)                    │
│      로컬이 먼저 끊었으면 그 사건도 끼임으로 받는다                        │
│   2. 50 mm 반전 시퀀스        ─┐  /studio/internal/window_override      │
│   3. SAFETY_HOLD 진입 / 해제   ├→ (브릿지가 제어기 지령보다 먼저 적용)    │
│   5. 동일 위치 2회 반복 → 방향 잠금 ─┘                                   │
│   → state/safety_state · state/pinch_detected (계약 토픽)               │
└────────────────────────┬───────────────────────────────────────────────┘
                         ▼
┌─ smart_home_controller ───────────────────────────────────────────────┐
│   4. 역할 재분배 (safety_state ≠ NORMAL → 창문 불가 → 팬으로 이전)        │
│      사용자 알림 W_PINCH · W_LOCK (state/alerts — 명령 거부 사유)         │
└────────────────────────────────────────────────────────────────────────┘
```

| 계층 | 임계값 | 역할 | 반응 경로 |
|---|---:|---|---|
| **로컬** | 1.80 A / 120 N (**보수적**) | **정지만** | 물리 스텝 (통신 0) |
| **상위** | 0.25 A 초과 + 속도 저하 (**정밀**) | 판정·반전·정책 | ROS 2 토픽 |

> **로컬 임계값이 상위보다 높은 이유:** 로컬은 **최후의 방어선**이다.
> 정밀 판정은 상위가 하고, 로컬은 *"어떤 판단 로직도 놓쳤을 때"* 만 작동하도록 여유를 둔다.
> 로컬이 너무 민감하면 정상 주행(Zone A 기동 피크)에서 오작동한다.

**얻는 것**
- 안전 반응이 **네트워크 상태와 무관**해진다
- W06의 통신 지연 측정과 안전 지표가 **분리**되어 지표가 깨끗해진다
- 발표 논거: *"통신 지연이 안전에 영향을 주지 않는 2계층 구조"*

#### 끼임 후 동작 시퀀스

```text
[로컬]  1. 즉시 모터 정지 (PWM 0)
        2. pinch_detected = true 발행
[상위]  3. 정밀 판정 (오검출이면 해제 후 재개)
        4. 반대 방향으로 50 mm 반전 → 물체 해방
        5. SAFETY_HOLD 상태 진입
        6. 역할 재분배 — 창문 불가 → 팬으로 냉각 이전
        7. 동일 위치 2회 연속 끼임 → 해당 방향 구동 잠금, 사용자 개입 요구
```

> ⚠️ **상위 계층이 500 ms 내에 응답하지 않으면 로컬은 정지 상태를 유지한다**(`upstream_timeout_ms`).
> 제어기가 죽어도 창문이 계속 밀지 않는다.

> **W10 구현 메모 (v1.4 · 2026-10-12)**
> - 상위 계층은 제어기와 분리된 노드 `scripts/nodes/window_safety_node.py` (코어 `controller/window_safety.py`, 순수 Python). 제어기가 죽어도 상위 안전은 돈다.
> - 로컬 차단 뒤 상위가 반전을 내기 전까지(무응답 포함) 로컬은 **같은 방향 재지령을 거부**하고 정지를 유지한다 — 시간 제한 없이 유지하므로 `upstream_timeout_ms` 를 넘겨도 정지.
> - 반전이 `pinch_detection.reverse_timeout_s`(3 s) 안에 끝나지 않으면(막힘 · 지령 유실) 그 자리에서 `SAFETY_HOLD` — `PINCH_REVERSE` 에 갇히지 않는다.
> - `SAFETY_HOLD` = `layered_safety.safety_hold_s` (30 s, draft). 그동안 제어기 창문 지령은 브릿지가 무시하고, 제어기는 `safety_state` 를 보고 창문을 사다리에서 뺀다.
> - **방향 잠금 해제** = 사용자 활동 `WINDOW_UNLOCK` (`cmd/activity`). 잠금 중에도 반대 방향은 허용.
> - 반복 계수: 같은 방향 · ±`reverse_distance_m` 안의 끼임 기록. **같은 방향 정상 주행이 그 위치를 무사히 지나가면 기록을 지운다** (물체를 치움 — 다른 날 · 다른 물체를 반복으로 세지 않음).
> - 계측(브릿지 물리 콜백 120 Hz): 접촉 시작(`contact_onset_n` 5 N) → 감지(로컬 차단 또는 상위 반전 수신) → 정지(`stopped_speed_mps`) 지연을 `window_local` 의 `detect_ms` · `stop_ms` 로 낸다 (C2 '감지 후 200 ms 이내 정지').
> - Baseline A 는 안전 계층이 없다 (`--no-local-cutoff` · 상위 노드 미기동) — C2 대비군.
> - **반력 측정 방식 (2026-10-12 결정):** 강체 시험 물체(`rigid_pot`)에도 시험봉 강성 65 N/mm(draft) 컴플라이언스를 준다 (`scene_layout.yaml obstacles`). 강체끼리 충돌하면 접촉력이 1 물리 스텝 스파이크(패널 9 kg 관성)로 나와 지표 #5 가 측정 방식에 좌우되기 때문 — 여는 방향 30 kg 화분: 116 N → 70.7 N (정지 8.3 ms).
> - 끼임 반력 최댓값에서 **씰 구간(Zone D) 접촉은 뺀다** — 접촉 센서는 패널에 닿는 힘을 모두 합하므로, 닫힘 끝의 씰 압착(≈ 140 N)이 섞인다. 정지 = 감지 당시 진행 방향 속도가 `stopped_speed_mps` 아래 (곧바로 반전하면 0 근처를 샘플 사이에서 건너뛴다).

## 4. Isaac Sim 구현 방식

### 4.1 핵심 문제 — Isaac Sim에는 "모터 전류"가 없다

Isaac Sim이 제공하는 것은 **조인트 반력**이다. 따라서 **반력 → 전류**로 환산하는 모델을 우리가 만든다.

| 필요한 것 | Isaac Sim 제공 | 변환 |
|---|---|---|
| 모터 전류 `I` | Effort Sensor의 조인트 힘 `F` | `I = F·r_p/(η·G·K_t) + I_0` |
| 전류 리플 | 없음 | **해석적 합성** (§4.3) |
| 접촉 반력 검증 | Contact Sensor | 직접 사용 |

### 4.2 Effort Sensor 사용

Isaac Sim의 Effort Sensor는 **회전 조인트에서는 토크를, 직선(Prismatic) 조인트에서는 힘의 크기**를 측정한다.
창문은 Prismatic 조인트이므로 그대로 적용된다.

```python
from isaacsim.sensors.physics import EffortSensor   # Isaac Sim 5.1 실측 경로 (experimental 아님)

# prim_path = <Articulation 루트>/<조인트 이름> — 루트 경로로 Articulation을 만들고 이름으로 DOF를 찾는다
window_effort = EffortSensor(prim_path="/World/window/window_prismatic_joint")

def read_motor_current() -> float:
    """조인트 반력 → 등가 모터 전류로 환산"""
    F = abs(window_effort.get_sensor_reading().value)      # [N]
    tau_m = F * R_PINION / (ETA * GEAR_RATIO)              # [N·m]
    return tau_m / K_T + I_NO_LOAD                          # [A]
```

> ✅ **2026-10-09 실증** (`tools/isaac/check_effort_sensor.py`, Isaac Sim 5.1): Prismatic 조인트를 벽에 밀면 자유 이동 0 N → **300 N(드라이브 최대 힘)** 로 상승. `EffortSensor` 와 `get_measured_joint_efforts()` 값이 일치한다.

보조 API로 `get_measured_joint_forces()` / `get_measured_joint_efforts()` 도 사용 가능하며,
실제 접촉력 검증에는 **Contact Sensor**를 병행한다.

### 4.3 ⚠️ 리플 재현의 한계와 대응 (중요)

**물리 스텝이 리플 주파수보다 느리면 리플을 물리 엔진으로 재현할 수 없다.**

실제 리플 주파수를 계산해 보면:

```text
창문 속도 0.05 m/s 기준
  피니언 각속도 ω_p = 0.05 / 0.010 = 5.0 rad/s
  모터 각속도  ω_m = 5.0 × 30 = 150 rad/s ≈ 23.9 rev/s
  리플 주파수  f_r = 23.9 × 10 = 239 Hz
```

Isaac Sim 물리 스텝을 240 Hz로 올려도 **나이퀴스트 한계에 정확히 걸린다.** 재현 불가다.

#### 채택 방안: 리플을 해석적으로 합성한다

실제 모터의 리플도 **회전각의 함수**이므로, 조인트 각도를 알고 있는 시뮬레이션에서 이를 합성하는 것은 물리적으로 타당하다.

```python
def synthesize_current(F_joint, x_panel, dt, t):
    """반력 + 위치 → 리플이 실린 전류 파형 합성 (고주파 오버샘플링)"""
    I_mean = joint_force_to_current(F_joint)
    theta_m = (x_panel / R_PINION) * GEAR_RATIO            # 모터 각도 [rad]
    samples = []
    for k in range(OVERSAMPLE):                            # 물리 1스텝을 N등분
        th = theta_m + k * (d_theta / OVERSAMPLE)
        ripple = 1.0 + RIPPLE_AMP * math.sin(N_COMMUTATOR * th)
        noise  = random.gauss(0.0, CURRENT_NOISE_SIGMA)
        samples.append(I_mean * ripple + noise)
    return samples                                          # → 리플 카운터에 입력
```

#### 정직성 확보 — 무엇이 진짜 검증이고 무엇이 모사인가

> 이 구분을 문서와 발표에서 **명확히 밝힌다.** 시뮬레이션 결과의 신뢰 범위를 정하는 문제다.

| 구성 요소 | 검증 성격 | 근거 |
|---|---|---|
| **끼임 감지 (부하 판정)** | ✅ **진짜 물리 기반 검증** | PhysX가 계산한 실제 접촉 반력에서 유도 |
| **최대 접촉 반력** | ✅ **진짜 물리 기반 검증** | Contact Sensor 실측 |
| **토크 프로파일 효과** | ✅ **진짜 물리 기반 검증** | 토크 지령이 실제 조인트 구동력으로 반영 |
| **리플 위치 추정** | ⚠️ **모사(emulation)** | 조인트 위치가 ground truth로 존재하므로, 여기에 **양자화·미스카운트·드리프트를 주입**하여 실제 센서리스 추정의 불확실성을 재현 |

**리플 추정 오차 주입 모델**

```text
x̂ = quantize(x_true, Δx=0.209mm)
    + cumulative_drift(miscount_rate = 0.3 %)
    + gauss_noise(σ = 0.15 mm)
하드 스톱 도달 시 x̂ ← 재동기화
```

### 4.4 Scene 구조

```text
    └── effort_sensor       (Effort)      ← 반력 → 전류 환산 입력
```

> 기존 설계의 `exclude_prims: ['window_frame']`(Raycast 씬 쿼리 제외)은 **더 이상 필요 없다.**
> Raycast를 쓰지 않으므로 자기 히트 문제 자체가 사라졌다.

## 6-1. 시뮬레이션의 물리적 근거 — Zone A–D 반력이 어디서 오나 (2026-10-11 · W05 T5.8)

| Zone | 실제 창문 | Scene (`tools/isaac/build_scene.py`) | 기준 프로파일 (폐쇄 · 5회 왕복 평균) |
|---|---|---|---:|
| A 기동 | 정지 마찰 + 모터 기동 돌입 | 스프링 패드의 정지 마찰 0.8 > 운동 0.5 (돌입 전류는 W10 전류 합성에서 더한다) | 5.9 N |
| B 주행 | 레일 모헤어 · 롤러 예압 | 패널 앞쪽 끝 패드를 Z 스프링 조인트(2,000 N/m · 예압 5 mm)로 레일에 누름 | 4.7 N (평탄) |
| C 엔드존 | 씰 · 가이드 접근으로 마찰 증가 | 닫힘 쪽 마지막 15 % 레일이 6 mm 오르는 경사로 → 스프링이 더 눌려 마찰 선형 증가 | 6.0 → 10.8 N |
| D 밀착 | 씰 압착 | 문설주 씰(compliant) — 닫힘 목표 −6 mm 로 눌러 닫는다 | 71 N |

> PhysX 의 compliant 접촉은 법선력이 겹침에 비례하지 않아(브러시 · 가이드를 접촉 강성으로 만든 첫 시도가 0.02 N) 스프링 조인트 + 경사로로 결정적으로 만들었다.
> 결과 표: `models/window_reference_profile.csv` (20 mm 구간 · 방향별 · 전류 환산 `I = I0 + |F|·r/(G·Kt·η)` 포함) — W10 `Î_expected(x)` 초기값.

## 7. 검증 계획

| 검증 항목 | 방법 | 목표 | 주차 |
|---|---|---|---|
| 전류 환산 모델 타당성 | 무부하 주행 시 전류가 `I_0` 부근인지 확인 | 오차 ≤ 10 % | W10 |
| 리플 위치 추정 정확도 | 추정 위치 vs 조인트 ground truth | 1회 왕복 누적 오차 ≤ 5 mm | W10 |
| Zone 전환 정확도 | 위치별 Zone 라벨이 설계대로 바뀌는지 | 100 % | W10 |
| 끼임 감지 성공률 | C2 · X4 시나리오 × 3회 | **100 %** | W11–W12 |
| 최대 접촉 반력 | Contact Sensor 실측 최댓값 | **≤ 100 N** | W11–W12 |
| 오검출률 | Zone B·C 정상 주행 100회 | **0 %** | W12 |
| 엔드존 미검출 방지 | 엔드존 직전 끼임 주입 | 100 % 검출 | W12 |
| 물체 강성별 민감도 | 강체 / 연질 / 탄성 3종 | 전부 검출 | W12 |

> **연질 물체가 가장 어려운 조건이다.** 부드러운 물체는 반력이 서서히 올라가 엔드존 램프와 구분이 어렵다.
> 이 경우 §3.4의 **"발생 위치" 조건**(엔드존은 행정 종단으로 한정)이 결정적 판별자가 된다.

## 8. 알려진 한계 (발표 Q&A 대비)

| # | 한계 | 대응 / 답변 |
|---|---|---|
| 1 | **접촉 후에야 감지된다** | 예방이 아닌 피해 최소화가 목표임을 명시. 반력 100 N 이하로 제한하는 것이 규격상 기준 |
| 2 | **저속에서 감지가 어려워진다** | 토크를 낮출수록 반력은 작아지지만 신호 대 잡음비도 나빠진다. Zone B 종료 토크 55 %는 이 트레이드오프의 절충값이며, W12에서 스윕하여 확정한다 |
| 3 | **리플 카운팅 드리프트** | 하드 스톱 재동기화로 매 왕복마다 오차를 0으로 복원.<br>**백업 플랜:** W10에서 위치 오차가 목표(5 mm)를 넘으면 **홀센서(A3144)+자석 2개(약 3,000원)** 를 완전개방/폐쇄 지점에 추가한다. 부품이 늘지만 기준점이 확실해진다 (`hall_reference_enabled`) |
| 4 | **랙-피니언 백래시가 전류에 노이즈를 준다** | 백래시 구간을 Zone A 블랭킹에 포함. 조인트 파라미터로 백래시를 모델링해 민감도 분석 |
| 5 | **온도·마모에 따른 드리프트** | 적응형 임계값(§3.6)으로 보상 |
| 6 | **시뮬레이션의 리플은 합성값이다** | §4.3에서 무엇이 물리 검증이고 무엇이 모사인지 명시적으로 구분함 |
