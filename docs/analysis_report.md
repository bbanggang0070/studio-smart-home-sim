## 3. 협조 제어가 무엇을 바꿨나 (Tier 2)

- **C1 고온다습 + 비** (`c1_compare.png`): A 는 온도 규칙대로 창문 40 % 를 열어 젖은 외기가 들어와 **습도 100 %** · 459 Wh.
  제안은 창문을 닫고 에어컨을 제습 · 냉방으로 번갈아 써 **73 %** · 416 Wh — 같은 '덥다'에 수단을 창문에서 에어컨 제습으로 옮겼다.
- **C9 요리 + 외기 매우나쁨** (`decision_trace_C9.md`): 요리 감지 1:11 → 후드 약 + 흡기 보상(I3, 외기 나쁨이라 창문 대신 필터 흡기) → 청정기 3단 →
  13:03 에어컨(I5 +1 °C) → 16:39 후드 예측 세 안이 같아져 정지 → 28:39 PM 목표 미달 지속으로 **DEGRADED** 보고. 결정마다 중재 사유가 남는다.
- **목표 달성 스코어카드 (C1–C8 · `tier2_scorecard.md` · `w13_scorecard.png`):** 시나리오마다 정한 판정 기준을 A 62 % · B 100 % · 제안 100 % 지켰다
  (시나리오 판정 A 25 % · B 96 % · 제안 100 % · Tier 2 전체 20개는 A 55 % · B 95 % · 제안 100 %). A 자신과 비교하는 기준은 A 에게 해당 없음으로 뺐다
- **쾌적-에너지 2축 (`w13_tradeoff.png` · 목표 이탈 적분 — 재실 중):** A → 제안으로 C8 온도 초과 2.7 → 0.1 °C·h · PM 35 초과 0.9 → 0 µg/m³·h,
  C1 습도 이탈 37 → 20 %RH·h, C6 4.2 → 1.0 %RH·h, C5 온도 0.7 → 0.2 °C·h. 에너지가 늘어난 곳(C5 · C8)은 A 가 목표를 크게 벗어난 곳이다.
  **반대 방향 하나:** C1 온도 초과 0.3 → 0.4 °C·h — 제안은 제습을 우선해 27.7–28.5 °C 를 유지하고, A 는 창문 + 냉방으로 26.5 °C 까지 내리지만 습도 100 % (트레이드오프)
- **불필요 구동:** 히스테리시스 · 자동 전환 대기를 뺀 B 는 시나리오당 평균 402회 전환 — 제안 46회 (A 7회는 장치가 거의 움직이지 않아서).

**그 밖의 한계 (지표 미달 · 모델):**
- **#7 에너지 미달 (−6.8 %, 목표 −20 %):** 전체 비교(+36 %)는 A 가 목표를 못 지키면서 덜 쓰기 때문이라(C15 빨래 1.86 vs 4.03 kWh — A 는 6 h 안에 못 말림 · C8 · C5 환기)
  **같은 목표 달성 기준**으로 재정의했다(docs/03 v2.34 — 두 제어기 모두 판정 통과 · 조명 제외: A 는 C4 외에는 조명을 켜지 않아 밤에 0 lux).
  그래도 비교 가능한 실행이 C6 · C19 · C3 의 9쌍뿐이고 −6.8 % 에 그친다 — C6 은 이슬점 기반 제습으로 −53 %, C19 는 비슷(+2.3 %), C3 은 실링팬 몇 Wh 차이(5.5 vs 8.8 Wh)가 비율로 커 보인다.
  **표본이 작아 '20 % 절감'을 입증하지 못했다**고 보고한다 — A 가 목표를 지키는 시나리오가 적다는 것 자체가 협조 제어의 효과(목표 달성)이기도 하다
- **#10 PM 피크 미달(−14.9 %):** 비교 쌍 6개뿐(C9 −19.5 % · C17 −2 %: 전력 한도로 후드 외 부하를 차단하는 시나리오) — 표본이 작아 결론을 내리기 어렵다
- **C8 대비 장면:** W12 막바지 보완(외기가 냉방 목표보다 더우면 즉시 에어컨) 이후 C8(외기 27 °C)은 시작부터 에어컨이 냉방을 맡아,
  '오염 등급에 따라 창문 · 배기가 단계적으로 준다'는 장면 대신 '배기 0 + 필터 흡기 + 에어컨'을 보인다 (`x8_vs_c8.png`).
  외기 24 · 22 · 20 °C 로도 시험했지만 방의 열용량 때문에 창문 환기로 15분에 0.1–0.4 °C 만 내려가 매번 에어컨으로 승격된다 —
  **에어컨이 있는 방에서 환기 냉방은 15분 진전 기준을 넘기 어렵다**(승격 기준 · 열용량의 상호작용, W14 이후 검토 항목)
- **주광 모델:** 하늘 상태별 직사광 비율(맑음 0.8 · 구름 0.3)은 가정 — 렌더는 해 · 하늘을 따로 찍었다 (docs/06 v2.2)
- **고속 모드 응답 시간:** 액추에이터는 1차 지연 근사 — #2 · #3 은 물리 모드 값만 쓴다

- **가장 민감한 것은 침기(틈새 바람)다.** 0.5 ACH(틈이 많은 원룸)면 비 · 고습 외기 시나리오(C1 · C13 · C18)에서 습기가 더 들어와 습도 회복 판정을 놓친다 —
  제어기의 판단이 아니라 제습 용량(에어컨 제습 0.5 L/h)의 한계. 실제 설치 전 침기 측정(블로어 도어 또는 CO₂ 감쇠법)이 필요하다
- **틈새 유입 식(docs/06 §5.1)은 결론을 바꾼다.** 'positive_zero'(양압이면 침기 0)이면 흡기팬 양압 운전 중 기저 침기가 사라져
  기본 환기 충족(C11 · C12) · CO₂(C8)가 떨어지고, C15 는 빨래 건조 감지(E10 습기 수지 잔차)가 진입하지 못한다 — 제어기의 습기 수지 추정이
  'additive' 를 가정하기 때문이다(참값 · 제어용 모델 불일치에 대한 민감도). 두 식 중 어느 쪽이 실제에 가까운지는 실측으로 정해야 한다
- 후드 포집률은 PM 피크를 ±4 µg/m³ 움직이지만 판정은 그대로 · 창 U값은 시험 시나리오(대부분 1–4 h)에서 영향이 거의 없다

## 8. 실측 기상 — 평가 연도 대입 · 연도 분리 (docs/11 필수 조치 3 · 2026-10-19)

자료: Open-Meteo 과거 기상 API (ERA5 재분석 · 서울 기상청 108 지점 좌표 · 시간별 기온 · 습도 · 일사 · 강수 · 운량 · 풍속) — `data/weather/` (학습 2021–2023 · 평가 2024).
재분석은 관측을 동화한 격자 값이다(지점 관측 아님) — 기상청 ASOS 로 바꿀 때는 같은 열의 CSV 로 교체한다.
`tools/run_measured_weather.py` → `tools/analysis/randomized_summary.py --kind weather` (`results/tables/measured_weather_summary.md`).

**방법.** 시나리오마다 시작 시각이 같고 시작 외기(기온 ±2 °C · 습도 ±10 %p · 비 여부)가 전제와 가까운 2024년의 날 5개를 고른다(모자라면 허용치 ×2 — C1 · C4 · C5 · B4 · X6 · X7 · X8).
그날의 기온 · 습도 · 일사(→ 조도, 참값 모델과 같은 발광 효율 105 lm/W) · 하늘 · 풍속 변화를 10분 간격으로 넣는다. 시나리오 events 가 바꾸는 외기 키(시험 자극)와 PM2.5 · 난방 경계는 시나리오 값을 쓴다. 참값 계수는 명목값 · 판정은 동결 정의.

**2R2C 제어용 모델 — 학습 / 평가 연도 분리** (`tools/energy/weather_crossyear.py` · `results/tables/weather_crossyear.md`):

- 합성 날씨(사인파 일교차 · 일정 습도)로 식별한 모델은 실측 날씨에서 오차가 3배로 커진다 — **EXP-4 의 0.52–0.70 °C 는 같은 합성 분포 안에서 잰 값**이므로 일반화 근거가 아니다
- 실측으로 학습해도 어느 2주를 쓰느냐에 따라 0.9–2.3 °C 로 흔들린다 — 한 계절 2주는 식별에 부족하다(특히 서늘한 6월 시험 기간에 큰 오차)
- 조치(제안 — 아직 하지 않음): 제어용 모델을 실측 학습 연도 여러 기간으로 다시 식별하고, 평가 연도로 검증한다. 모델을 바꾸면 제어기 동작이 바뀌므로 모든 결과를 다시 돌려야 한다

**남은 한계:** 시나리오 길이(최대 8 h)만큼만 실측을 넣었다 — 연속 폭염 · 장마 같은 여러 날 운전은 아직 없다. PM2.5 는 실측을 넣지 않았다(시나리오 자극). 물리 모드 39회는 명목 날씨.
