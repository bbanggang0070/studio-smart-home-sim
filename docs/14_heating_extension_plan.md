## 1. 목표와 연구 질문

**목표** — 겨울에 난방 · 가습 · 환기 · 결로 방지 · 외출 절약이 서로 부딪칠 때, 보일러까지 수단 사다리에 넣은 협조 제어가 기존 방식보다 실내 환경과 비용을 더 잘 지키는지 시뮬레이션으로 확인한다.

| # | 질문 | 비교 |
|---|---|---|
| H-RQ1 | 겨울 목표 충돌(가습 ↔ 결로 · 환기 ↔ 난방 · 샤워 · 빨래)에서 환경 결과 통과율이 기준선보다 높은가 | 제안-H vs A-H · A′-H · B-H |
| H-RQ2 | 외출 셋백 · 프리히팅으로 같은 쾌적에서 비용(가스 + 전기, 원)이 줄어드는가 | 기대비용 비 |
| H-RQ3 | 바닥난방처럼 느린 열원에서 예측 프리히팅이 단순 규칙(귀가 N분 전 켜기)보다 나은가 | EXP-5 교훈 반영 — '언제나 같은 셋백' 기준 정책 포함 |
| H-RQ4 | 난방을 넣어도 여름 결과(v1.29)가 바뀌지 않는가 | 여름 33개 회귀 |

## 2. 원룸 난방의 현실과 편입 방식

### 2.1 대상 설비 *(가정 — 국내 원룸 일반)*
- 개별 가스보일러(벽걸이) + 온수 바닥난방 · 방 하나 = 난방 구역 하나
- 제어: 유선 룸 온도조절기(실내 온도 · 온돌 모드 · 예약 · 외출) — 보일러와 2선 통신 또는 접점
- 일부 원룸은 냉난방기(에어컨 난방 모드) · 전기 라디에이터

### 2.2 편입 방식 비교

| 안 | 방법 | 장점 | 단점 | 계획 |
|---|---|---|---|---|
| **H-a 온도조절기 교체** | Wi-Fi 룸 컨트롤러로 교체 (제조사 호환 확인 필요) | 설정 온도 · 모드를 그대로 씀 · 안전 기능 유지 | 부품비 *(가정 5–15만원)* · 제조사 호환 · 임대 원룸 교체 허락 | **기본안** |
| H-b 접점 릴레이 | 기존 조절기의 외부 접점(있으면)에 릴레이 | 싸다 | 켬/끔만 · 조절기 기종 의존 · 배선 작업 | 대안 (민감도) |
| H-c 냉난방기 난방 모드 | 기존 IR 로 에어컨 난방 | 추가 부품 0 | 냉난방기가 있는 원룸만 · 바닥난방과 열 특성 다름 | 가전 프로파일 하나로 (X 시나리오) |
| H-d 전기 라디에이터 | 계량 플러그 켬/끔 | 쉽다 | 보일러를 대체하지 않음 · 전력 한도(I8) 부담 | 범위 밖 유지 |

- **센서는 늘리지 않는다** (7종 유지). 보일러 상태는 **보일러 전원 계량 플러그 전력**(연소 · 순환펌프 가동 시 증가 *(가정)*)으로 확인 — 기존 '가전 전력' 비센서 신호 · E9 확인 로직과 같은 틀
- 부품비 영향: 기본안 기준 137,300원 → *(가정)* 약 19–29만원. 실행 전 제품 가격 확인

### 2.3 안전 원칙
- 보일러 자체 안전 장치(과열 · 동파 방지 · 점화 실패)는 보일러에 맡기고 **제어기는 끄지 않는다** — 제어기는 설정 온도 · 모드만 바꾼다
- 동파 방지: 어떤 모드 · 계층에서도 실내 ≥ **10 °C** *(가정)* 를 L1 에서 보장 (E16)

## 3. 참값 환경 모델 (env_model · 고속 / 물리 공통)

### 3.1 열 구조 — 3R3C → 4R4C (바닥 슬래브 노드 추가)
```text
지금 (3R3C):  공기 Ta ─ 축열 질량 Tm ─ 외피 Te ─ 외기 To  (+ 난방 경계 조건: 공기 노드에 이상적 열)
변경 (4R4C):  바닥 슬래브 Tf ─(R_fa)─ 공기 Ta ─ 축열 Tm ─ 외피 Te ─ 외기 To
              Tf ─(R_fg)─ 아래층 · 지반 Tg (경계 조건)
              Cf·dTf/dt = Q_hyd − (Tf−Ta)/R_fa − (Tf−Tg)/R_fg
              Q_hyd = 보일러 출력 × 배관 효율 (공급수 온도 · 유량 1차 지연 τ_b)
```
| 계수 | 값 *(가정 · 민감도 대상)* | 근거로 찾을 것 |
|---|---|---|
| 바닥 열용량 Cf | **0.4–0.6 kWh/K** (17.5 m² × 모르타르 5–7 cm × 약 2,000 kg/m³ × 0.84 kJ/kgK — v0.1 의 4–8 kWh/K 는 10배 과대 · 2026-10-28 정정) | 온수 바닥난방 시공 단면 · 재료 물성 |
| 바닥 → 실내 열류 | **EN 1264 특성식 q ≈ 8.92 · (θ_바닥 − θ_실내)^1.1 W/m²** (복사 + 대류 합) — 17.5 m² 에서 ΔT 3 K 면 약 0.5 kW | EN 1264 (원문 확인 후 인용) |
| 배관 → 바닥 | 공급수 온도(설정 40–60 °C *(가정)*) 와 바닥 온도 차 × 배관 열전달 K_p *(가정 60–90 W/K)* · 보일러 최대 출력으로 상한 | 식별 · 민감도 |
| 보일러 출력 | 원룸용 소형 가스보일러 최대 출력 *(가정 · 제품 확인)* — 실제 전달량은 배관 · 바닥이 제한 | 제품 사양 |
| 보일러 효율 | 0.85 (일반) · 0.90 (콘덴싱) | 제품 사양 · 문헌 |
| 응답 | 바닥 표면이 1 K 오르는 데 수십 분–수 시간 | 식별 · 문헌 |

- 기존 `heating` 경계 조건(A13)은 **옵션으로 남긴다** — v1.29 시나리오 · 결과 재현용 (`heating.mode: boundary | hydronic`)
- 결로 · 습도 모델은 그대로 (창 표면 온도는 실내 온도에 따라 달라지므로 난방 제어가 결로 결과를 바꾼다 — 이것이 확장의 핵심 상호작용)

### 3.2 보일러 동역학 · 에너지
- 상태: 꺼짐 · 대기 · 연소(출력 %) · 순환 · 이상
- 최소 연소 · 최소 정지 시간 *(가정 3 · 5분)* — 잦은 점화 방지 (참값 쪽에도 존재)
- 가스 사용량 [kWh_gas] = 연소 출력 / 효율 · 전력(펌프 · 팬) [Wh] *(가정 80–120 W 가동 · 5 W 대기)*
- **비용 단위 통일**: 가스와 전기를 같은 단위로 비교하려면 원(₩)으로 환산 — 도시가스 원/MJ · 전기 원/kWh (누진 · 계절 요금) 를 `config` 에 두고 **요금 변경 민감도** 를 본다

### 3.3 물리 모드 (Isaac Sim)
- 난방은 관절 · 접촉이 필요 없다 → **환경 노드가 같은 4R4C 를 계산** (지금 물리 모드도 열은 환경 노드가 계산) · Isaac 쪽 변경은 바닥 색 표시(시각용) 정도
- 물리 모드 시나리오는 창문이 관여하는 겨울 상황 1–2개만 (H3 · H6)

## 4. 제어기 변경 (v1.30-H · `scripts/controller/` 순수 Python)

### 4.1 제어용 모델 (참값과 분리 유지)
- 2R2C(공기 · 축열) + **바닥 1노드** = 3노드 제어용 모델 — 운전 기록으로 식별 (`tools/energy/train_energy_model.py` 확장 · 난방 운전 무작위화)
- 겨울 실측 기상(2021–23)으로 식별 → 2024 겨울로 검증 (여름 2R2C 의 연도 분리 점검과 같은 방식)

### 4.2 모드별 난방 목표 (`user_modes.yaml` · 사용자 편집 범위 포함) *(가정)*
| 모드 | 난방 목표 | 비고 |
|---|---|---|
| NORMAL | 21 °C | A13 과 같은 값 — 비교의 기준점 |
| STUDY | 21 °C | |

### 4.3 난방 사다리 (싼 수단부터)
```text
1. 일사 받기     — 낮에 블라인드 열기 (겨울 · 재실 · 눈부심 규칙과 충돌 시 조도 규칙 우선)
2. 열 손실 줄이기 — 창문 닫힘 유지 · 기본 환기는 짧고 강하게(퍼지) · 밤 블라인드 닫기(단열)
3. 실링팬 역회전 — 천장 쪽 더운 공기 섞기 (I5 의 겨울판)
4. 보일러        — 설정 온도 · 출력
(5. 냉난방기 난방 — 가전 프로파일에 있을 때만 · 빠른 보조)
```

### 4.4 새 상호작용 규칙 (docs/07 에 I11–I14 추가)
| 규칙 | 내용 | 충돌 대상 |
|---|---|---|
| **I11 환기 ↔ 난방** | 창문 · 배기로 환기하는 동안 보일러 설정을 올리지 않는다 · 겨울 기본 환기는 '짧고 강하게(퍼지)' 로 바꿔 열 손실을 줄인다 | 기본 환기 미달(E4) · 요리(E1) · 샤워(E3) |
| **I12 난방 ↔ 결로 · 가습** | 실내 온도가 오르면 창 표면 결로 여유가 바뀐다 → I4 가습 상한을 난방 상태와 함께 다시 계산 · 결로 위험이면 '가습 줄이기' 보다 '실내 온도 유지 + 순환' 을 먼저 | I4 · E2 |
| **I13 후드 ↔ 난방** | 요리 중 후드 배기로 찬 외기가 들어오면 보일러를 즉시 올리지 않는다(요리가 끝나면 회복) — 4차까지 드러난 '겨울 후드 냉기' 결함과 연결 | E1 · I3 |
| **I14 빨래 건조 ↔ 난방** | 빨래 건조(E10)는 실내 온도를 1–2 °C 올리면 빨리 마른다 — 허용 손실 예산 안에서 난방을 수단으로 쓴다 | E10 · L4.5 |

### 4.5 외출 · 귀가 (EXP-5 교훈 반영)
- 기대비용 계획기(E13) 구조를 난방에 쓴다: 셋백 · 끄기 · 귀가 전 프리히팅 시작 시각
- **EXP-5 에서 냉방 계획기가 '언제나 끄기' 보다 비쌌다** → 난방에서는 처음부터 **기준 정책(언제나 셋백 16 °C · 언제나 끄기 · 귀가 N분 전 고정)** 을 함께 평가하고, 계획기가 이를 이기지 못하면 단순 규칙을 기본값으로 쓴다 (사전 등록에 미리 적는다)
- 바닥난방은 응답이 느려 끄면 회복에 오래 걸린다 → 냉방과 반대로 셋백이 이길 가능성이 크다 — 이것 자체가 H-RQ3 의 질문

**바꾸는 것 (모두 보일러가 있을 때만 — v1.29 회귀 그대로)**
- C5 난방 사다리 3 (실링팬 역회전) 끔 — `heating.fan_reverse_rung: false` (결로 대응 E2 의 역회전은 그대로)
- C6 난방 중 가습 목표 = 모드 하한 + `heating.humidify_target_above_lo_pct` (5 %p · 40 → 45 %) — 결로 상한(I4)은 그대로 · 겨울 실내 40–45 % 권고와 결로 위험 사이
- C7 난방 중 E2 '위험' 의 비싼 수단(제습 · 간헐 환기 · 배기)은 **지금 여유**가 위험 기준 아래일 때만 — 블라인드 개방 · 가습 금지 · 역회전은 지금처럼 유지(싼 것부터)
- C8 고장 감지 = 조절기 켬 · 실내 < 설정 − `fault_demand_below_c`(0.5) 가 `fault_confirm_s`(900 s) 이어졌는데 연소 전력 · 온도 상승 없음 (전: 1.0 °C · 1800 s)

  '온도 상승 0.3 °C' 조건이 정상으로 오판 (지연 8,660–10,521 s). 전력을 모를 때만 온도 상승 (`appliances.boiler.fault_power_decides`) → 지연 900 s
- 비교용 변형 `proposed_v131` (`harness.yaml controller_variants`) — C5–C8′ 플래그만 v1.31-H 값 · 같은 새 데이터 짝 비교 · v1.31-H 보관본과 지표 대조로 재현 확인
- M5 건물 프리셋을 한 곳에 (`harness.yaml building_presets`) · **old_light** (노후 + 열용량 ×0.4 · τ12 ≈ 48 h · 옥탑 · 패널 · 목조 원룸) 추가 · 무작위 열용량 범위 ×0.35–1.4 (τ12 약 40–250 h) · `tools/energy/building_calibration.py` 로 UA · τ · 하루 가스 재현
- M6 참값에 조절기 점화 요구(`truth.boiler_call`) 출력 · 지표 `boiler_fault_alert_delay_s` (첫 점화 요구 → 알림) · 개발 H11 판정을 '점화 요구 뒤 1시간 안' 으로 (판정 개정은 docs/15 §12 에 기록)
