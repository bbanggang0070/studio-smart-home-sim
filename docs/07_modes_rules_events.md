# 제어 구조 설계서 — 규칙 + 모드 + 이벤트

> **신규 산출물** · 작성일 2026-10-05 · v1.0 → **v1.1 (기획 v3.1 · 피드백 2)** — 이벤트 13종 · 규칙 I8 · I9 · **우선 목표 + 허용 손실 예산** · 30분 예측 검사
> **작성 배경:** 가전 편입(11종)으로 장치 조합이 폭증했다. 상황마다 특수 케이스 코드를 쓰면 유지할 수 없으므로,
> 제어를 **규칙(어떻게) · 모드(무엇을 원하나) · 이벤트(지금 무슨 일인가)** 세 요소의 조합으로 재구성한다.
>
> 가전·센서 상세는 [`06_appliance_integration.md`](06_appliance_integration.md), 파라미터는
> [`config/user_modes.yaml`](../config/user_modes.yaml) · [`config/thresholds.yaml`](../config/thresholds.yaml) v3.0 참조.

## 0. 한눈에 보기

```text
 사용자 ──► 모드    (의도)   "지금 공부한다"          → 목표값 · 상한 · 허용 장치
 센서   ──► 이벤트  (상황)   "요리가 시작됐다"        → 일시적 규칙 추가 · 상한 덮어쓰기
 설계자 ──► 규칙    (방법)   "우천이면 창문을 닫는다"  → 조건 → 행동 · 우선순위

            모드 ⊕ 이벤트 ⊕ 규칙  ──►  수단 사다리  ──►  중재  ──►  가전 보호  ──►  출력
```

| 요소 | 누가 정하나 | 수명 | 바꾸는 것 | 예 |
|---|---|---|---|---|
| **모드** | 사용자 (또는 AUTO) | 사용자가 바꿀 때까지 | **목표값 · 상한 · 허용 장치** | 공부: 기본 환기 40 m³/h, 소음 N2 |
| **이벤트** | 센서 · API 자동 감지 | 진입 → 해제 조건까지 | **임시 오버레이** (규칙 추가 · 상한 완화/강화) | 요리: 후드 + 보상 급기, 소음 N3 임시 |
| **규칙** | 설계자 (config) | 고정 | **조건 → 행동** · 계층 | 제습기 ⟂ 가습기 |

### 왜 세 요소로 나누었나

| | 나누지 않으면 | **나누면** |
|---|---|---|
| 경우의 수 | 모드 6 × 이벤트 9 = **54가지 특수 케이스 코드** | 모드 6개 + 이벤트 9개 + 규칙 표 = **15개 정의의 조합** |
| v2.1의 사례 | "수면 중 팬 600 rpm"은 모드에, "우천 폐쇄"는 규칙에 있었지만 **"요리"처럼 일시적인 일을 둘 곳이 없었다** | 일시적인 일은 **이벤트**가 된다 |
| 설명 가능성 | 왜 그 명령이 나왔는지 코드를 읽어야 안다 | 모든 명령에 **사유 코드**(모드/이벤트/규칙 ID)가 붙는다 |

## 1. v2.1 대비 무엇이 바뀌었나

| | v2.1 | **v3.0** |
|---|---|---|
| 모드 결정 | **센서가 자동 판정** (STUDY / RELAX / SLEEP / OFF) | **사용자 설정 6종** — 그중 **AUTO가 v2.1 자동 판정을 계승** |
| 모드 이름 | RELAX · OFF | **NIGHT(야간)** · **AWAY(외출)** — 무재실 절전은 모드가 아니라 **제어 상태**로 분리 |
| 일시적 상황 | 규칙 안에 흩어짐 | **이벤트 계층 신설** (9종) |
| 수단 선택 | 시나리오별 기대 동작 | **수단 사다리**로 일반화 ([`06` §4](06_appliance_integration.md)) |
| 우선순위 | 안전 > 절전 > 모드 > 온·습도 > 조도 | **안전 > 건강·재산 이벤트 > 절전 > 모드 > 쾌적 > 조도** (6계층) |

> ### v2.1 문구 정정
> v2.1은 *"사용자가 버튼으로 모드를 고르는 것은 제어 연구로서의 값어치가 없다"* 고 적었다.
> v3.0에서 이 판단을 바로잡는다. **연구 대상은 '모드를 누가 고르는가'가 아니라 '모드가 정한 목표 안에서 11종의 수단을 어떻게 협조시키는가'** 다.
> 사용자는 **의도**를 정하고, 시스템은 **수단**을 정한다. 자동 판정은 AUTO 모드로 그대로 남는다.

## 2. 사용자 모드 6종

### 2.1 모드 정의

| 항목 | 🏠 **일반** NORMAL | 📖 **공부** STUDY | 🌙 **야간** NIGHT | 😴 **수면** SLEEP | 🚪 **외출** AWAY |
|---|---|---|---|---|---|
| 의도 | 일상 생활 | 집중 | 취침 전 휴식 | 수면 | 부재 |
| 조명 | 천장 400 lux · 4000 K | **책상 600 lux · 5500 K** + 천장 300 lux | 150 lux · 3000 K | 30 lux · 2700 K → **15분 후 소등** | 소등 |
| 냉방 목표 (여름) | 26 °C | 25 °C | 26 °C | 27 °C + 실링팬 약 | 정지 · 귀가 예약 시 **30분 전 프리쿨링** |
| 습도 목표 | 40–60 % | 40–60 % | 40–60 % | 45–60 % | **≤ 70 %** (곰팡이 방지만) |
| **기본 환기** (v1.4) | 25 m³/h | **40 m³/h** | 25 m³/h | 16 m³/h (N0 이내) | 0 (무재실) |
| **소음 등급** | N2 | N2 | N1 | **N0** | – |
| 창문 | 정상 | 정상 | 정상 | **우선** (팬보다 창문) | **닫힘 (보안)** |
| 블라인드 | 채광 | 채광 · 눈부심 차단 | **닫힘 (프라이버시)** | 닫힘 · 여름 야간 냉각 시 개방 | 기본 30° |
| 금지 장치 | – | – | 후드 강 | **제습기** · 후드 · 청정기 2단+ | 가습기 · 조명 · 실링팬 · 청정기 |

**🤖 자동 AUTO** — 시스템이 위 5개 중 하나를 고른다.

| 선택 결과 | 조건 (v2.1 자동 판정 계승) |
|---|---|
| STUDY | 재실 고정 + mmWave 책상 게이트(2–3) + 08–22시 |
| NIGHT | 재실 + 21–24시 + 책상 미사용 |
| SLEEP | 재실 + 침대 게이트(5–6) + 23–07시 |
| AWAY | **문 닫힘 후 판정 창 3분에 사람 증거 없음 → 빈방 고정** (이벤트 E8 · 폴백 시 15분 융합) |
| NORMAL | 그 외 |

> **근거:** 조도 = KS A 3011 (독서 300–750 / 거실 100–200 lux) · 색온도 = 멜라토닌 억제 연구 ·
> 기본 환기량 = **1인 기준 필요 환기량**(공부 800 · 그 외 1,000 ppm 상당 — [`06` §5.2](06_appliance_integration.md)) · 근거: 1,000 ppm 이상에서 의사결정 수행 저하(Satish et al., 2012) · 실내 CO₂ 유지기준 1,000 ppm(실내공기질 관리법).
> **v1.4: CO₂는 측정하지도 계산하지도 않는다 — 필요한 환기량을 처음부터 공급해 보장한다** (§3.3)

### 2.2 사용자가 바꿀 수 있는 것 / 없는 것

| 항목 | 기본값 | **사용자 설정 범위** | 비고 |
|---|---:|---|---|
| 냉방 목표 | 26 °C | 24 – 28 °C | 수면은 25 – 28 °C |
| 기본 환기량 (v1.4) | 모드별 (§2.1) | 15 – 50 m³/h | **재실 중 하한 15 m³/h** — 사용자도 더 낮출 수 없다 |
| 습도 목표 범위 | 40 – 60 % | 하한 30 – 50 · 상한 50 – 65 % | **가습은 이슬점 규칙이 추가로 제한** (I4) |
| 조도 · 색온도 | 모드별 | ±30 % · 2700 – 6500 K | |
| 모드별 소음 등급 | 모드별 | N0 – N2 | N3는 이벤트 전용 |
| 자동 전환 시간대 | 위 표 | 30분 단위 | AUTO에서만 |
| 외출 자동 전환 | 켬 | 켬 / 끔 | 끄면 무재실 시 **절전 상태**만 진입 |
| 귀가 예약 프리쿨링 | 없음 | 시각 지정 | 시뮬레이션에서는 시나리오 입력 |

**사용자가 절대 바꿀 수 없는 것** — 안전 · 재산 · 기기 보호

| 고정 항목 | 이유 |
|---|---|
| 끼임 감지 (반력 ≤ 100 N) | 안전 |
| 우천 · 외기 미세먼지 인터록 | 안전 · 건강 |
| 이슬점 가습 상한 (I4) · 결로 위험 대응 | 재산 (곰팡이 · 마감재 손상) |
| 압축기 보호 · 실링팬 방향 전환 대기 | 기기 수명 |
| 재실 중 최소 환기 15 m³/h · 기본 환기 미달 대응(E4) | 건강 |

> 사용자 설정값은 `config/user_modes.yaml` 에 저장되고, 제어기는 로드 시 **범위를 벗어난 값을 클램프하고 경고를 발행**한다.

### 2.3 소음 등급 (N0 – N3)

모드는 장치별 상한을 직접 나열하지 않고 **소음 등급 하나**로 지정한다. 등급이 장치별 상한으로 펼쳐진다.

| 등급 | 의미 | 배기팬 | 흡기팬 | 실링팬 | 에어컨 풍량 | 청정기 | 제습기 | 후드 |
|---|---|---:|---:|---|---|---|:---:|---|
| **N0** | 수면 | ≤ 600 rpm | ≤ 700 rpm (≈ 21 m³/h) | 약 | 약 | 1단 | ✗ | ✗ |
| **N1** | 조용 | ≤ 1,000 | ≤ 1,200 | 약 | 약 · 중 | 2단 | ✗ | 약 |
| **N2** | 보통 | ≤ 1,400 | ≤ 2,000 | 강 | 자동 | 3단 | ✓ | 약 |
| **N3** | 제한 없음 | 2,000 | 2,000 | 강 | 강 | 3단 | ✓ | 강 |

> **N3는 모드로 고를 수 없다.** 요리(E1) 이벤트 중에만 임시로 적용된다. 샤워(E3) 중에는 N2 임시(수면 모드면 N1).
> 수면 N0의 흡기 상한 21 m³/h는 수면 기본 환기 16 m³/h를 덮는다([`06` §5.2](06_appliance_integration.md)). 필터가 막혀 못 채우면 E4.

### 2.4 모드 전환 규칙

| 전환 경로 | 방법 | 우선 |
|---|---|:---:|
| **수동** | `/studio/cmd/mode` ← `"STUDY"` 등 (실물: 버튼 · 앱 — 범위 밖) | 1 |
| **스케줄** | `user_modes.yaml` 의 요일 · 시각 | 2 |
| **AUTO** | §2.1 자동 판정 | 3 |
| **귀가 (E7)** | AWAY 중 **문 열림** → **직전 모드로 복귀** | – |
| **외출 (E8)** | 문 닫힘 후 판정 창 3분에 사람 증거 없음(빈방 고정) → AWAY (옵션) | – |

- 수동 설정은 **다음 스케줄 경계 또는 외출까지** 유지된다. 그 뒤에는 원래 경로(스케줄/AUTO)로 돌아간다
- **자동 전환에만 히스테리시스 10분**을 둔다 (경계 시각 채터링 방지). 수동 전환은 즉시 반영
- 모드 전환은 **목표값 세트를 바꿀 뿐 액추에이터를 직접 구동하지 않는다.** 구동은 다음 정책 주기(1 Hz)에 규칙이 결정한다

## 3. 이벤트 15종

이벤트는 **진입 조건 · 해제 조건(히스테리시스) · 오버레이 · 계층**을 갖는다. 여러 이벤트가 동시에 활성일 수 있다.

| ID | 이벤트 | 감지 소스 | 진입 | 해제 | 오버레이 | 계층 |
|---|---|---|---|---|---|:---:|
| **E1** | **요리** COOKING | **후드 아래 온도 (v1.3 1순위 · 가스 · 빌트인 포함)** · 쿡탑 전력 (플러그형) · 미세먼지는 연기 세기 · 원인 구분 | **후드 아래 − 실내 ≥ 8 °C ∧ 상승 ≥ 3 °C/분** ∨ 쿡탑 가열 진입 | 후드 아래 온도 하강 ∧ 쿡탑 꺼짐 (+ PM ≤ 기준 + 10) | 후드 · **보상 급기** · 청정기 · 소음 **N3 임시** | L2 |
| **E2** | **결로 위험** CONDENSATION | 온습도 + 외기온 → 결로 여유 Δ | 경고 Δ < 2.0 °C / **위험 Δ < 0.5 °C** | Δ > 3.0 °C 가 10분 지속 | 가습 금지 · 실링팬 역회전 · 블라인드 45°(경고)/0°(위험) · 제습기 · 간헐 환기 | L5 / **L2** |
| **E3** 🔄 | **샤워** SHOWER (v1.4) | 온습도 · 후드 아래 온도 · 가습기 전력 · 레이더 | **5분 RH ≥ +8 %p** ∧ 후드 아래 온도 정상(요리 아님) ∧ 가습기 꺼짐 ∧ 재실 (+ 직전 레이더 무신호 5분 = 욕실 사용 → 신뢰도 가산) | 실내 이슬점 ≤ 샤워 전 + 1 °C ∨ 40분 | 배기팬 강 + **균형 급기**(I3) · **I10** · **에어컨 제습 강화 / 제습기**(I6 해제) · 소음 N2 임시 · 겨울: 가습 정지 · 실링팬 역회전 | L2 |
| **E4** 🔄 | **기본 환기 미달** VENT_SHORTFALL (v1.4) | 흡기팬 명령 rpm × 필터 상태 · E9 · E11 | 기본 환기량 미달 10분 | 충족 5분 | 다른 수단 보충(창문 소폭 · 배기 + 흡기) · 소음 **1단계 완화**(N0 → N1) · 필터 교체 · 점검 알림 | **L2** |
| **E5** | 강우 RAIN | 기상청 API | 강우 | 그친 후 300 s | 창문 폐쇄 | L1 |
| **E6** | **외기 오염** OUTDOOR_PM | 에어코리아 API + **실측 교차 확인** | 나쁨 이상 | 개선 후 300 s | 창문 상한 · **급기 없는 배기 금지** · 필터 급기 | L1 |
| **E7** | 귀가 ARRIVAL | **문 열림 (v1.2 1순위)** ∨ 휴대폰 Wi-Fi 접속 ∨ mmWave 이동 (AWAY 중) | 트리거 | 즉시 | AWAY → 직전 모드 · 프리쿨링 종료 · 현관 조명 | 모드 |
| **E8** | 외출 DEPARTURE | **문 닫힘 후 판정 창 3분에 사람 증거 없음** (v1.2) · 폴백: Wi-Fi 해제 ∧ mmWave 클리어 ∧ 전력 없음 15분 | 판정 창 종료 | 다음 문 열림 | AWAY 전환 (옵션) | 모드 |
| **E15** 🆕 | **불 켜고 외출** UNATTENDED_COOKING | 빈방 판정 ∧ (후드 아래 온도 높음 ∨ 쿡탑 전력 가동) | 판정 창 종료 시점 | 온도 하강 · 쿡탑 꺼짐 | **즉시 사용자 알림** · 플러그형 인덕션은 **전원 차단** · 가스는 경고만 | **L1** |
| **E14** 🆕 | **문 센서 이상** DOOR_SENSOR_FAULT | 빈방 고정 중 실내 강한 사람 신호 + 기기 조작 (모순) · Wi-Fi 출입은 있는데 문 이벤트 24시간 없음 · 문 10분 이상 열림 | 모순 감지 | 정상 문 이벤트 재개 | **24시간 융합 판정으로 폴백** · 사용자 알림 | L1 |
| **E9** | **가전 이상** APPLIANCE_FAULT | **전력 확인(10 s) 1차** · 환경 효과 2차 | 재송신 2회 실패 · **물통 가득**(명령 ON + 대기) · **효율 저하**(전력 정상 + 효과 미달) | 정상 복귀 | 해당 가전을 사다리에서 제외 · 사용자 알림 | L1 |
| **E10** 🆕 | **빨래 건조** LAUNDRY_DRYING | **세탁기 탈수 종료** + RH 완만 상승 ∨ 사용자 선언 | 종료 엣지 후 RH ≥ +3 %p/h 가 1시간 · 요리 없음 | 잔여 수분 ≤ 5 % ∨ 최대 8 h | **우선 목표 = 건조 시간** · I6 해제 · 허용 손실 예산 (§5.4) | **L4.5** |
| **E11** 🆕 | **전력 한도** POWER_LIMIT | 기기 전력 합계 | ≥ 한도 90 % | < 75 % 가 5분 | 미뤄도 되는 부하부터 차단 (I8) | **L1** |
| **E12** 🆕 | **수동 조작** MANUAL_OVERRIDE | 명령 없는 전력 상태 변화 | 엣지 `source = manual` | 30분 경과 | 해당 기기 자동 제어 보류 · 목표 오프셋 학습 (I9) | L4 |

### 3.1 요리 감지 (E1)

> **v1.6 구현 규칙 (2026-10-09, `scripts/controller/event_detector.py`)**
> - 진입: 후드 아래 − 실내 ≥ 8 °C ∧ 상승 ≥ 3 °C/분 ∨ 쿡탑 전력 ≥ 300 W. 진입 후 PM 이 +10 µg/m³ 오르면 **열 + 연기(요리)**, 아니면 **열만(수증기 — 후드 약 · 청정기 그대로)**
> - 해제: **열 꺼짐(후드 아래 ≤ 실내 + 3 °C ∧ 쿡탑 꺼짐)이 기준**이다. PM ≤ 진입 시 + 10 은 보조 조건이라 열이 꺼진 뒤 **최대 `release_hold_s`(5분)** 까지만 기다린다 → 이어서 후드 잔류 5분.
>   PM 에 무기한 묶으면 요리 뒤에 생긴 **열 없는 미세먼지에도 E1 이 이어져 후드가 켜진다**(B7 ② 위반) — 이를 막기 위한 정리다
> - 후드 단수는 열이 남아 있는 동안만 다시 고르고(60 s 주기), 열이 꺼진 뒤에는 마지막 단수를 유지한다
>   **단 외기 오염(E6) 중이면 열이 꺼진 시점에 '발생원 없음'으로 한 번 더 예측**해 고른다 — 대개 '끔'이 되어 잔류 운전을 하지 않는다.
>   후드 음압이 오염 외기를 끌어들이는 것을 막기 위해서다 (C9 외기 150: 요리 후 PM 35 복귀 1,440 s → 882 s)

센서 값만으로는 요리와 외기 유입을 구분할 수 없다. **외기 유입분을 모델로 예측하고, 설명되지 않는 잔차를 실내 발생으로 본다.**
→ 알고리즘 · 판별표: [`06` §3.3](06_appliance_integration.md)

### 3.2 결로 위험 (E2) — 2단계

| 단계 | 조건 | 대응 | 계층 |
|---|---|---|:---:|
| ⚠️ 경고 | Δ < 2.0 °C | 가습 상한 하향 · 실링팬 역회전 · **블라인드 슬랫 45°** (시선 차단 유지 + 공기 순환) | L5 쾌적 |
| 🔴 위험 | Δ < 0.5 °C | + 제습기 · **블라인드 0°(완전 개방)** · 외기 절대습도가 낮으면 간헐 환기 | **L2 재산** |

> **야간 모드의 프라이버시와 충돌한다.** 경고 단계에서는 모드(L4)와 쾌적(L5) 중 모드가 이기므로 블라인드는 닫힌 채로 슬랫만 45°로 연다.
> 위험 단계는 L2라서 모드를 이긴다 — **"사생활보다 곰팡이 방지가 우선인 경계선"을 Δ = 0.5 °C로 명시**한 것이다.

### 3.3 재실 기본 환기 (v1.4) — CO₂를 재지도, 계산하지도 않는다

**재실 중에는 1인 기준 필요 환기량을 항상 공급한다.** 사람 수를 세지 않고, 원룸 1인 가구를 설계 기준으로 삼는다(아파트 전열교환기 상시 운전과 같은 방식).

| 모드 | 기본 환기 (팬 몫) | 근거 — 1인 CO₂ 발생량 · 틈새 바람 하한 0.15회/h(6 m³/h) 제외 |
|---|---:|---|
| 일반 · 야간 | **25 m³/h** | 총 31 m³/h → 정상상태 약 1,000 ppm |
| 공부 | **40 m³/h** | 총 47 m³/h → 약 800 ppm (Satish 2012) |
| 수면 | **16 m³/h** | 총 22 m³/h → 약 1,000 ppm · N0 흡기 상한 21 m³/h 이내 |
| 외출 | 0 | 결로 · 곰팡이 방지(E2 · C14)만 |

- **수단:** ① 창문 10 % (외기 양호 · 비 X · 냉방 X · 외기온 15–28 °C) → ② **흡기팬(필터)** — 비 · 외기 오염 · 냉방 중에도 쓸 수 있다
- **이슬점 규칙 I10의 예외** — 건강을 위한 최소량이다. 바깥이 더 습하면 들어온 습기는 에어컨 · 제습기가 처리한다
- **CO₂는 시뮬레이션 참값으로만** 계산해 기본 환기량이 충분했는지 검증한다(지표 #9 · EXP-3). 제어기는 CO₂를 구독하지 않는다
- **한계:** 손님 2명 이상이면 부족할 수 있다(일반 모드 2인 ≈ 1,550 ppm). 사람 수를 세지 않기로 한 대가로 명시한다

**E4 기본 환기 미달** — 필터 막힘 · 흡기팬 고장(E9) · 전력 한도 차단(E11) · 수면 소음 상한 때문에 기본 환기량을 **10분 넘게** 못 채우면
① 다른 수단(창문 소폭 · 배기 + 흡기)으로 보충 → ② 그래도 부족하면 소음 상한을 **한 단계만** 완화(N0 → N1) → ③ 필터 교체 · 점검 알림.
공급량은 흡기팬 명령 rpm × 필터 상태(누적 가동 시간)로 추정한다. — 시나리오 X6

> **우선순위 역전처럼 보이지만 설계된 예외다.** 건강 이벤트가 모드를 이기되, **완화 폭을 1단계로 제한**해 수면을 완전히 깨우지 않는다.

### 3.4 샤워 (E3) — 습도 급상승의 원인을 가린다 (v1.4)

욕실은 따로 모델링하지 않는다. **샤워 후 욕실 문을 열 때 습기가 방으로 쏟아지는 순간**을 방의 센서로 잡는다(마이크 · 욕실 센서 없음).

| 습도 변화 | 후드 아래 온도 | 그 밖의 신호 | 판단 |
|---|:---:|---|---|
| 5분에 +8 %p 이상 | ↑ | – | 요리 수증기 → **E1** |
| 5분에 +8 %p 이상 | – | 가습기 꺼짐 · 재실 | **샤워 → E3** |
| 1시간 이상 완만 | – | 세탁기 탈수 종료 | 빨래 → **E10** |
| 완만 | – | 비 · 외기 습함 | 장마 → 제습 (이벤트 아님) |
| 상승 | – | 가습기 켜짐 | 가습기 |

- **두 번째 신호:** 재실 고정 중 **레이더 무신호 5분 이상**(욕실은 레이더 시야 밖)이 앞서 있으면 신뢰도를 더한다 — 피드백 ① "서로 다른 신호 2개"
- **v3.3 후드 아래 온도 센서가 여기서도 쓰인다** — 요리 수증기와 샤워 습기를 가른다

### 3.5 실내 환경 회복 — 창문 · 흡기가 막힐 때 (v1.4)

요리 · 샤워 · 빨래 건조는 **실내 환경을 빨리 되돌려야 하는 상황**이다. 비 · 외기 미세먼지 · 냉방 · 수면이 창문과 환기를 막아도 회복이 멈추지 않도록 네 원칙을 둔다.

| # | 원칙 | 규칙 |
|---|---|---|
| **R1** | **원인 지점에서 뺀다** — 요리는 후드, 샤워는 배기팬 | E1 · E3 |
| **R2** | **뺀 만큼 채운다** — 창문을 못 쓰면 흡기팬(필터)으로 급기. 외기 오염 시 배기 단독 금지 | I3 (개정) · I7 |
| **R3** | **바깥이 더 습하면 짧게 빼고 안에서 처리한다** — 배기로 습기를 빼는 것은 실내 이슬점이 바깥보다 2 °C 이상 높을 때만. 차이가 1 °C 아래로 줄면 배기를 멈추고 제습으로 넘긴다 | **I10** (신설) |
| **R4** | **안에서 처리하는 수단을 앞당겨 세게 쓴다** — 습기: 에어컨 제습 강화(설정 −1 °C · 제습 운전) · 제습기(이벤트 중엔 I6 해제) / 연기: 청정기 상향 / 섞기: 실링팬 | E1 · E3 · E10 오버레이 |

> **R3이 "비 오면 배기 정지"를 대신한다.** 비는 "바깥이 더 습하다"의 대리 지표였을 뿐이다.
> 여름 장맛비는 바깥 이슬점 ≈ 23 °C로 냉방 중인 실내(≈ 16 °C)보다 습해 배기가 습기를 들인다 → **배기 정지**(지금과 같음).
> 샤워 직후 실내 이슬점은 일시적으로 바깥보다 높아진다 → **비가 와도 그 동안은 배기**. 겨울비는 바깥이 차고 건조(≈ 4 °C)해 → **환기가 곧 제습**.

#### 상황 × 제한 — 회복 조합

| 상황 | 제한 없음 | **비** (여름 — 바깥이 더 습함) | **외기 미세먼지 나쁨** | 시나리오 |
|---|---|---|---|---|
| **요리** | 후드 + 창문 10–20 % + 청정기 | 후드 + **흡기팬 급기** + **에어컨 제습 앞당김** (요리가 끝나도 습도 회복까지 유지) | 후드(3안 예측) + **흡기팬 최대(필터)** + 청정기 3단 | B7 · **X5** · C9 |
| **샤워** | 배기팬 강 + 창문 10–20 % | **배기 + 흡기 동시**(이슬점 차이가 있는 동안만) → 이후 **에어컨 제습 강화 · 제습기 허용** | **배기 + 흡기(필터) 동시** — 배기 단독 금지 · 겨울이면 결로 방지 병행 | **B6 · C18 · C19** |
| **빨래 건조** | 창문 환기 + 실링팬 (바깥이 건조할 때) | **밀폐 건조** — 제습기 + 에어컨 + 실링팬 | 바깥이 건조(겨울)하면 **흡기(필터) + 배기 균형 환기** + 제습기 · 실링팬 | C15 · **C19** |

- **전력 한도와 함께:** 인덕션(2 kW) + 에어컨 + 제습기는 3 kW 한도에 닿는다. 요리 중에는 에어컨 제습으로 버티고 **제습기는 요리가 끝난 뒤 투입**한다(I8 차단 순서와 같은 방향)
- **예산(§5.4):** E3도 E10처럼 `overrides: [I6]` · `budget: 실내 온도 ±1.0 °C · 소음 N2`를 선언한다

| **R-H 건강 · 재산** | 이벤트가 추가하는 규칙 | 요리 국소 배기 · 샤워 배기 · 결로 대응 |
| **R-C 쾌적** | 목표값 추종 (히스테리시스) | 온도 · 습도 · 기본 환기 · 조도 |
| **R-E 절전** | 무재실 · 외출 | 조명 · 냉방 정지 |

### 4.2 상호작용 규칙 10개 — 협조가 규칙으로 표현되는 곳

| ID | 규칙 | 두 장치 | 이유 |
|---|---|---|---|
| **I1** | 제습기 ⟂ 가습기 (상호배제) | 제습기 · 가습기 | 동시 가동은 에너지 낭비 + 제어 진동 |
| **I2** | 에어컨 냉방 중 창문 ≤ 10 % | 에어컨 · 창문 | 냉방 손실. 10 %는 틈새 환기 허용 |
| **I3** | 기계 배기(배기팬 + 후드) 시 **급기 확보** — 창문을 쓸 수 있으면(외기 양호 · 비 X · 냉방 X) 창문 10–20 % / **쓸 수 없으면 흡기팬(필터)**, 외기 나쁨이면 최대 (v1.4: 비 · 냉방 중 명시) | 후드 · 배기팬 · 흡기팬 · 창문 | 음압 → 틈새 유입 (A8) · 후드 성능 저하 |
| **I4** | **가습 상한 = f(결로 여유)** — 이슬점이 창 표면온도 − 2 °C를 넘지 않게 | 가습기 · (실링팬 · 블라인드) | 결로. **실링팬 역회전 시 상한이 올라간다** |
| **I5** | 실링팬 정회전 중 냉방 목표 **+1.0 °C 완화** | 실링팬 · 에어컨 | 체감온도 보상 → 에어컨 부하 감소 |
| **I6** | **여름 제습은 에어컨, 겨울 제습은 제습기** — **단 E10 빨래 건조 · E3 샤워가 해제할 수 있다** → 에어컨 + 제습기 동시 | 에어컨 · 제습기 | 제습기 발열(**약 480 W** = 전력 200 W + 응축 잠열)은 여름엔 냉방 부하, 겨울엔 이득. 빨래 건조에는 그 열이 오히려 도움 |
| **I7** | 외기 오염 시 **배기 단독 금지 → 필터 급기로 양압 유지** | 배기팬 · 흡기팬 | 음압 유입 차단 (v2.1 C8의 "팬 정지"를 대체 수단으로 승격) |
| **I8** 🆕 | **전력 한도** — 가습기 → 제습기 → 청정기 단 하향 → 에어컨 설정 +1 °C → 풍량 약 순으로 차단 · **요리 중 후드는 차단 금지** | 전 가전 | 원룸 차단기 용량. 미뤄도 되는 부하부터 |
| **I9** 🆕 | **수동 조작 존중** — 사용자가 직접 바꾼 기기는 30분 자동 제어 보류, 협조 동작(창문 · 배기)은 계속 · 같은 방향 반복 시 모드 목표 오프셋 ±0.5 °C 누적(상한 ±1.5) | 해당 기기 · 관련 기기 | 수동 조작은 고장이 아니라 **사용자 의도에 대한 정보** |
| **I10** 🆕 | **환기 제습은 바깥이 더 건조할 때만** — 배기 · 창문을 제습 수단으로 쓰는 것은 *바깥 이슬점 < 실내 이슬점 − 2 °C* 일 때. 차이 < 1 °C면 중단하고 에어컨 · 제습기로 넘긴다 · **기본 환기(§3.3)는 예외** | 배기팬 · 창문 · 흡기팬 · 에어컨 · 제습기 | "비 오면 배기 정지"를 대신하는 물리 기준 — 샤워 직후 · 겨울비에는 비가 와도 배기가 이득 (§3.5) |

**R-P 30분 예측 검사 (v1.1)** — 사다리의 다음 칸을 쓰기 전에 환경 모델로 30분을 앞당겨 본다.
그 칸이 **다른 목표를 허용 범위 밖으로** 밀어내면 건너뛴다(예: 외기 미세먼지가 나쁜데 창문 열기, 수면 중 에어컨 강풍).
v1.0에서는 후드 단수 선택에만 예측을 썼고, v1.1에서 **사다리 전반**으로 넓혔다. 후보가 칸당 1개라 1 Hz 주기 안에서 충분하다.

### 4.3 수단 사다리

> **v1.8 구현 규칙 (2026-10-09, `scripts/controller/ladders.py` · thresholds `comfort_ladders`)**
> - **냉방:** ① 블라인드 차광(낮) ② 창문 40 % + 배기 저속(외기 < 실내 − 1 °C) ③ 실링팬 정회전 ④ 창문 불가 시 배기 + 흡기 ⑤ 에어컨(I5 +1 °C).
>   에어컨은 무료 냉방(②④)을 쓸 수 없을 때, 또는 무료 냉방을 15분 써도 목표 + 1 °C 를 넘을 때 **승격**한다 (C5)
> - **제습이 필요한데 바깥이 더 습하면(I10 불만족) 무료 냉방 환기를 쓰지 않는다** — 환기가 습기를 들인다 (C1)
> - **냉방 + 제습이 함께 필요하면** 실내가 냉방 설정 + 0.5 °C 이내로 내려온 뒤 에어컨을 **제습 모드**로 바꾼다 (저부하 냉방은 습기를 거의 못 뺀다)
> - **제습:** I10 이면 창문 → 배기 + 흡기, 아니면 I6 계절 수단(여름 에어컨 제습 · 그 외 제습기). 외출은 에어컨을 쓰지 않으므로 제습기 (C14)
> - **가습:** 유효 상한 = min(모드 상한, I4 결로 상한). 겨울에 결로 상한이 더 낮으면 실링팬 역회전으로 상한을 넓힌다 (C10)
> - 계절(I6)은 날짜 대신 외기온으로 판단한다 (≥ 20 °C 여름 · ≤ 10 °C 겨울 — draft). 히스테리시스 폭은 Baseline B 에서 0
> - **에어컨 승격은 유지(히스테리시스)한다** — 목표 + 1 °C 에서 승격, 목표 + 0.5 °C 이하에서 해제. 승격 중에는 무료 냉방을 요청하지 않는다
>   (유지가 없으면 I2 로 창문이 닫히는 순간 승격 조건이 풀려 창문 ↔ 에어컨이 매 초 바뀐다 — C5 에서 3,081회)
> - 실링팬 강/약도 0.5 °C 폭으로 전환한다 · 결로 위험(E2)에는 외기 절대습도가 낮을 때 간헐 환기(창문 20 % × 60 s / 300 s + 배기 저속) · 외기 매우나쁨은 청정기 2단 예방 가동

목표별 수단을 비용 순으로 세우고, 제약이 칸을 지우면 다음 칸으로 오른다. → 전체 표: [`06` §4](06_appliance_integration.md)

```text
냉방 사다리 (여름 낮, 고온 31 °C · 외기 33 °C)

 ① 블라인드 차광   ✅ 사용
 ② 창문 환기       ✗ 외기가 더 뜨겁다 (외기 < 실내 −1 °C 조건 불충족)
 ③ 실링팬 정회전   ✅ 사용 → 체감 −1.5 °C, 규칙 I5로 냉방 목표 26 → 27 °C 완화
 ④ 배기 + 흡기     ✗ 외기가 더 뜨겁다
 ⑤ 에어컨          ✅ 사용 (목표 27 °C) → 규칙 I2로 창문 ≤ 10 %
```

## 5. 중재 — 최종 명령 결정

### 5.1 6계층

| 계층 | 내용 | 위치 |
|:---:|---|---|
| **L0** | 로컬 하드 보호 — 끼임 정지 · 압축기 최소 ON/OFF · 실링팬 방향 전환 대기 | 브릿지 · `appliance_bridge` (**상위 명령 무시**) |
| **L1** | 안전 인터록 — 우천(E5) · 외기 오염(E6) · 상호배제(I1) · 가전 무응답(E9) · 센서 고장 | 제어기 |
| **L2** | 건강 · 재산 이벤트 — 요리(E1) · 샤워(E3) · 기본 환기 미달(E4) · 결로 위험(E2 위험) | 제어기 |
| **L3** | 절전 — 무재실 절전 상태 · 외출 모드 | 제어기 |
| **L4** | 모드 제약 — 소음 등급 · 금지 장치 · 조명 정책 | 제어기 |
| **L5** | 쾌적 목표 — 온도 · 습도 · 기본 환기 · 결로 경고 | 제어기 |
| **L6** | 조도 | 제어기 |

> **v2.1과의 차이:** 건강 · 재산(L2)을 절전(L3) **위**에 두었다. 무재실이면 환기는 필요 없지만(사람이 없다), **결로는 사람이 없어도 진행**되기 때문이다.
>
> **L4.5 우선 목표 (v1.1):** 빨래 건조 같은 **사용자 행동이 만든 최우선 목표**는 모드(L4) 위 · 건강(L2) 아래에 둔다.
> 쾌적 목표(L5)를 **허용 손실 예산 안에서** 희생할 수 있지만, 안전 · 건강 · 결로는 절대 희생하지 않는다 → §5.4

### 5.2 병합 규칙 — 같은 장치에 여러 요구가 걸리면

모든 후보 명령은 `(계층, 종류, 값, 사유)` 를 가진다. 종류는 **need(필요) · cap(상한) · force(강제)** 셋이다.

```text
1. force : 가장 높은 계층의 force가 있으면 그것이 최종값이다   (예: 우천 → 창문 0 %)
2. cap   : 활성 cap 중 최솟값                                  (예: 수면 N0 → 흡기 ≤ 700 rpm)
           단 L2 이벤트는 L4 cap을 '완화'할 수 있다             (예: 기본 환기 미달 → N0를 N1로)
3. need  : 서로 다른 목표의 need는 최댓값                       (예: 기본 환기 40 % vs 제습 환기 60 % → 60 %)
4. 최종  : min(max(need), min(cap))
5. L0    : 가전 보호가 마지막에 덮어쓴다                         (예: 압축기 OFF 180 s 미경과 → 기동 지연)
6. 예산  : 우선 목표 활성 중이면 R-P 예측으로 예산 초과를 검사 → 초과 예상 시 우선 목표 동작을 한 단계 낮춘다
```

### 5.4 우선 목표와 허용 손실 예산 (v1.1 · 피드백 ④)

> **협조 제어는 모든 목표를 동시에 만족시키는 것이 아니다.** 상황에 따라 하나를 최우선으로 두고, 나머지를 **정해진 만큼만** 내준다.

이벤트가 다음을 선언한다.

| 선언 항목 | 의미 | E10 빨래 건조의 예 |
|---|---|---|
| `primary_goal` | 최우선 목표 | 건조 시간 |
| `budget` | 감수할 손실의 **상한** | 실내 온도 +1.0 °C (외출 중 +3.0) · 소음 N2 · 에너지 상한 없음 |
| `overrides` | 해제하는 규칙 | I6 (계절별 제습 수단) |
| `never_overrides` | 절대 해제 불가 | L0 · L1 · L2 (안전 · 건강 · 결로) |

| 상황 | 중재기 동작 |
|---|---|
| 예산 안 | 우선 목표 명령이 쾌적 목표(L5)를 해쳐도 통과 — 예: 제습기 + 에어컨 동시 |
| 예산 초과 예상 (R-P) | 우선 목표 동작을 한 단계 낮추거나 보상 수단 추가 — 예: 에어컨 설정 −1 °C |
| 예산 초과 발생 | 지표 #16 위반으로 기록 · 우선 목표 동작 축소 |

**Tier 2 시나리오 전체의 우선 목표 · 감수 손실 점검표:** [`03` §1.5](03_scenarios.md)
